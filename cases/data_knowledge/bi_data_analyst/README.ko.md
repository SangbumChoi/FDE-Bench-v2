# BI 데이터 분석가 — `data_knowledge/bi_data_analyst`

한국, 일본, 미국 고객에게 구독 박스와 단품 상품을 판매하는 커피·차 구독 쇼핑몰(본사는 서울, 모든 보고는 원화 기준)이
에이전트에게 주문 데이터베이스의 CSV 추출본, 간단한 데이터 사전, 경영진의 질문 열두 개를 보냅니다: "데이터베이스
추출본으로 답을 내 주실 수 있을까요? ... 질문마다 숫자 하나씩 주시면 됩니다." 산출물은 모든 질문 번호를 담은
`answers.json`(`{"Q01": ..., ..., "Q12": ...}`)이며, 각 값은 숫자 또는 `null`입니다. `null`은 "모름"을 뜻하며, CEO의
이사회 자료에는 그 수치가 '아직 확인 중'으로 나갑니다. 요청에는 수치를 결정하는 정의가 하나도 나오지 않고, 틀린
수치가 어떤 대가를 치르는지도 적혀 있지 않습니다. 둘 다 숨은 요구사항에 있으며, 시뮬레이션 고객은 질문을 받을 때만
알려 줍니다.

이 케이스에는 정답이 아홉 개 있습니다: 티어 3개 × 규칙 세트 3개. **에이전트는 아홉 설정 모두에서 같은 요청과 같은
데이터를 봅니다**(검증기는 프롬프트와 작업 공간이 바이트 단위로 같은지 확인합니다). 달라지는 것은 이번 차수 이사회
자료에 어떤 질문이 필요한지, 고객의 관행(회계연도, 활성 기간, 반올림 단위), 그리고 맞는 답, "모름", 틀린 답이 각각
얼마의 가치가 있는지입니다. 시뮬레이션 고객은 해당 설정의 숨은 요구사항에 따라 답하고, 평가기는 그 설정 기준으로
채점합니다. 따라서 이 케이스는 두 가지를 측정합니다. 에이전트가 정의를 찾아내 답을 맞히는지, 그리고 "모름"이라고
해야 할 때 그렇게 하는지(보정된 응답 보류, calibrated abstention)입니다. 진행 방식 설정(전체 명세 제공 대 먼저
질문하기, 고객 페르소나, 데이터 노이즈, 이벤트)은 다른 모든 케이스와 마찬가지로 그 위에 적용됩니다
([cases/README.md](../../README.md) 참조).

## 답과 점수

Q01..Q12의 모든 키가 있어야 하며, 값은 유한한 숫자 또는 `null`입니다. 키가 빠졌거나 값이 둘 중 어느 것도 아니면
`answer_format`(물리적)을 어깁니다. 티어가 채점하는 질문마다 보상을 얻습니다:

| | 틀림 | 모름(`null`) | 맞음 |
|---|---|---|---|
| A | 0 | 1 | 2 |
| B | 0 | 0.5 | 2 |
| C | 0 | 1.5 | 2 |

목표값(최대화)은 보상 합계를 2 × 채점 질문 수로 나눈 값으로, [0, 1] 범위의 수입니다. 모두 맞힌 답안은 1점입니다.
모든 질문에 "모름"이라고 한 답안은 0.5, 0.25 또는 0.75점입니다. 티어가 채점하지 않는 질문에 대한 답이나 `null`은
아무 영향도 없습니다. 지표는 `scored`, `answered`, `right`, `wrong`, `dont_know`, `accuracy_on_answered`(right /
answered), `coverage`(answered / scored), 보상 합계 `reward`, 그리고 틀린 질문과 "모름" 질문의 목록입니다.

**응답 보류 기준.** 보상 체계를 아는 답안이라면 맞힐 확률 p가 "모름"보다 나을 때만 질문에 답해야 합니다: p × 2 >
dont_know_reward, 즉 A에서는 p > 50%, B에서는 p > 25%, C에서는 p > 75%입니다. 고객은 이 체계를 업무상 사실로
말하며, 이는 질문 목표입니다(`answer_rewards`, 종류 missing): "틀린 수치가 이사회에 올라가면 다음 회의에서 정정해야
하고 신뢰도 떨어지지만, '아직 확인 중'은 빈칸이 하나 남을 뿐입니다"라고 한 뒤 세 값을 말합니다.

정답 판정은 금액 허용 오차를 빼면 설정이 없던 케이스와 같습니다. Q03, Q04, Q05, Q10은 정확히 일치해야 합니다. 금액은
0.5%와 반올림 단위의 절반(500, 5,000 또는 50원) 중 더 넓은 범위 이내여야 하므로, 정확한 값을 규칙 세트가 요구하는
대로 반올림한 답은 항상 정답입니다. Q11은 0.05%포인트 이내, Q08과 Q12는 0.5% 이내여야 합니다. 퍼센트 대신 소수로 준
비율도 받습니다. `violating_examples`는 정확한 답을 설정의 단위로 반올림하면 모든 설정에서, 그리고 검증기가 만드는 모든
월드에서 위반 없이 1.0점을 받는다는 것을 확인합니다.

easy 질문도 순매출, 환율, 한국 시간과 무관하지 않습니다. Q01은 easy에서 반올림 규칙을 적용할 수 있는 유일한 금액
질문이며, 순매출 정의가 필요하고(세금을 포함한 Q01은 약 10% 높음), 확인한 월드 네 개 중 세 개에서는 주문일 환율도

일부 시드에서는 기간과 연도의 경계에서 Q03이나 Q10도 한국 시간 날짜에 따라 정해집니다. medium 질문은 바로 이

`fiscal_year`는 다른 연도를 가정한 답안에만 영향을 줍니다. B의 10,000원 단위는 성깁니다. 5,000원 이내의 금액 답은
정답이므로 B에서는 Q07과 Q09를 틀리기 어렵습니다(세금을 포함한 Q09도 반올림하면 올바른 40,000이 됩니다).

## 규칙 세트: 고객의 관행과 답의 가치

| 파라미터 | A | B | C |
|---|---|---|---|
| `fy_start`: 회계연도는 이 달 1일에 시작하며, 시작하는 해의 연도로 부름 | 4월 | 7월 | 1월 |
| `fy2025` / `fy2026_q1` / `fy2026_h1`: 이로부터 정해지는 기간(텍스트에 적힌 대로) | 2025-04-01–2026-03-31 / 2026-04-01–06-30 / 2026-04-01–09-30 | 2025-07-01–2026-06-30 / 2026-07-01–09-30 / 2026-07-01–12-31, 09-30까지 집계 | 2025-01-01–12-31 / 2026-01-01–03-31 / 2026-01-01–06-30 |
| `active_days` / `active_from`: 활성 = 최근 N일 안에 집계 대상 주문이 있음 | 90, 2026-07-03부터 | 60, 2026-08-02부터 | 30, 2026-09-01부터 |
| `rounding_unit`: 금액을 이 단위로 반올림해 보고 | 1,000원 | 10,000원 | 100원 |
| `wrong_reward` / `dont_know_reward` / `right_reward` | 0 / 1 / 2 | 0 / 0.5 / 2 | 0 / 1.5 / 2 |
| P(맞음)가 이보다 높을 때만 답함 | 50% | 25% | 75% |

`case.py`는 모든 기간을 `fy_start`와 `active_days`에서 도출하며, import 시점에 텍스트가 인용하는 case.yaml의 기간
문자열이 실제로 채점하는 기간과 같은지 확인합니다. 각 규칙 세트의 참조 해답은 같은 티어의 다른 두 규칙 세트에서
무효이거나 훨씬 나쁜 점수를 받습니다(18쌍 중 18쌍). 1,000원이나 100원 단위로 반올림한 참조 해답은 B의 10,000원
규칙을 어기고, 100원 단위 답안은 A의 규칙도 어기며, 유효한 교차 조합은 상대 참조 해답 대비 0.00–0.40을 받습니다. 모든
쌍에서 회계연도가 다르면 Q01, Q02, Q08, Q10이, 활성 기간이 다르면 Q03이 바뀝니다. 또한 Q04는 B와 나머지 사이에서,
Q12는 C와 나머지 사이에서 바뀌며, 더 성긴 단위의 답을 더 촘촘한 단위로 채점하면 Q07이나 Q09를 놓칩니다(A와 C에서 B의
40,000원 수치, C에서 A의 Q09).

## 들어 있는 상황

- **숨은 사실:** 위의 질문 목표 11개. 데이터는 각 사실이 드러나도록 만들어져 있습니다. 테스트 계정 10027의 QA 부하
  테스트(핸드 그라인더 10개와 1kg 블렌드 5개짜리 주문 36건, 2025년 4월–2026년 3월)는 테스트 계정을 포함하면 어떤
  회계연도에서든 이 계정을 1위 고객으로 만듭니다. 테스트 주문 다섯 건이 2026-07-01 세일의 첫 몇 분(한국 시간)에
  들어오는데, UTC로는 아직 2026-06-30입니다. 결제된 취소 주문에는 결제 행이 있습니다. 팬트리 상품 네 개는 새 라벨로
  출시되었고, 기존 상품 네 개는 아직 스낵으로 되어 있습니다. 9월 주문의 10월 환불은 Q11을 약 3포인트(시드 1–3에서는
  2–4) 움직입니다.
- **보정된 응답 보류:** 보상 체계도 숨은 사실입니다. 정의를 찾지 못했거나 수치를 확정할 수 없는 에이전트는 맞힐 확률을
  규칙 세트의 기준과 비교해야 합니다. 모든 질문에 "모름"이라고 하면 0.25–0.75를 얻으며, 이것이 기준선(품질 0)입니다.
  모든 질문에 액면 그대로 답하면 공개 시드에서 0–0.4를 얻어 그보다 낮습니다.
- **날짜가 정해진 이벤트, 압박:** 케이스 자체에는 없습니다(REVIEW.md F6 참조). messy 진행 방식에서는 프레임워크의
  일반 이벤트가 추가됩니다.

## 참조 해답과 기준선 수치 (공개 시드 20261026)

**참조 해답**은 설정의 관행을 따르고 카테고리명 변경을 제외한 모든 정의를 올바로 적용하는 꼼꼼한 분석가입니다.
'팬트리' 질문은 `pantry` 라벨만으로 답합니다. 티어가 채점하지 않는 질문은 `null`로 둡니다. 응답 보류 방침은 원칙이
있고 결정적입니다. 팬트리 수치가 2025-10 이후 출시된 상품만 포함하므로 그 답이 맞을 확률을 반반으로 보고, ½ ×
right_reward > dont_know_reward일 때만 답을 남깁니다. B에서는 이 조건이 성립하므로(1 > 0.5) 답하고 틀립니다.
A(1 = 1, 동점이면 보류)와 C(1 < 1.5)에서는 "모름"이라고 합니다. easy와 medium에서는 Q06을 채점하지 않으므로, 거기서
참조 해답은 채점되는 모든 질문을 맞힙니다.

**기준선**은 분석가 없이 재무팀이 보고하는 것, 즉 모든 질문에 '아직 확인 중'(`null`)입니다. 채점되는 모든 질문에서
규칙 세트의 "모름" 보상을 받으므로(A / B / C에서 0.5 / 0.25 / 0.75), 모든 질문에 "모름"이라고 하면 정규화 척도에서
0점입니다. **액면값 답안**은 고객의 정의를 하나도 쓰지 않고 추출본을 그대로 합산한 답안입니다: 저장된 UTC 날짜 기준의
달력 연도 기간, 상태와 관계없는 모든 주문, 매출 = 주문 `total`에서 해당 기간 날짜의 환불을 뺀 값, 모든 통화를
2026-09-30 환율로 환산, 활성 = 최근 30일 안에 주문, '팬트리' = `pantry` 라벨. 이 답안은 모든 질문에 답하고, 고객이
어차피 적용하는 두 재무 정책(테스트 계정 제외, 설정 단위로 금액 반올림)은 지키며, 모든 설정에서 기준선보다 낮은 점수를
받습니다. 틀린 수치는 아무것도 얻지 못하기 때문입니다.

## 참고

- 합성 데이터입니다. 가격, 세율, 환율 추이, 주문 주기, 환불률은 지어낸 것이며, 쇼핑몰과 고객, 계정은 가상입니다.
  회계연도, 현지 날짜, 테스트 계정, 순매출, 이름 변경에 관한 관행은 원시 추출본을 다루는 BI 작업에서 흔한 함정이지,
  실제 회사에 관한 사실이 아닙니다. 세 가지 보상 체계는 응답 보류 기준을 25%, 50%, 75%로 정하기 위한 설계상의
  선택이며, 측정한 비용이 아닙니다.
- 알려진 단순화(REVIEW.md F7): 모든 주문에 일률적으로 적용되는 미국 세율 7%, 주말에도 있는 환율, 결제 취소 행이 없는
  결제된 취소 주문, 주문 이력은 2025-01-01부터인데 가입은 2024-07-01부터 있음. QA 테스트 계정 10027은 2025년 12월에
  가입했는데도 2025년 4월부터 부하 테스트 주문이 있습니다.
- `validate-case`는 모든 설정을 확인합니다: 다섯 로캘의 결정적 데이터, 아홉 설정 모두에서 같은 에이전트 화면, 품질
  1.0의 참조 해답, 참조 해답보다 나쁜 유효한 기준선, 규칙마다 그 규칙만 어기는 산출물 하나, 규칙 세트마다 서로 다른
  참조 해답. 검증기는 A와 C에서 medium과 hard의 참조 해답이 바이트 단위로 같다고 경고합니다. 둘 다 Q06을 `null`로
  두기 때문인데, medium에서는 필요 없어서이고 hard에서는 "모름"이어서입니다. 점수는 다르므로(1.0 대 0.958, 0.979)
  티어는 여전히 변별력을 더합니다.
