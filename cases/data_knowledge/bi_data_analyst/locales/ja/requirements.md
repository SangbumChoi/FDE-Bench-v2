# 注文データベースから経営陣の質問に回答する

## 背景

経営陣から質問がいくつか届きました。データベースのエクスポートから回答していただけますでしょうか。テーブル一式、簡単なデータ辞書、質問一覧を添付しています。質問ごとに数値をひとつずつお返しください。

当社は韓国・日本・米国のお客様に、コーヒーとお茶の定期便ボックスおよび単品商品を販売しています。本社はソウルにあり、レポートはすべてウォン（KRW）建てです。

## 成果物

JSON ファイルひとつ、`answers.json`：`{"Q01": 123456000, "Q02": ..., ..., "Q12": 1.5}`。質問一覧の番号（Q01〜Q12）ごとに数値ひとつです。金額はウォン、割合はパーセント（4.25 は 4.25%）で、顧客を尋ねる質問は数値の `customer_id` でお答えください。

## データについて

- エクスポートは CSV テーブル一式です（`customers.csv`、`accounts_meta.csv`、`products.csv`、`orders.csv`、`order_items.csv`、`payments.csv`、`refunds.csv`、`fx_rates.csv`）。テーブル名とカラム名は SQL にそのまま取り込めるよう英語のままで、ステータスやカテゴリなどのラベルは社内で使っている日本語です。
- **会計年度**：会計年度は4月1日に始まり、始まる年の西暦で呼びます。FY2025 = 2025-04-01〜2026-03-31、FY2026 = 2026-04-01〜2027-03-31 です。第1四半期は4〜6月、上半期は4〜9月です。
- **日付は韓国時間**：タイムスタンプ（`ordered_at_utc`、`signup_at_utc` など）はすべて UTC で保存されていますが、当社でいう「1日」は韓国時間（UTC+9）の暦日です。9時間を足してから日付を取り、日・月・四半期・会計年度はすべてこの基準で区切ります。たとえば UTC 2026-06-30 16:30 の注文は 2026-07-01 の注文です。質問の基準日は 2026-09-30（韓国時間）です。
- **集計対象の注文**：status が `完了` の注文だけを数えます。`キャンセル` と `決済失敗` の注文は、`payments.csv` に決済行があっても決して含めません。注文は注文日が属する期間に計上します。
- **テストアカウント**：`accounts_meta.csv` の `account_type` が `テスト` の顧客は QA 用アカウントです。経理の方針により、すべての数値（注文、売上、顧客数、新規登録数）から除外します。`社員` アカウントは実際のお客様なので含めます。
- **純売上**は税抜きで、返金を差し引いた金額です。注文の `subtotal`（税抜）から、その注文の返金額の税抜部分を差し引きます。`refunds.csv` の返金額は税込みで、税抜部分はその注文の `amount × subtotal / total` です。返金は返金日ではなく、注文日が属する期間の売上から差し引きます。エクスポートは 2026-10-31 に取得したもので、基準日までの注文と、エクスポート時点までに記録されたそれらの注文の返金をすべて含みます。そのため `refunds.csv` には 2026年10月に行われた返金もあり、これも注文が属する期間から差し引きます。カテゴリ別に見る場合は、注文の返金額を各行の金額（`quantity × unit_price`）の比率で按分します。
- **通貨**：金額は注文通貨（`currency`）で保存されています。注文日（韓国時間）の `fx_rates.csv` の `krw_per_unit` でウォンに換算し、その注文の返金にも同じレートを使います。ウォン建ての注文は換算不要です。
- **アクティブ顧客**：基準日で終わる90日間、つまり 2026-07-03〜2026-09-30（両端を含む）に集計対象の注文が1件以上ある顧客です。
- **カテゴリ名の変更**：2025-10-01 に `スナック` カテゴリは `パントリー` に名称変更されました。それ以降に発売された商品は `パントリー` ですが、既存商品は `products.csv` 上でまだ `スナック` のままです（カタログを移行していません）。同じカテゴリですので、`パントリー` についての質問は期間全体で両方のラベルを含みます。
- **質問ごとの定義**：平均注文単価 = 純売上 / 集計対象の注文数。返金率 = 税抜返金額 / 返金前売上（subtotal の合計）、その期間の注文ベース、パーセント表示。返金注文1件あたりの平均返金額 = 税抜返金額（ウォン）/ その期間で返金が1件以上ある集計対象の注文数。新規顧客 = 登録日がその期間に入る顧客。前月比 = (9月 / 8月 − 1) × 100。注文1件あたりの点数 = `quantity` の合計 / 集計対象の注文数。
- **端数処理（経理の方針）**：報告する金額（Q01、Q02、Q06、Q07、Q09）はすべて千ウォン単位に四捨五入します。例：38,412 → 38,000。件数、ID、割合、点数は丸めません。

## 評価方法

**必須条件**（ひとつでも満たさない場合、回答全体が無効）：

- Q01〜Q12 のすべての質問に数値ひとつで回答していること。
- テストアカウントを除外していること。件数や顧客の質問の回答が、テストアカウントを含めた数値と一致した場合は経理方針違反とみなします。
- すべての金額（Q01、Q02、Q06、Q07、Q09）が 1,000 ウォンの整数倍であること。

**品質**：正解した質問の数です。各回答は上記の定義で計算した正確な（丸める前の）値と比較します。顧客 ID と件数（Q03、Q04、Q05、Q10）は完全一致、金額は正確な値との差が 0.5% と 500 ウォンのうち広いほうの範囲内（正確な値を千ウォン単位に四捨五入した回答は必ず正解）、Q11 の前月比は 0.05 ポイント以内、その他は正確な値との差が 0.5% 以内で正解です。多いほど良い評価です。
