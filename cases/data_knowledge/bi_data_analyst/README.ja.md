# BI データアナリスト — `data_knowledge/bi_data_analyst`

韓国・日本・米国のお客様に定期便ボックスと単品商品を販売するコーヒーとお茶の定期便ショップ（本社はソウル、レポートはすべてウォン建て）が、注文データベースの CSV エクスポート、簡単なデータ辞書、経営陣からの12の質問をエージェントに送ります。「データベースのエクスポートから回答していただけますでしょうか。…質問ごとに数値をひとつずつお返しください。」成果物はすべての質問番号を含む `answers.json`（`{"Q01": ..., ..., "Q12": ...}`）で、それぞれの値は数値または `null` です。`null` は「わからない」を意味し、CEO の取締役会資料ではその数値が「集計中」と表示されます。依頼には数値を決める定義がひとつも書かれておらず、誤った数値がどれほどの損失になるかも書かれていません。どちらも隠れた要件に含まれており、シミュレーションの顧客は質問されたときにだけ答えます。

設定は、ティアとルールシードの組み合わせです。ティアは、今回の取締役会資料にどの質問が必要かを決めます。ルールシードは、顧客のルールを四つ、それぞれ独立に三つの候補値から抽選します。会計年度の最初の月、アクティブ顧客の期間、金額を丸める単位、そして「わからない」が正しい回答と誤った回答に比べてどれだけの価値を持つかです。そのため組み合わせはティアごとに81通りになります。公開ルールシードは 4、12、23 です（9つの設定。`dataset/gt/` に保存され、検証器が確認します）。それ以外のシードはすべて非公開の抽選で、その正解はどこにも公開されません。**エージェントはどの設定でも同じ依頼と同じデータを見ます**（検証器は、プロンプトと作業領域がバイト単位で同一であることを確認します）。シミュレーションの顧客はその設定の隠れた要件に基づいて答え、評価器はその設定で採点します。したがって、このケースは二つのことを測ります。エージェントが定義を見つけて正しく答えられるか、そして「わからない」と言うべきときにそう言えるか（較正された回答保留、calibrated abstention）です。進め方の調整項目（仕様をすべて渡すか先に質問させるか、顧客のペルソナ、データのノイズ、イベント）は、ほかのすべてのケースと同様にその上に適用されます（[cases/README.md](../../README.md) を参照）。

## 回答と得点

Q01..Q12 のすべてのキーが必要で、値は有限の数値または `null` です。キーが欠けていたり、値がそのどちらでもなかったりすると、`answer_format`（物理的）に違反します。ティアが採点する質問ごとに報酬が得られます。正しければ 2、誤りなら 0、`null` なら `dont_know_reward` で、この値はルールシードが抽選します：

| `dont_know_reward` | 誤り | わからない（`null`） | 正しい | すべて `null` の回答シートの得点 | P(正解) がこれを上回るときだけ答える |
|---|---|---|---|---|---|
| 0.5 | 0 | 0.5 | 2 | 0.25 | 25% |
| 1 | 0 | 1 | 2 | 0.50 | 50% |
| 1.5 | 0 | 1.5 | 2 | 0.75 | 75% |

目的値（最大化）は報酬の合計を 2 × 採点対象の質問数で割った値で、[0, 1] の範囲の数です。すべて正しい回答シートは 1 になります。ティアが採点しない質問への回答や `null` は何の影響もありません。指標は `scored`、`answered`、`right`、`wrong`、`dont_know`、`accuracy_on_answered`（right / answered）、`coverage`（answered / scored）、報酬の合計 `reward`、そして誤った質問と「わからない」とした質問の一覧です。

**回答保留のしきい値。** 報酬の仕組みを知っている回答シートなら、正解の確率 p が「わからない」を上回るときだけ質問に答えるべきです：p × 2 > dont_know_reward。顧客はこの仕組みを業務上の事実として述べ、これは確認すべき事項です（`answer_rewards`、種類 missing）。「誤った数値が取締役会に出ると次の会議で訂正が必要になり、信用も損ないますが、『集計中』は空欄がひとつ残るだけです」と述べたあと、三つの値が続きます。`null` の価値が 0.5 のとき、顧客は「今回、取締役会は空欄よりも数値を見たいと考えています」と付け加え、1.5 のときは、前回までの2回の資料で訂正が続いたため「今回、取締役会は誤った数値よりも空欄のほうがずっと良いと考えています」と付け加えます。

正誤の判定は、金額の許容誤差を除けば抽選された値に左右されません。Q03、Q04、Q05、Q10 は完全に一致しなければなりません。金額は 0.5% と端数処理単位の半分（50、500 または 5,000 ウォン）のうち広いほうの範囲内でなければならないため、正確な値を抽選された単位のとおりに丸めた回答は必ず正解になります。Q11 は 0.05 ポイント以内、Q08 と Q12 は 0.5% 以内でなければなりません。割合をパーセントではなく小数で答えたものも受け付けます。`violating_examples` は、正確な回答を設定の単位に丸めると、すべての設定、そして検証器が作るすべてのワールドで、違反なしに 1.0 になることを確かめています。

## ティア：今回の取締役会資料に必要な質問

| | easy | medium | hard |
|---|---|---|---|
| **採点する質問** | Q01、Q03、Q04、Q10、Q12（5問） | + Q02、Q05、Q07、Q08、Q09、Q11（11問） | 全12問（+ Q06） |
| **試す内容** | どの注文を集計するか、テストアカウントの除外と社員アカウントの算入、会計年度、アクティブ期間、端数処理（金額の質問は Q01 だけ） | 純売上（税、返金の計上先）、注文日の為替レート、月・四半期・セール当日の境界での韓国時間の日付、9月の注文に対する10月の返金 | スナック → パントリーの名称変更（Q06） |
| **要件が範囲外とするもの** | 「今回の取締役会資料に必要なのは Q01、Q03、Q04、Q10、Q12 だけです … 回答いただいても今回は使いません」 | 「Q06（パントリーの数値）以外のすべての質問」 | なし |

## パラメータとルールシード

各パラメータの候補は一つで、どのティアでも同じです。ルールシード s は、各候補の `Random("data_knowledge/bi_data_analyst|<name>|s").randrange(3)` 番目の値を、ほかのパラメータともティアとも独立に抽選します。

| パラメータ | 候補（easy、medium、hard） | 変わるもの | 事項 |
|---|---|---|---|
| `fy_start`：会計年度はこの月の1日に始まり、始まる年で呼ぶ | 1月、4月、7月（1, 4, 7） | FY2025、FY2026 の第1四半期と上半期の期間。したがって Q01、Q02、Q06、Q07、Q08、Q09、Q10、Q12 の正確な値、そして7月の場合は Q04（10392 ではなく 10247）。Q03、Q05、Q11 は変わらない | `fiscal_year` |
| `active_days`：アクティブ = 直近 N 日間に集計対象の注文がある | 30, 60, 90 | Q03（公開ワールドで 623 / 801 / 881） | `active_customer` |
| `rounding_unit`：金額はこの単位に四捨五入して報告 | 100、1,000、10,000 ウォン | どの金額の回答が有効か（細かい単位に丸めた回答シートは、粗い単位のルールに違反する）と、金額の許容誤差（単位の半分）。粗い単位の回答シートを細かい単位で採点すると Q07 か Q09 を外す | `report_rounding` |
| `dont_know_reward`：`null` が得る報酬（誤り 0、正しい 2） | 0.5, 1, 1.5 | すべての `null` の報酬。したがって回答保留のしきい値（25%、50%、75%）と、すべて `null` のベースライン（0.25、0.50、0.75）。参照解は、確定できない Q06 に 0.5 のときだけ答える | `answer_rewards` |

`derive_params` は、テキストが引用する値を加えます。`fy2025`、`fy2026_q1`、`fy2026_h1`（ロケールごとの言い回しの日付範囲。例："2025-07-01 to 2026-06-30" / "del 2025-07-01 al 2026-06-30"。上半期は期間全体を記し、基準日までで集計する）、`active_from`（期間の初日）、そして報酬の仕組みの固定された両端である `right_reward` 2 と `wrong_reward` 0 です。`admissible` は、報酬が誤り・わからない・正しいの順に大きくなること、基準日までに FY2026 が始まっていること、期間がデータの範囲内にあることを求めます。現在の候補の81通りの組み合わせはすべて通り、このフックは今後追加される候補に備えるものです。要件には `<!-- when: -->` の箇所が三つあります。上半期についての7月始まりの年度の注記と、`null` の価値が 0.5 または 1.5 のときの顧客の一言（上記）です。

**パラメータが効くかの確認**（validate-case、`hard/s4` から）：どのパラメータも、最初に試す別の値だけで正解か得点を変えます。`fy_start` 1 → 4：s4 の参照解は 0.958 から 0.542 に下がります。`active_days` 60 → 30：0.875 に（Q03）。`rounding_unit` 100 → 1,000：参照解が無効になります。`dont_know_reward` 1 → 0.5：その参照解の目的値は 0.958 から 0.938 に動き、0.5 で抽選された参照解は Q06 に答えて 0.917 になります。easy と medium では参照解が採点されるすべての質問に答えるので、そこでは `dont_know_reward` によって参照解の目的値は 1.000 のまま変わりません。それでも、すべて `null` のベースライン（0.25 / 0.50 / 0.75）と、エージェントが出すすべての `null` の報酬は変わるので、回答を保留する回答シートであれば、その正規化品質は変わります。同様に、Q01 が唯一の金額の質問である easy では、10,000 ウォン単位の回答シートは 100 ウォンや 1,000 ウォンのもとでも有効かつ正解のままで、そこでルールに違反するのは逆方向（細かい回答シートを粗い単位で採点する場合）だけです。各公開シードの参照解を同じティアのほかの二つのシードで採点すると（18組）、9組は無効になり（端数処理：100 ウォンの回答シートを 1,000 または 10,000 ウォンで、1,000 ウォンの回答シートを 10,000 ウォンで採点）、有効な9組は 0.00–0.38 です（設定自身の参照解は 0.92–1.00）。どの組でも、会計年度が違えば Q01、Q02、Q08、Q10 が動き（Q12 は1月始まりの年度とそれ以外の間で、Q04 は7月始まりの年度とそれ以外の間で動く）、期間が違えば Q03 が動き、粗い単位の回答を細かい単位で採点すると Q07 か Q09 を外します。

## エージェントが確認すべきこと

hard では11件すべての事項（easy では9件、medium では10件）ですが、そのうち四つはルールシードが抽選した値を含むため、別の実行から持ち越すことも、データから推測することもできません。会計年度の最初の月（`fiscal_year`）、アクティブ期間（`active_customer`）、端数処理の単位（`report_rounding`）、そして「集計中」の価値（`answer_rewards`）です。残りの七つは、どの値が抽選されても同じです。`answer_rewards` がなければ、正解の確率が60%の回答を出すべきかどうか（0.5 と 1 では出す、1.5 では出さない）がわからず、`report_rounding` がなければ、どの金額が有効かがわかりません。

## ルール

| ルール | 区分 | 違反となる条件 |
|---|---|---|
| `answer_format` | 物理的 | 質問番号が欠けている、または値が有限の数値でも `null` でもない（採点の有無にかかわらず12問すべてを確認） |

## 含まれる状況

- **隠れた事実：** 上の11件の確認すべき事項。データはそれぞれの事実が表に出るように作られています。テストアカウント 10027 の QA 負荷テスト（ハンドグラインダー10台と1kgブレンド5袋の注文36件、2025年4月〜2026年3月）により、テストアカウントを含めると、どの会計年度でもこのアカウントがトップの顧客になります。テスト注文5件が 2026-07-01 のセール開始直後の数分（韓国時間）に入りますが、UTC ではまだ 2026-06-30 です。決済済みのキャンセル注文には決済行があります。パントリー商品のうち4つは新しいラベルで発売され、古い4つはまだスナックのままです。9月の注文に対する10月の返金は Q11 を約3ポイント（シード 1–3 では 2–4）動かします。
- **較正された回答保留：** 報酬の仕組みも隠れた事実です。定義を見つけられなかった、あるいは数値を確定できないエージェントは、正解の確率を、抽選された値のしきい値と比べるべきです。すべてに「わからない」と答えると 0.25–0.75 になり、これがベースライン（品質 0）です。すべてに額面どおり答えると、公開ワールドの公開ルールシードで 0–0.4 となり、それを下回ります。
- **日付の決まったイベント、圧力：** ケース自体にはありません（REVIEW.md F6 を参照）。messy の進め方では、フレームワーク共通のイベントが加わります。

## 参照解とベースラインの数値（公開ワールドシード 20261026）

**参照解**は、設定の慣行に従い、カテゴリ名の変更を除くすべての定義を正しく扱う、注意深いアナリストです。「パントリー」の質問には `pantry` ラベルだけで答えます。ティアが採点しない質問は `null` のままにします。回答保留の方針は筋が通っていて決定的です。パントリーの数値は 2025-10 以降に発売された商品しか含まないため、その回答が正しい確率を五分五分とみなし、½ × right_reward > dont_know_reward のときだけ回答を残します。`null` の価値が 0.5 のときはこれが成り立つので（1 > 0.5）答えて誤ります。1（1 = 1、同点なら保留）と 1.5（1 < 1.5）では「わからない」と答えます。easy と medium では Q06 を採点しないので、そこでは参照解は採点されるすべての質問に正解します。

**ベースライン**は、アナリストなしで経理チームが報告するもの、つまりすべての質問について「集計中」（`null`）です。採点されるすべての質問で、抽選された「わからない」の報酬を得るので（最大値の 0.25 / 0.50 / 0.75）、すべてに「わからない」と答えると正規化した尺度では 0 になります。**額面どおりの回答シート**は、顧客の定義をひとつも使わずにエクスポートをそのまま集計したものです：保存された UTC の日付による暦年の期間、ステータスにかかわらずすべての注文、売上 = 注文の `total` からその期間の日付の返金を差し引いたもの、すべての通貨を 2026-09-30 のレートで換算、アクティブ = 直近30日間に注文あり、「パントリー」= `pantry` ラベル。この回答シートはすべての質問に答え、顧客がいずれにせよ適用する二つの経理の方針（テストアカウントの除外、設定の単位での金額の丸め）は守ります。公開ワールドの公開ルールシードでは、どの設定でもベースラインを下回ります。誤った数値は何も得られないからです。

## 補足

- 合成データです。価格、税率、為替レートの推移、注文のリズム、返金率は作りものであり、ショップもその顧客もアカウントも架空のものです。会計年度、現地の日付、テストアカウント、純売上、名称変更に関する慣行は、生のエクスポートを扱う BI 業務でよくある落とし穴であって、実在の会社についての事実ではありません。三つの `null` の報酬は、回答保留のしきい値を 25%、50%、75% に置くための設計上の選択であり、実測したコストではありません。
- 既知の単純化（REVIEW.md F7）：すべての注文に一律7%の米国の税、週末にもある為替レート、取消行のない決済済みのキャンセル注文、そして注文履歴は 2025-01-01 からなのに 2024-07-01 からある会員登録。QA 用のテストアカウント 10027 は2025年12月に登録したにもかかわらず、2025年4月から負荷テストの注文があります。
- `validate-case` はすべての公開設定を確認します：五つのロケールでの決定的なデータ、9つの設定すべてで同じエージェントの見え方、品質 1.0 の参照解、参照解より悪い有効なベースライン、ルールごとにそのルールだけに違反する成果物ひとつ、パラメータの候補と公開ルールシード、すべての組み合わせでの `derive_params`、そしてすべてのパラメータが効くこと。シード 4 と 23 では medium と hard の参照解がバイト単位で同一だという警告が出ます。どちらも Q06 を `null` にしているためで、medium では不要だから、hard では `null` の価値が 1 または 1.5 のとき「わからない」だからです。得点は異なる（1.0 に対して 0.958 と 0.979）ので、ティアは引き続き識別力を加えています。
