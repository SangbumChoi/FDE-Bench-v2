# 共有ドライブをきれいなライブラリに

## 背景

共有ドライブには当社の本およそ100冊分の資料が、中国語・英語・韓国語・日本語・スペイン語で入っていますが、誰も整理してきませんでした。書名、著者、年、紹介文が、各地のオフィスやスキャン担当、版権チームが置いていったさまざまなファイルに散らばっています。ドライブのサンプルを添付します（`corpus/`）。ドライブ全体で実行してきれいなライブラリと一覧を作るプログラムが必要で、整理できないものは推測せず当社のチームに回してください。

## 納品物

`program/` フォルダの `organize.py` に `organize(task)` を定義してください。`task = {"corpus_dir": ..., "out_dir": ...}` です。当社はドライブ全体（サンプルと同じ構成・同じ種類のファイルで約100冊）に対してオフラインで1回実行します。Python 標準ライブラリのみ、最長5分です。プログラムは `corpus_dir` を読むだけで、出力はすべて `out_dir` の中に書きます。

- **ライブラリ。** 1冊につき1ファイル、パスは `library/<著者>/<年>_<書名>.txt`（`out_dir` からの相対パス）。
  - `<年>` は初版の刊行年で、4桁の数字です。年が1つしかない本は、その年が初版の年でもあり、この版の年でもあります。
  - `<書名>` と `<著者>` はラテン文字（中国語・韓国語・日本語の本はメタデータにあるローマ字表記）で書きます。
  - 共著の本：`<著者>` は全著者を順番どおり `" & "` でつなぐです。
  - `<書名>` と `<著者>` の名前の規則：Unicode の NFKC 正規化（全角英数は半角に、分解されたアクセントは合成）を行い、`\ / : * ? " < > |` と制御文字はすべて空白に置き換え、連続する空白は半角スペース1つ（スペースはそのまま）に置き換え、先頭から **40 文字**だけ残し、最後に両端の空白・ピリオド・区切り文字を取り除きます。`<年>` は4桁の数字そのままです。
  - ファイルには**その本の紹介文だけ**を入れます（書名・著者・年の行は入れない）。UTF-8、段落の間は空行1つ、最後は改行で終わります。段落内の改行や空白の数は問いません。
- **`manifest.csv`**：ヘッダーは `source,status,path,reason`。1冊につき1行で、`source` はその本を読んだファイルの corpus からの相対パス（複数は `;` 区切り）、`status` は `placed`（`path` にライブラリのパス、例 `library/...`）か `review`（下の理由コード）です。本でないファイルは `skipped` として載せてもかまいません。
- **`_review/`**：確認に回す本は、元のファイルを `_review/` の下のどこかにコピーし、当社のチームが見られるようにします。理由コードは `UNREADABLE`、`NO_TITLE`、`NO_AUTHOR`、`NO_YEAR`、`NO_DESCRIPTION`、`CONFLICT` で、複数当てはまるときはこの順で最初のものを使います。

## データについて

- 1冊の情報は、形式の違う1〜3個のファイルに分かれていることがあります。JSON、版権チームの ONIX XML 書き出し、EPUB、DOCX、PDF、HTML、フロントマター付きの Markdown、プレーンテキストです。
- 情報源の優先順位：**埋め込みメタデータ**（JSON の項目、ONIX、EPUB のパッケージファイル、DOCX の文書プロパティ、PDF の文書情報、HTML の `<title>`/`<meta>`、Markdown のフロントマター、目録の行）が**扉ページのテキスト**（テキスト・PDF・DOCX・HTML・Markdown 本文の最初の数行：書名、かっこ内のローマ字書名、著者行、版の行）より優先し、扉ページのテキストが**ファイル名**より優先します。ある段階にない項目は次の段階から取ります。
- 年：JSON には `first_published` と `edition_year` があります。ONIX の `PublishingDateRole` 01 はこの版、11 は初版です（01 だけなら唯一の年）。EPUB の `dc:date` はこの版、`first-published` は初版です。扉ページには `初版 2009年 / 新版 2019年` のように書かれ、他の言語では `本版`、`초판` / `개정판`、`First published ... · This edition ...`、`Primera edición: ... · Esta edición: ...` です。文書の作成日・更新日（DOCX、PDF、EPUB）はファイルの日付で、刊行年ではありません。
- 名前：中国語・韓国語・日本語の本は、書名と著者を原語の文字とローマ字の両方で書き、メタデータ（`title_latin`、`name_latin`、`author_latin`、ONIX の `textscript="Latn"`、EPUB の `alternate-script`）と扉ページ（かっこ内のローマ字書名、`名前（ローマ字）`）で対にしています。この対になったローマ字が、著者と書名の正式なラテン文字表記です。英語とスペイン語の名前は名・姓の順に書きます。
- 今回は形式の整った本だけを確認します。1冊1ファイル、UTF-8、メタデータがそろっていて、年がふつうの4桁の数字の本です。ドライブのほかのファイル（古いエンコーディング、複数形式のコピー、壊れた・不完全な資料、アーカイブ、目録、スキャン）はまだ確認しませんが、それが原因でプログラムが止まってはいけません。

## 評価方法

ドライブ全体でプログラムを実行し、ライブラリを当社の目録と照合します。

- 形式の整った本だけを数えます。
- 正しいパスにその本の紹介文で置かれた本は1点です。紹介文は正しいがパスが違うライブラリのファイルは置き場所の誤りで0.4点です（当社のチームが探して手で移す必要があります）。パスは正しいが紹介文が違えば0.2点です。
- 確認に回すべき本は、その本のファイルを挙げている一覧の行がすべて `review` で正しい理由コードなら1点、すべて同じ別のコードなら0.4点です。行どうしが食い違う場合や、その本のファイルがライブラリにもある場合は0点です。
- 各本の一覧の行も確認します。その本のファイルを挙げる行はその1行だけで、ファイルをすべて挙げ、`placed` とその本のライブラリのパス、または `review` とファイルの `_review/` へのコピーがそろっていること。行がない、または誤っている場合は、その本の点数の5分の1を失います。
- 品質 = 100 × 合計点 / 数えた本の数。高いほど良い結果です。

**必須条件**（1つでも破ると結果は無効）：

- ライブラリのファイルと `manifest.csv` はすべて正しい UTF-8 です。ファイル名・フォルダ名に `\ / : * ? " < > |` や制御文字を含まず、`.` や `..` ではなく、空白やピリオドで終わらず、255バイトを超えません。
- 1冊につきライブラリのファイルは1つ。
- `review` の行にはすべて6つの理由コードのどれかがあります。
- `manifest.csv` はライブラリの索引です。ライブラリのファイルはどれもちょうど1つの `placed` 行の `path` で、`placed` 行の `path` はどれもライブラリのファイルで、その行の `source` にはその本を読んだドライブ上のファイルを挙げ、どの情報源（ファイル、アーカイブ内の項目、目録の1行）も2つの行に挙げません。
- `review` の行に挙げたドライブのファイルはすべて `_review/` の下にコピーします（アーカイブ内の項目と目録の行は不要）。
