# 把共享盘整理成干净的书库

## 背景

我们的共享盘里放着大约一百本书的资料，有中文、英文、韩文、日文和西班牙文的，一直没人整理：书名、作者、年份和简介散落在各地办公室、扫描组和版权组留下的各种文件里。附件是共享盘的一个样本（`corpus/`）。我们需要一个能在整个共享盘上运行的程序，整理出干净的书库并附一份清单；归不了档的留给我们的人处理，不要猜。

## 交付物

一个 `program/` 文件夹，其中 `organize.py` 定义 `organize(task)`，`task = {"corpus_dir": ..., "out_dir": ...}`。我们会在完整的共享盘上离线运行一次（结构和文件种类与样本相同，约 100 本书，只能用 Python 标准库，最多 5 分钟）。程序只读取 `corpus_dir`，所有输出都写在 `out_dir` 里：

- **书库。** 每本书一个文件，路径为 `library/<年份>/<作者>/<书名>.txt`（在 `out_dir` 之下）。
  - `<年份>` 是本版（我们手上这一版）的出版年份，四位数字。一本书只给出一个年份时，它既是首次出版年份，也是本版年份。
  - `<书名>` 和 `<作者>` 用原文文字（中文、韩文、日文书保留原文文字）书写。
  - 多位作者合著的书：`<作者>` 为第一作者（只写一位）。
  - `<书名>` 和 `<作者>` 的命名规则：先做 Unicode NFKC 规范化（全角字母变成普通字母，带重音的字母合成为一个字符）；每个 `\ / : * ? " < > |` 和控制字符都换成空格；每一段连续空白换成下划线 `_`；只保留前 **60 个字符**；最后去掉两端的空格、句点和分隔符。`<年份>` 就是四位数字。
  - 文件里**只放这本书的简介**（不要书名、作者、年份那几行），UTF-8 编码，段落之间空一行，文件以换行结尾。段落内部怎么换行、空格多少不计较。
- **`manifest.csv`**，表头 `source,status,path,reason`：每本书一行，`source` 是这本书所用文件在 corpus 里的相对路径，多个用 `;` 分隔；`status` 为 `placed`（`path` 填书库路径，如 `library/...`）或 `review`（填原因代码，见下）。不是书的文件可以记为 `skipped`。
- **`_review/`**：每本送去复核的书，把它的源文件复制到 `_review/` 下面，方便我们的人查看。原因代码有 `UNREADABLE`、`NO_TITLE`、`NO_AUTHOR`、`NO_YEAR`、`NO_DESCRIPTION`、`CONFLICT`；同时符合几种时，取这个顺序里的第一个。

## 数据说明

- 一本书的信息可能分散在一到三个不同格式的文件里：JSON、版权组导出的 ONIX XML、EPUB、DOCX、PDF、HTML、带前置元数据块的 Markdown、纯文本。
- 信息来源的优先级：**内嵌元数据**（JSON 字段、ONIX、EPUB 的包文件、DOCX 文档属性、PDF 文档信息、HTML 的 `<title>`/`<meta>`、Markdown 前置元数据、目录行）优先于**书名页文字**（文本、PDF、DOCX、HTML 或 Markdown 正文开头几行：书名、括号里的罗马字书名、作者行、版次行），书名页文字又优先于**文件名**。某一级缺的字段从下一级取。
- 年份：JSON 有 `first_published` 和 `edition_year`；ONIX 里 `PublishingDateRole` 01 是本版，11 是首次出版（只有 01 时就是唯一的年份）；EPUB 的 `dc:date` 是本版，`first-published` 是首次出版；书名页上写作 `初版 2009年 · 本版 2019年`，或日文的 `新版`、韩文的 `초판` / `개정판`、英文的 `First published ... · This edition ...`、西班牙文的 `Primera edición: ... · Esta edición: ...`。文档的创建和修改日期（DOCX、PDF、EPUB）只是文件日期，绝不是出版年份。
- 名称：中文、韩文、日文书的书名和作者既有原文写法，也有罗马字写法，两者在元数据里成对出现（`title_latin`、`name_latin`、`author_latin`、ONIX 的 `textscript="Latn"`、EPUB 的 `alternate-script`），书名页上也有（括号里的罗马字书名、`姓名（罗马字）`）。这个成对给出的罗马字就是作者和书名的正式拉丁字母写法。英文和西班牙文人名名在前、姓在后。
- 这一轮只检查格式规整的书：每本只有一个文件，UTF-8，元数据完整，年份是普通的四位数字。共享盘里的其他文件（旧编码、同一本书的多份副本、损坏或不完整的资料、压缩包、目录表、扫描件）这次还不检查，但程序不能因为它们而中断。

## 评判方式

我们在完整的共享盘上运行程序，把书库和我们自己的目录比对。

- 只计算格式规整的书。
- 一本书放在完全正确的路径、内容是它的简介，得 1 分。简介正确但路径不对的书库文件算放错了位置，得 0.4 分（我们的人得把它找出来，手工挪到正确的位置）；路径正确但简介不对得 0.2 分。
- 应当复核的书：清单里列出它的文件的每一行都是 `review` 且原因代码正确，得 1 分；都是同一个错误代码得 0.4 分；这些行互相矛盾，或者这本书同时还有书库文件，得 0 分。
- 每本书在清单里的那一行也要检查：列出这本书文件的只能有这一行，要列全它的文件，并且是 `placed` 加上这本书的书库路径，或者是 `review` 且文件已复制到 `_review/` 下。缺了这一行或这一行有错，扣掉这本书得分的五分之一。
- 质量 = 100 × 总得分 / 计入的书的数量，越高越好。

**硬性约束**（违反任何一条，结果作废）：

- 每个书库文件和 `manifest.csv` 都是合法的 UTF-8；文件名和文件夹名不含 `\ / : * ? " < > |` 或控制字符，不是 `.` 或 `..`，不以空格或句点结尾，不超过 255 字节。
- 每本书只有一个书库文件。
- 每个 `review` 行都带六个原因代码之一。
- `manifest.csv` 是书库的索引：每个书库文件恰好是一个 `placed` 行的 `path`，每个 `placed` 行的 `path` 都是一个书库文件，它的 `source` 写出这本书是从共享盘上哪些文件读出来的，任何来源（一个文件、压缩包里的一个条目或目录表的一行）都不能出现在两行里。
- `review` 行里列出的共享盘文件都要复制到 `_review/` 下（压缩包里的条目和目录表的行不必）。
