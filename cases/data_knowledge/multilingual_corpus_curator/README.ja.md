# 多言語コーパスキュレーター — `data_knowledge/multilingual_corpus_curator`

小さな出版社が、約100冊の本（中国語・英語・韓国語・日本語・スペイン語）の資料を、散らかった共有ドライブ1つに置いています。各本の書名、著者、刊行年、紹介文は形式の異なる1〜3個のファイルに分かれていて、その横にはスキャン、アーカイブ、目録の書き出し、不要ファイルが並んでいます。エージェントは**プログラム** `program/organize.py`（`organize(task)`、`task = {"corpus_dir": "$INPUT_DIR", "out_dir": "$OUTPUT_DIR"}`）を納品し、このプログラムが正規化されたライブラリを作ります。

```
out_dir/library/<抽選されたパス構成>.txt   1冊につき UTF-8 のファイル1つ：その本の紹介文だけ
out_dir/_review/...                        ライブラリに並べられない本の元ファイル
out_dir/manifest.csv                       source,status,path,reason（placed | review | skipped）
```

エージェントは公開サンプル（`data/corpus/`、100冊、約120ファイル）を見ることができ、プログラムは同じ作り方で別のシードから作った**隠れたコーパス**（同じ規模・同じ構成）で採点されます。隠れたコーパスはどの設定でも同一です。すべて合成データで、書名、人名、紹介文は各言語でネイティブに書いた架空の語彙から生成しています。どの形式も標準ライブラリだけで読めます。

## 設定：コーパスは一つ、ティア × ルールシード

設定はティアとルールシードの組です。ワールド、公開コーパス、隠れたコーパス、依頼はどの設定でも同じです（エージェントに見える内容がバイト単位で同一であることを検証器が確認します）。ティアは、どの本を採点するか、どのルールを適用するか、ルールシードがどの候補プールから抽選するかを決めます。ルールシードは顧客のライブラリ規則をパラメータごとに別々に抽選するので、正しいライブラリはシードごとに異なります。公開パネルはルールシード **11、18、21** です（9つの設定。`dataset/gt/` に保存され、検証器が確認します）。それ以外のシードは非公開の抽選で、その正解はどこにも公開されません。

### ティア（コーパスは同じで、範囲、厳しさ、候補プールが異なる）

| | easy | medium | hard |
|---|---|---|---|
| **採点する本**（隠れたコーパス） | 形式の整った本30冊：1ファイル、UTF-8、メタデータ完備、ふつうの4桁の年 | 66冊：+ 読めるすべての本 | 100冊：+ 例外 |
| **加わる内容** | 各形式、パス構成、名前の規則、紹介文の抽出、年の基準、ローマ字の対 | 古いエンコーディング（GB18030、CP949、Shift_JIS、CP1252）；`令和元年`、`民國98年`、`단기 4342년`、`二〇〇九年`、`MMIX`；全角の書名とアクセントが分解された書名；パスに使えない文字；同じ著者のいくつものローマ字表記（正式な対はその著者のほかの本にだけある）；形式やフォルダをまたぐコピーの統合；情報源の優先順位（埋め込みメタデータ > 扉ページ > ファイル名） | 欠けた著者・書名・紹介文を別のファイルから補う；意味のあるファイル名から書名；`©` の行から年；理由コードを付けて確認に回す：`NO_TITLE` / `NO_YEAR` / `NO_DESCRIPTION` / `CONFLICT`（同じ段階の情報源で年が食い違う）/ `UNREADABLE`（画像だけのスキャン）；著者のない本についての顧客の方針（`NO_AUTHOR` で確認に回すか、代替の著者名で並べる）；読めるファイルと重複するスキャン；不要ファイル（`.DS_Store`、`Thumbs.db`、`desktop.ini`、`~$` ロックファイル、`__MACOSX/._*`、空のファイル）；zip アーカイブの中の本；複数の本を収めた目録 CSV（英語と日本語のヘッダー） |
| **名前の長さのプール**（`max_len`） | 60、48、40：副題付きの長い書名だけが切られる | 50、40、32：+ やや長い書名がいくつか、32 では共著者の並びも | 40、32、24：+ 中くらいの長さの書名と共著者の並び |
| **著者のない本の方針**（`no_author`） | 抽選しない（該当する本は範囲外） | 抽選しない | 確認に回すか、「Unknown」または「Anonymous」の名前で並べる |
| **ルール** | `utf8_output`、`safe_names`（物理的）；`one_file_per_book`、`review_reason`（契約上） | 同じ | + `no_fabrication`（契約上）；確認方針のときだけ `missing_author_review`（業務慣行、緩和可能） |
| **採点の追加要素** | 範囲外の本は無視 | 本でないライブラリのファイル1つにつき −0.5 | 確認方針：著者がなく確認待ちの本は0.7（代替の著者名で並べると1だが、承認された例外が必要）；配架方針：そうした本もほかの並べる本と同じように採点し、確認に回すと0；どの情報源にもない文章を収めたライブラリのファイルは `no_fabrication` 違反 |
| **要件が範囲外とするもの** | 「ドライブのほかのファイル（古いエンコーディング、複数形式のコピー、壊れた・不完全な資料、アーカイブ、目録、スキャン）はまだ確認しませんが、それが原因でプログラムが止まってはいけません」 | 「例外（項目の欠落、スキャン、アーカイブ、目録、不要ファイル）はまだ採点しませんが、本でないものをライブラリに入れてはいけません」 | なし |

ルールシードはどのティアでもプールの同じ位置を抽選します（抽選はティアに左右されません）。ただし `max_len` はティアごとにプールが異なり、`no_author` は hard にしか候補がありません。そのため同じシードでも、ティアが難しくなるほど名前の長さの上限が厳しくなり、hard では著者のない本の方針が変わることがあります。3つのティアの参照解はどの公開シードでも互いに異なり、それぞれを別のティアで採点すると、そのティア自身の参照解より低い点になります（下の表）。

### パラメータ

ルールシード s は、候補が n 個ある各プールから位置 `Random("data_knowledge/multilingual_corpus_curator|<name>|s").randrange(n)` を、ほかのパラメータとは独立に抽選します。最初の5つのプールはどのティアでも同じです。

| パラメータ | プール | 変わるもの（隠れたコーパス、公開ワールド、範囲内で並べる本 easy / medium / hard） | 確認すべき事項 |
|---|---|---|---|
| `layout` | `library/<年>/<書名>/<著者>.txt`、`library/<年>/<著者>/<書名>.txt`、`library/<著者>/<年>_<書名>.txt` | 並べるすべての本のパス（30 / 66 / 88） | `layout` |
| `year_basis` | 初版の刊行年、この版の刊行年（年が1つしかない本はその年を両方に使う） | 2つの年が異なる本（14 / 30 / 38） | `year_basis` |
| `script` | 原語の文字、ラテン文字（メタデータで対になっているローマ字） | 中国語・韓国語・日本語の本（18 / 40 / 55） | `script` |
| `multi_author` | 筆頭著者のみ、全著者を `" & "` でつなぐ | 著者が2人の本（6 / 13 / 14） | `co_authors` |
| `sep` | `_`、`-`、半角スペース | 空白を含む名前（原語の文字では 18 / 40 / 52、ラテン文字ではすべての本） | `name_rules` |
| `max_len` | easy 60、48、40；medium 50、40、32；hard 40、32、24 | 上限より長い名前：easy はどの値でも3；medium 7、7、8–11；hard 9、10–13、13–21（幅は文字と共著者の規則による） | `name_rules` |
| `no_author` | easy と medium は `review`；hard は `review`、`Unknown`、`Anonymous` | 著者のない本2冊（hard）：`review` なら緩和可能な `missing_author_review` のもとで `NO_AUTHOR` として確認に回し（各0.7）、名前ならその著者名でほかの本と同じように並べる（各1、確認では0） | `missing_author` |

`derive_params` は、テキストが引用する名前 `fallback_author` を加えます。配架方針では抽選された名前、確認方針では「Unknown」（承認された例外で使う名前）です。実行不可能な組み合わせはありません。公開ワールドとワールドシード 1–20（公開コーパスと隠れたコーパス）では、easy と medium の216通り、hard の648通りのどの組み合わせでも、どのティアでも並べる本2冊が同じパスになることはないので、このケースは `admissible` を定義しません。

どの設定にも共通の名前の規則：NFKC、`\ / : * ? " < > |` と制御文字はそれぞれ空白に、連続する空白は区切り文字に、`max_len` 文字で切り詰め、両端の空白・ピリオド・区切り文字を除去。上限が厳しいほど多くの名前にかかるので、この手順の順番を誤ると失点する機会が増えます。アクセントが分解されたスペイン語の書名を NFKC の前に切ると残る文字が減り、切った位置が区切り文字に当たると、除去すべき区切り文字が1つ残ります。

パネルにはすべてのプールのすべての候補が現れます。シード11、18、21を合わせると、候補が3つのプールは3つの値すべてを（どのティアでも）、候補が2つのプールは両方の値を出します。シード11が先頭なのは、validate-case がこのシードからパラメータの影響をチェックするためです。その hard の抽選は著者のない本を並べるので、方針のチェックでは、有効な配架方針の参照解を、それが違反することになる確認方針と比べます。

### エージェントが確認すべきこと

6つの確認すべき事項がルールシードの抽選結果を担っていて、データから読み取ることも、別の実行から持ち越すこともできません：`layout`、`year_basis`、`script`、`co_authors`、`name_rules`（区切り文字と長さの上限）、そして hard では `missing_author`（著者のない本の方針と代替の名前）です。そのほか（`content`、`manifest_review`、`precedence`、`scoring`、ティアごとの `encodings`、`year_notations`、`author_variants`、`duplicates`、`exceptions`、`containers`）は、どの抽選でも同じです。

## 採点

採点する本ごとに：正しいライブラリのパスに正しい紹介文があれば **1** です。そうでなければ、紹介文から見つかったライブラリのファイルは0.4に、合っている要素（年、書名、著者）1つごとに0.2を加えた点数を得ます。正しいパスに別の文章がある場合は0.2です。確認に回すべき本は、その本のファイルのどれかを挙げる一覧の行がすべて `review` で理由コードが正しければ1（すべて同じ別のコードなら0.4、確認方針では `NO_AUTHOR` の本は確認で0.7）で、行どうしが食い違う場合やその本のライブラリファイルもある場合は0です。ライブラリに並べるべき本は、確認に回すと0点です。配架方針では著者のない本もこれに当たり、その本の期待される著者は抽選された代替の名前です。各本の一覧の行も確認します（その本のファイルを挙げる唯一の行で、ファイルをすべて挙げてほかは挙げないこと。`placed` とその本のライブラリのパス、または `review` とファイルの `_review/` 以下へのバイト単位のコピーがそろっていること。読めるファイルと重複するスキャンは、その行に入れても、skipped として載せても、省いてもかまいません）。行がない、または誤っている場合は、その本の点数の5分の1を失います。medium と hard では本でないライブラリのファイル1つにつき0.5を引きます。目的値 = 100 × 点数 / 採点する本の数（最大化）で、品質はベースライン（0）と参照解（1）の間で正規化します。紹介文は NFKC のあと空白をすべて除いて比べるので、改行位置は影響しません。hard では、空でないライブラリのファイルが、どの本の紹介文の段落も丸ごとは含まず、紹介文の断片（20文字以上）でもない場合にも `no_fabrication` が発動します。仮の文や作った紹介文がこれに当たり、見出しが1つ残っていたり段落が1つ抜けていたりするだけなら点数を失うだけです。

採点の振る舞いを確かめる2つのプローブ（隠れたコーパス、公開ワールド）：`expected_output` の確認行を、コーパスのファイルごとに `review` 行6つ（理由コードごとに1行）へ置き換えると、hard/s18 で72.40、hard/s11 と hard/s21 で74.00（easy と medium では80.00）になり、ツリーそのものは 99.40 / 100.00 です。同じ期待ツリーの紹介文をすべて `x` に置き換えると、easy と medium では20.00、hard では `no_fabrication` 違反になります。

隠れたコーパスでのプログラムの出力はプログラムのダイジェストをキーにキャッシュされるので、各設定、違反例、パラメータ影響チェックとティア間のチェックは、異なるプログラムごとに1回だけ実行されます（既定のワールドシード 1–3 で `validate-case` は約2分かかります）。

## 参照解と検証済みの数値（シード 20261027、隠れたコーパス）

ベースライン（`reference/baseline.py` + 同じ `config.json`）は、顧客がエンジニアなしで書けるスクリプトです。完全な UTF-8 の JSON 書き出し（書名、著者、ふつうの4桁の年、紹介文）がある本だけを目録の規則どおりにライブラリに並べ、ほかのファイルはすべてチームに残します（ほかの形式、古いエンコーディング、元号の年は扱わず、コピーを統合せず、確認用の領域もありません）。どの設定でも有効です。

参照解（`reference/organize.py` + その設定の `config.json`）は、しっかりしたルールベースの整理プログラムです。すべての形式、コーパス自身の UTF-8 文字統計による古いエンコーディングの判定、元号の年、NFKC のスラッグ、正規化した書名によるグループ化、項目ごとの優先順位、その本自身のファイルでの名前の対の照合、スキャン、不要ファイル、目録に対応し、抽選された著者のない本の方針に従います。意図的に残した穴（改善余地）：zip アーカイブ、ローマ数字や漢数字の年、著作権表示の年には対応せず、同じ段階の衝突を検出せず、コーパス全体の著者名の対応表を持ちません。

| ティア | 採点する本 | ベースラインの目的値 | 参照解の目的値 | 最高可能値（緩和なし） | その正規化品質 |
|---|---|---|---|---|---|
| easy（s11、s18、s21） | 30 | 10.00 | 100.00 | 100.00 | 1.00 |
| medium（s11、s18、s21） | 66 | 13.33 | 92.73 | 100.00 | 1.09 |
| hard、確認方針（s18） | 100 | 10.80 | 85.60 | 99.40（例外ありで100） | 1.18（1.19） |
| hard、配架方針（s11、s21） | 100 | 10.80 | 86.20 | 100.00 | 1.18 |

このワールドでは、ティアの中で抽選されたライブラリ規則がこれらの数値を変えることはありません（各設定のパスはその設定自身の規則で採点）。変えるのは著者のない本の方針だけで、その差は0.6です。パネルでの参照解のティアごとの平均は **easy 100.00、medium 92.73、hard 86.00**、ベースラインは easy 10.00、medium 13.33、hard 10.80 です（ベースライン/参照解 0.10 / 0.14 / 0.13）。ベースラインは 3 / 10 / 12 冊を正確に並べます。medium と hard ではそのうち6冊（コピーと優先順位のペア）が、ほかにもファイルがあるのに一覧の行に JSON しか挙げていないため5分の1を失い、hard では `CONFLICT` の本2冊を並べてしまい、その2冊は0点です。ワールドシード 1、2、3 ではベースラインは 6.67–20.00（easy）、8.18–13.33（medium）、5.40–8.80（hard）で、参照解は 100.00、94.24–95.76、86.60–87.60（確認方針）または 87.20–88.20（配架方針）です。確認方針のもとで `missing_author_review` を緩和する（著者のない2冊を「Unknown」で並べる）と、緩和が認められる場合は有効で、hard/s18 で86.20（正規化品質 1.008）になります。

参照解が隠れたコーパスで失う点：medium — ローマ数字や漢数字の年の本4冊が `NO_YEAR` で確認に回り、著者の表記に揺れのある本4冊が非公式の名前になります（各0.8）。hard — さらに zip の中の本4冊、著作権表示の年3冊、確認に回さず並べてしまう同じ段階の衝突2冊、そして確認方針では `NO_AUTHOR` の方針を守ることによる 2 × 0.3 です。

## 補足

- 公開コーパスはどの設定・どのロケールでもバイト単位で同一です（`content_dirs: [corpus]`）。ローカライズされているのは、コーパスの外にある整理メモだけです。
- `write only inside out_dir` と `never modify the corpus` はランナーが強制し（プログラムはコーパスのコピーを受け取り、docker では読み取り専用）、採点はしません。

## 保存されたデータセット（`dataset/`）

`python -m fdebench2.cli export-dataset cases/data_knowledge/multilingual_corpus_curator` で書き出します。`validate-case` が再生成し、生成器とずれていれば失敗します（約 2 MB、小さなファイル約2,300個）。

```
dataset/
  agent_view/<lang>/corpus/...       エージェントのサンプルドライブ（どのロケールでもバイト単位で同一）+ 整理メモ
  hidden/corpus/...                  organize() が受け取るそのままの隠れたドライブ（どの設定でも同じ）
  gt/<tier>_s<seed>/                 easy_s11 ... hard_s21、公開パネル
    setting.json, score.json         抽選されたパラメータ（+ 導出された fallback_author）と、隠れたコーパスでの
                                       参照解のスコア（ベースラインの目的値と両方の正規化品質を含む）
    reference/program/               参照解の成果物（organize.py + その設定の config.json）
    reference_output/                参照解が隠れたコーパスで書き出すもの（library/、_review/、manifest.csv）
    expected_output/                 この設定で採点する本についての正しい out_dir（隠れたコーパス）：
                                       library/... 並べる本ごとに紹介文のファイル1つ、その設定のパスに
                                       _review/<REASON>/<パスの / を __ にした名前>  確認に回す本の元ファイル
                                       manifest.csv  placed / review の行（理由付き）と、hard では JUNK の skipped 行
    books.csv                        正解キー（隠れたコーパス）：各本の種類、ティア、採点対象か、期待される状態、
                                       パスと理由、正規の書名・著者・年、元ファイル
    expected_score.json              評価器による expected_output のスコア：easy と medium は100、hard は
                                       確認方針で99.4（NO_AUTHOR の2冊が確認で0.7；緩和したルールはない）、
                                       配架方針で100
```

正解キーがあるのは隠れたコーパスだけです。公開サンプルはエージェントが学ぶための材料で、そこではスコアを計算しません。期待ツリーにはそのティアで採点する本（30 / 66 / 100）だけが入っており、ティア外の本はその設定の正解に含まれません。顧客のメールや SQL の書き出しは追加していません。ドライブにはすでに顧客自身の目録の書き出しがあり、新しい周辺資料を加えるとこのケースが試すものが変わってしまうからです。
