# 多言語コーパスキュレーター — `data_knowledge/multilingual_corpus_curator`

小さな出版社が、約100冊の本（中国語・英語・韓国語・日本語・スペイン語）の資料を、散らかった共有ドライブ1つに置いています。各本の書名、著者、刊行年、紹介文は形式の異なる1〜3個のファイルに分かれていて、その横にはスキャン、アーカイブ、目録の書き出し、不要ファイルが並んでいます。エージェントは**プログラム** `program/organize.py`（`organize(task)`、`task = {"corpus_dir": "$INPUT_DIR", "out_dir": "$OUTPUT_DIR"}`）を納品し、このプログラムが正規化されたライブラリを作ります。

```
out_dir/library/<ルールセットのパス構成>.txt   1冊につき UTF-8 のファイル1つ：その本の紹介文だけ
out_dir/_review/...                            ライブラリに並べられない本の元ファイル
out_dir/manifest.csv                           source,status,path,reason（placed | review | skipped）
```

エージェントは公開サンプル（`data/corpus/`、100冊、約120ファイル）を見ることができ、プログラムは同じ作り方で別のシードから作った**隠れたコーパス**（同じ規模・同じ構成）で採点されます。隠れたコーパスは9つの設定すべてで同一です。すべて合成データで、書名、人名、紹介文は各言語でネイティブに書いた架空の語彙から生成しています。どの形式も標準ライブラリだけで読めます。

## 設定：コーパスは一つ、正解は9通り

ワールド、公開コーパス、隠れたコーパス、依頼はどの設定でも同じです（エージェントに見える内容がバイト単位で同一であることを検証器が確認します）。ティアはどの本を採点し、どのルールを適用するかを決め、ルールセットは正しいライブラリの姿を決めます。

### ティア（コーパスは同じで、範囲と厳しさが異なる）

| | easy | medium | hard |
|---|---|---|---|
| **採点する本**（隠れたコーパス） | 形式の整った本30冊：1ファイル、UTF-8、メタデータ完備、ふつうの4桁の年 | 66冊：+ 読めるすべての本 | 100冊：+ 例外 |
| **加わる内容** | 各形式、パス構成、名前の規則、紹介文の抽出、年の基準、ローマ字の対 | 古いエンコーディング（GB18030、CP949、Shift_JIS、CP1252）；`令和元年`、`民國98年`、`단기 4342년`、`二〇〇九年`、`MMIX`；全角の書名とアクセントが分解された書名；パスに使えない文字；同じ著者のいくつものローマ字表記（正式な対はその著者のほかの本にだけある）；形式やフォルダをまたぐコピーの統合；情報源の優先順位（埋め込みメタデータ > 扉ページ > ファイル名） | 欠けた著者・書名・紹介文を別のファイルから補う；意味のあるファイル名から書名；`©` の行から年；理由コードを付けて確認に回す：`NO_AUTHOR` / `NO_TITLE` / `NO_YEAR` / `NO_DESCRIPTION` / `CONFLICT`（同じ段階の情報源で年が食い違う）/ `UNREADABLE`（画像だけのスキャン）；読めるファイルと重複するスキャン；不要ファイル（`.DS_Store`、`Thumbs.db`、`desktop.ini`、`~$` ロックファイル、`__MACOSX/._*`、空のファイル）；zip アーカイブの中の本；複数の本を収めた目録 CSV（英語と日本語のヘッダー） |
| **ルール** | `utf8_output`、`safe_names`（物理的）；`one_file_per_book`、`review_reason`（契約上） | 同じ | + `no_fabrication`（契約上）；`missing_author_review`（業務慣行、緩和可） |
| **採点の追加要素** | 範囲外の本は無視 | 本でないライブラリのファイル1つにつき −0.5 | + 著者がなく確認待ちの本は0.7（代替の著者名で並べると1だが、承認された例外が必要）；どの情報源にもない文章を収めたライブラリのファイルは `no_fabrication` 違反 |

### ルールセット（顧客のライブラリ規則のハイパーパラメータ）

| パラメータ | A | B | C |
|---|---|---|---|
| パス構成 | `library/<年>/<書名>/<著者>.txt` | `library/<年>/<著者>/<書名>.txt` | `library/<著者>/<年>_<書名>.txt` |
| 年の基準 | 初版 | この版 | 初版 |
| 書名と人名の文字 | 原語の文字 | 原語の文字 | ラテン文字（メタデータで対になっているローマ字） |
| 共著者 | 筆頭著者のみ | 全員、`" & "` でつなぐ | 筆頭著者のみ |
| 空白の代わりの区切り文字 | `_` | `-` | 半角スペース |
| 書名・著者部分の最大長 | 60 | 40 | 80 |
| 代替の著者名（承認された例外がある場合のみ） | `Unknown` | `Anonymous` | `Unknown Author` |

どのルールセットにも共通の名前の規則：NFKC、`\ / : * ? " < > |` と制御文字はそれぞれ空白に、連続する空白は区切り文字に、最大長で切り詰め、両端の空白・ピリオド・区切り文字を除去。

各ティアの中で、各ルールセットの参照解はほかのルールセットのもとでは明らかに誤りになります（行の参照解を列のルールセットで採点した目的値を、そのルールセットの参照解の目的値で割った値です。すべて有効なので、差はパスにあります）。

| 参照解 → 採点に使うルールセット | easy | medium | hard |
|---|---|---|---|
| A を B で / B を A で | 0.507 | 0.520 | 0.575 |
| A または B を C で / C を A または B で | 0.400 | 0.405 | 0.470 |

## ファイル形式と例外の種類

| 種類 | 情報のある場所 |
|---|---|
| JSON | `title`、`title_latin`、`authors[{name, name_latin}]`、`first_published`、`edition_year`、`description`（medium では年が元号などの文字列のことがある） |
| ONIX 風の XML（名前空間 `ns.editeur.org/onix/3.0`） | `TitleText`（+ `textscript="Latn"`）、`Contributor/PersonName` + `AlternativeName` または `PersonNameInverted`、`PublishingDateRole` 01 = この版、11 = 初版、`TextContent/Text` |
| EPUB（zip + OPF） | `dc:title`、`alternate-script` / `file-as` の補足が付いた `dc:creator`、`dc:date`（この版）、`first-published` の meta、`dc:description`；`dcterms:modified` は罠 |
| DOCX（zip + XML） | `docProps/core.xml` の title と creator（`dcterms:created` は罠）；複数の run に分かれた本文の段落 = 扉ページ + 紹介文 |
| PDF（圧縮していないテキストストリーム） | Info の `/Title`、`/Author`（UTF-16 の16進文字列；`/CreationDate` は罠）；ページのテキストは UTF-16 の `Tj` 文字列で、行が折り返されている |
| スキャン PDF | 画像だけのページで、テキストも書名もない：読めない |
| HTML | `<title>`、`<meta name="author">`；本文の `h1`、`p.latin`、`p.byline`、`p.edition`、`h2`、紹介文の段落；`<meta charset>`（medium では Shift_JIS / CP949） |
| Markdown | フロントマター（`title`、`title_latin`、`author`、`author_latin`、`first_published`、`edition`）+ 本文の扉ページ |
| プレーンテキスト | 扉ページ（書名、`(ローマ字書名)`、`名前（ローマ字） 著` / `지음` / `by` / `por`、版の行、任意の `©` の行）、見出し（`内容简介`、`内容紹介`、`책 소개`、`About this book`、`Sinopsis`）、紹介文（固定位置での改行、CRLF、古いエンコーディングのこともある） |
| 目録 CSV | 1行1冊；英語か日本語のヘッダー；`source` = `file.csv#row` |
| zip アーカイブ | それぞれ2冊と AppleDouble の `__MACOSX/._*` 項目1つ；`source` = `archive.zip!inner/path` |

各コーパスの構成（件数は固定、言語は一部ランダム）：easy 30冊；medium はエンコーディング7、年の表記6、全角・分解アクセントの書名4、禁止文字5、ローマ字の揺れ5、複数ファイルのコピー6、優先順位の衝突3；hard は著者の補完3、著者なし2、ファイル名からの書名2、書名なし2、紹介文の補完2、紹介文なし2、著作権表示の年3、年なし2、同じ段階の衝突2、スキャンのみ2、読めるコピーのあるスキャン2、zip の中の本4、目録の行6；ほかに不要ファイル8。

## 採点

採点する本ごとに：正しいライブラリのパスに正しい紹介文があれば **1** です。そうでなければ、紹介文で見つかったライブラリのファイルが0.4に、合っている要素（年、書名、著者）1つごとに0.2を加え、正しいパスに別の文章があれば0.2です。確認に回すべき本は、その本のファイルのどれかを挙げる一覧の行がすべて `review` で理由コードが正しければ1（すべて同じ別のコードなら0.4、`NO_AUTHOR` の本は確認で0.7）で、行どうしが食い違う場合やその本のライブラリファイルもある場合は0です。各本の一覧の行も確認します（その本のファイルを挙げる唯一の行で、ファイルをすべて挙げてほかは挙げないこと。`placed` とその本のライブラリのパス、または `review` とファイルの `_review/` 以下へのバイト単位のコピーがそろっていること。読めるファイルと重複するスキャンは、その行に入れても、skipped として載せても、省いてもかまいません）。行がない、または誤っている場合は、その本の点数の5分の1を失います。medium と hard では本でないライブラリのファイル1つにつき0.5を引きます。目的値 = 100 × 点数 / 採点する本の数（最大化）で、品質はベースライン（0）と参照解（1）の間で正規化します。紹介文は NFKC のあと空白をすべて除いて比べるので、改行位置は影響しません。hard では、空でないライブラリのファイルが、どの本の紹介文の段落も丸ごとは含まず、紹介文の断片（20文字以上）でもない場合にも `no_fabrication` が発動します。仮の文や作った紹介文がこれに当たり、見出しが1つ残っていたり段落が1つ抜けていたりするだけなら点数を失うだけです。

採点が答えを出す2つのプローブ（hard、隠れたコーパス）：`expected_output` の確認行を、コーパスのファイルと理由コードの組ごとに1行へ置き換えると71.6点です（以前は最高可能値の99.4が取れました）。同じ期待ツリーの紹介文をすべて `x` に置き換えると `no_fabrication` 違反になります（以前は64.2点で有効でした）。

隠れたコーパスでのプログラムの出力はプログラムのダイジェストをキーにキャッシュされるので、9つの設定、違反例、ルールセット間のチェックは、異なるプログラムごとに1回だけ実行されます（既定のワールドシード 1–3 で `validate-case` は約40秒かかります）。

## 参照解と検証済みの数値（シード 20261027、隠れたコーパス）

ベースライン（`reference/baseline.py` + 同じ `config.json`）は、顧客がエンジニアなしで書けるスクリプトです。完全な UTF-8 の JSON 書き出し（書名、著者、ふつうの4桁の年、紹介文）がある本だけを目録の規則どおりにライブラリに並べ、ほかのファイルはすべてチームに残します（ほかの形式、古いエンコーディング、元号の年は扱わず、コピーを統合せず、確認用の領域もありません）。どの設定でも有効です。

参照解（`reference/organize.py` + ルールセットの `config.json`）は、しっかりしたルールベースの整理プログラムです。すべての形式、コーパス自身の UTF-8 文字統計による古いエンコーディングの判定、元号の年、NFKC のスラッグ、正規化した書名によるグループ化、項目ごとの優先順位、その本自身のファイルでの名前の対の照合、スキャン、不要ファイル、目録に対応します。意図的に残した穴（伸びしろ）：zip アーカイブ、ローマ数字や漢数字の年、著作権表示の年には対応せず、同じ段階の衝突を検出せず、コーパス全体の著者名の対応表を持たず、`NO_AUTHOR` の方針を守ります。

| 設定 | 採点する本 | ベースラインの目的値 | 参照解の目的値 | 最高可能値（緩和なし） | その正規化品質 |
|---|---|---|---|---|---|
| easy/A, B, C | 30 | 10.00 | 100.00 | 100.00 | 1.00 |
| medium/A, B, C | 66 | 13.33 | 92.73 | 100.00 | 1.09 |
| hard/A, B, C | 100 | 10.80 | 85.60 | 99.40（例外ありで100） | 1.18（1.19） |

このシードでは3つのルールセットの数値が同じです（各ルールセットのパスはそのルールセット自身の規則で採点）。参照解のティアごとの平均は **easy 100.00、medium 92.73、hard 85.60**、ベースラインは easy 10.00、medium 13.33、hard 10.80 です（ベースライン/参照解 0.10 / 0.14 / 0.13）。ベースラインは 3 / 10 / 12 冊を正確に並べます。medium と hard ではそのうち6冊（コピーと優先順位のペア）が、ほかにもファイルがあるのに一覧の行に JSON しか挙げていないため5分の1を失い、hard では `CONFLICT` の本2冊を並べてしまい、その2冊は0点です。ワールドシード 1、2、3 ではベースラインは 6.7–20.0（easy）、8.2–13.3（medium）、5.4–8.8（hard）で、参照解は 100.00、94.24–95.76、86.60–87.60 です。公開サンプルでは参照解は 100.00 / 94.24 / 86.60 です。`missing_author_review` を緩和する（著者のない2冊を代替の著者名で並べる）と、緩和が認められる場合は有効で、hard で86.20（正規化品質 1.008）になります。

ルールセットの各パラメータが答えを変える頻度（範囲内でライブラリに並べる本、隠れたコーパス）：

| | easy | medium | hard |
|---|---|---|---|
| 年の基準（初版 ≠ この版） | 14 | 30 | 38 |
| 文字（ラテン文字以外の書名と人名） | 18 | 40 | 55 |
| 共著者（著者が2人の本） | 6 | 13 | 14 |
| 区切り文字（空白を含む書名） | 18 | 40 | 52 |
| 長さの切り詰め（A 60 / B 40 / C 80） | 3 / 3 / 0 | 7 / 7 / 2 | 9 / 9 / 3 |

参照解が隠れたコーパスで失う点：medium — ローマ数字や漢数字の年の本4冊が `NO_YEAR` で確認に回り、著者の表記に揺れのある本4冊が非公式の名前になります（各0.8）。hard — さらに zip の中の本4冊、著作権表示の年3冊、確認に回さず並べてしまう同じ段階の衝突2冊、`NO_AUTHOR` の方針を守ることによる 2 × 0.3 です。

## 補足

- 公開コーパスはどの設定・どのロケールでもバイト単位で同一です（`content_dirs: [corpus]`）。ローカライズされているのは、コーパスの外にある整理メモだけです。
- `write only inside out_dir` と `never modify the corpus` はランナーが強制し（プログラムはコーパスのコピーを受け取り、docker では読み取り専用）、採点はしません。

## 保存されたデータセット（`dataset/`）

`python -m fdebench2.cli export-dataset cases/data_knowledge/multilingual_corpus_curator` で書き出します。`validate-case` が再生成し、生成器とずれていれば失敗します（約 2 MB、小さなファイル約2,300個）。

```
dataset/
  visible/<lang>/corpus/...          エージェントのサンプルドライブ（どのロケールでもバイト単位で同一）+ 整理メモ
  hidden/corpus/...                  organize() が受け取るそのままの隠れたドライブ（9つの設定すべてで同じ）
  gt/<tier>_<A|B|C>/
    setting.json, score.json         設定と、隠れたコーパスでの参照解のスコア（ベースラインの
                                       目的値と両方の正規化品質を含む）
    reference/program/               参照の成果物（organize.py + ルールセットの config.json）
    reference_output/                参照解が隠れたコーパスで書き出すもの（library/、_review/、manifest.csv）
    expected_output/                 この設定で採点する本についての正しい out_dir（隠れたコーパス）：
                                       library/... 並べる本ごとに紹介文のファイル1つ、ルールセットのパスに
                                       _review/<REASON>/<パスの / を __ にした名前>  確認に回す本の元ファイル
                                       manifest.csv  placed / review の行（理由付き）と、hard では JUNK の skipped 行
    books.csv                        正解キー（隠れたコーパス）：各本の種類、ティア、採点対象か、期待される状態、
                                       パスと理由、正規の書名・著者・年、元ファイル
    expected_score.json              評価器による expected_output のスコア：easy と medium は100、hard は99.4
                                       （NO_AUTHOR の2冊が確認で0.7；緩和したルールはない）
```

正解キーがあるのは隠れたコーパスだけです。公開サンプルはエージェントが学ぶための材料で、そこではスコアを計算しません。期待ツリーにはそのティアで採点する本（30 / 66 / 100）だけが入っており、ティア外の本はその設定の正解に含まれません。顧客のメールや SQL の書き出しは追加していません。ドライブにはすでに顧客自身の目録の書き出しがあり、新しい周辺資料を加えるとこのケースが試すものが変わってしまうからです。
