# 다국어 코퍼스 큐레이터 — `data_knowledge/multilingual_corpus_curator`

작은 출판사가 책 100권 정도(중국어, 영어, 한국어, 일본어, 스페인어)의 자료를 어지러운 공유 드라이브 하나에 두고 있습니다. 책마다 제목, 저자, 출판 연도, 소개글이 형식이 제각각인 파일 한 개에서 세 개에 흩어져 있고, 그 옆에 스캔본, 압축 파일, 카탈로그 내보내기 파일, 쓰레기 파일이 섞여 있습니다. 에이전트는 **프로그램** `program/organize.py`(`organize(task)`, `task = {"corpus_dir": "$INPUT_DIR", "out_dir": "$OUTPUT_DIR"}`)를 납품하며, 이 프로그램이 정규화된 서고를 만듭니다.

```
out_dir/library/<규칙 세트의 경로 구조>.txt   책마다 UTF-8 파일 하나: 그 책의 소개글만
out_dir/_review/...                           서고에 올릴 수 없는 책의 원본 파일
out_dir/manifest.csv                          source,status,path,reason (placed | review | skipped)
```

에이전트는 공개 샘플(`data/corpus/`, 책 100권, 파일 약 120개)을 보고, 프로그램은 같은 방법으로 시드만 바꿔 만든 **숨은 코퍼스**(크기와 구성이 같음)에서 채점됩니다. 숨은 코퍼스는 아홉 설정 모두에서 같습니다. 모든 것이 합성 데이터이며, 제목, 이름, 소개글은 각 언어로 직접 작성한 가상의 어휘에서 생성합니다. 모든 형식을 읽는 데 표준 라이브러리만 있으면 됩니다.

## 설정: 코퍼스 하나, 정답 아홉 개

월드, 공개 코퍼스, 숨은 코퍼스, 요청은 모든 설정에서 같습니다(검증기가 에이전트에게 보이는 내용이 바이트 단위로 같은지 확인합니다). 티어는 어떤 책을 채점하고 어떤 규칙을 적용할지 정하고, 규칙 세트는 올바른 서고가 어떤 모습인지 정합니다.

### 티어 (코퍼스는 같고 범위와 엄격함이 다름)

| | easy | medium | hard |
|---|---|---|---|
| **채점 대상 책**(숨은 코퍼스) | 형식이 잘 갖춰진 책 30권: 파일 하나, UTF-8, 메타데이터 완비, 평범한 네 자리 연도 | 66권: + 읽을 수 있는 모든 책 | 100권: + 예외 상황 |
| **추가되는 것** | 여러 형식, 경로 구조, 이름 규칙, 소개글 추출, 연도 기준, 로마자 짝 | 옛 인코딩(GB18030, CP949, Shift_JIS, CP1252); `令和元年`, `民國98年`, `단기 4342년`, `二〇〇九年`, `MMIX`; 전각 제목과 악센트가 분리된 제목; 경로에 쓸 수 없는 문자; 한 저자의 여러 로마자 표기(공식 짝은 그 저자의 다른 책에만 있음); 형식과 폴더를 넘나드는 사본 합치기; 출처 우선순위(내장 메타데이터 > 표제지 > 파일 이름) | 빠진 저자/제목/소개글을 다른 파일에서 복구; 의미 있는 파일 이름에서 제목; `©` 줄에서 연도; 사유 코드와 함께 검토로: `NO_AUTHOR` / `NO_TITLE` / `NO_YEAR` / `NO_DESCRIPTION` / `CONFLICT`(같은 단계 출처끼리 연도 불일치) / `UNREADABLE`(이미지뿐인 스캔본); 읽을 수 있는 파일과 중복되는 스캔본; 쓰레기 파일(`.DS_Store`, `Thumbs.db`, `desktop.ini`, `~$` 잠금 파일, `__MACOSX/._*`, 빈 파일); zip 압축 파일 안의 책; 여러 권이 든 카탈로그 CSV(영어·일본어 머리글) |
| **규칙** | `utf8_output`, `safe_names`(물리적); `one_file_per_book`, `review_reason`(계약상) | 같음 | + `no_fabrication`(계약상); `missing_author_review`(업무 관행, 완화 가능) |
| **추가 채점 요소** | 범위 밖의 책은 무시 | 책이 아닌 서고 파일마다 −0.5 | + 저자가 없어 검토에서 기다리는 책은 0.7(대체 저자 이름으로 서고에 올리면 1이지만 승인된 예외가 필요); 어느 출처에도 없는 글이 든 서고 파일은 `no_fabrication` 위반 |

### 규칙 세트 (고객 서고 규칙의 하이퍼파라미터)

| 파라미터 | A | B | C |
|---|---|---|---|
| 경로 구조 | `library/<연도>/<제목>/<저자>.txt` | `library/<연도>/<저자>/<제목>.txt` | `library/<저자>/<연도>_<제목>.txt` |
| 연도 기준 | 초판 | 이 판 | 초판 |
| 제목과 이름의 문자 | 원래 문자 | 원래 문자 | 로마자(메타데이터에서 짝지어진 로마자 표기) |
| 공저자 | 첫 번째 저자만 | 모두, `" & "`로 연결 | 첫 번째 저자만 |
| 공백 대신 쓰는 구분자 | `_` | `-` | 일반 공백 |
| 제목/저자 부분의 최대 길이 | 60 | 40 | 80 |
| 대체 저자 이름(승인된 예외가 있을 때만) | `Unknown` | `Anonymous` | `Unknown Author` |

모든 규칙 세트에 공통인 이름 규칙: NFKC, `\ / : * ? " < > |`와 제어 문자는 각각 공백으로, 연속 공백은 구분자로, 최대 길이로 자르기, 양 끝의 공백·마침표·구분자 제거.

각 티어 안에서 각 규칙 세트의 참조 해답은 다른 규칙 세트에서는 확실히 틀립니다(행의 참조 해답을 열의 규칙 세트로 채점한 목표값을 그 규칙 세트 참조 해답의 목표값으로 나눈 값입니다. 모두 유효하므로 차이는 경로에서만 납니다).

| 참조 해답 → 채점 규칙 세트 | easy | medium | hard |
|---|---|---|---|
| A를 B로 / B를 A로 | 0.507 | 0.520 | 0.575 |
| A 또는 B를 C로 / C를 A 또는 B로 | 0.400 | 0.405 | 0.470 |

## 파일 형식과 예외 상황 일람

| 종류 | 정보가 있는 곳 |
|---|---|
| JSON | `title`, `title_latin`, `authors[{name, name_latin}]`, `first_published`, `edition_year`, `description`(medium에서는 연도가 연호 문자열일 수 있음) |
| ONIX 형식의 XML(네임스페이스 `ns.editeur.org/onix/3.0`) | `TitleText`(+ `textscript="Latn"`), `Contributor/PersonName` + `AlternativeName` 또는 `PersonNameInverted`, `PublishingDateRole` 01 = 이 판, 11 = 초판, `TextContent/Text` |
| EPUB(zip + OPF) | `dc:title`, `alternate-script` / `file-as` 보충 정보가 붙은 `dc:creator`, `dc:date`(이 판), `first-published` meta, `dc:description`; `dcterms:modified`는 함정 |
| DOCX(zip + XML) | `docProps/core.xml`의 title과 creator(`dcterms:created`는 함정); 여러 run으로 쪼개진 본문 문단 = 표제지 + 소개글 |
| PDF(압축하지 않은 텍스트 스트림) | Info의 `/Title`, `/Author`(UTF-16 16진 문자열; `/CreationDate`는 함정); 페이지 텍스트는 UTF-16 `Tj` 문자열이며 줄이 나뉘어 있음 |
| 스캔 PDF | 이미지뿐인 페이지, 텍스트도 제목도 없음: 읽을 수 없음 |
| HTML | `<title>`, `<meta name="author">`; 본문의 `h1`, `p.latin`, `p.byline`, `p.edition`, `h2`, 소개글 문단; `<meta charset>`(medium에서는 Shift_JIS / CP949) |
| Markdown | 프런트매터(`title`, `title_latin`, `author`, `author_latin`, `first_published`, `edition`) + 본문 표제지 |
| 일반 텍스트 | 표제지(제목, `(로마자 제목)`, `이름(로마자) 著` / `지음` / `by` / `por`, 판 줄, 선택적인 `©` 줄), 소제목(`内容简介`, `内容紹介`, `책 소개`, `About this book`, `Sinopsis`), 소개글(때로 강제 줄바꿈, CRLF, 옛 인코딩) |
| 카탈로그 CSV | 한 줄에 한 권; 영어 또는 일본어 머리글; `source` = `file.csv#row` |
| Zip 압축 파일 | 각각 책 2권과 AppleDouble `__MACOSX/._*` 항목 하나; `source` = `archive.zip!inner/path` |

각 코퍼스의 구성(개수는 고정, 언어는 일부 무작위): easy 30권; medium 인코딩 7, 연도 표기 6, 전각/분리 악센트 제목 4, 금지 문자 5, 로마자 변형 5, 여러 파일 사본 6, 우선순위 충돌 3; hard 저자 복구 3, 저자 없음 2, 파일 이름에서 제목 2, 제목 없음 2, 소개글 복구 2, 소개글 없음 2, 저작권 줄 연도 3, 연도 없음 2, 같은 단계 충돌 2, 스캔본만 있음 2, 읽을 수 있는 사본이 있는 스캔본 2, zip 안의 책 4, 카탈로그 행 6; 그 밖에 쓰레기 파일 8.

## 채점

채점 대상 책마다: 정확한 서고 경로에 올바른 소개글이 있으면 **1**입니다. 그렇지 않으면 소개글로 찾은 서고 파일이 0.4에 맞은 구성 요소(연도, 제목, 저자)마다 0.2를 더하고, 올바른 경로에 다른 글이 있으면 0.2입니다. 검토로 가야 할 책은 그 책의 파일을 하나라도 적은 매니페스트 줄이 모두 `review`이고 사유 코드가 맞으면 1(모두 같은 다른 코드면 0.4, `NO_AUTHOR` 책은 검토에서 0.7)이고, 줄끼리 어긋나거나 그 책의 서고 파일도 있으면 0입니다. 책마다 매니페스트 줄도 확인합니다(그 책의 파일을 적은 유일한 줄이어야 하고, 파일을 모두 적되 다른 것은 적지 않으며, `placed`와 그 책의 서고 경로, 또는 `review`와 `_review/` 아래에 바이트 그대로 복사한 파일이 있어야 합니다. 읽을 수 있는 파일과 중복되는 스캔본은 그 줄에 넣어도, skipped로 적어도, 빼도 됩니다). 줄이 없거나 틀리면 그 책 점수의 5분의 1을 잃습니다. medium과 hard에서는 책이 아닌 서고 파일마다 0.5를 뺍니다. 목표값 = 100 × 점수 / 채점 대상 책 수(최대화)이며, 품질은 기준선(0)과 참조 해답(1) 사이에서 정규화합니다. 소개글은 NFKC 정규화 후 공백을 모두 지우고 비교하므로 줄바꿈은 영향을 주지 않습니다. hard에서는 비어 있지 않은 서고 파일이 어떤 책의 소개글 문단도 온전히 담고 있지 않고 소개글의 조각(20자 이상)도 아니면 `no_fabrication`이 발동합니다. 자리 표시 문구와 지어낸 소개글이 여기에 해당하며, 남은 소제목 하나나 빠진 문단 하나는 점수만 깎입니다.

채점이 답을 주는 두 가지 프로브(hard, 숨은 코퍼스): 검토 줄을 코퍼스 파일과 사유 코드 조합마다 한 줄씩으로 바꾼 `expected_output`은 71.6점입니다(예전에는 최고 가능 점수 99.4). 같은 예상 트리에서 소개글을 모두 `x`로 바꾸면 `no_fabrication` 위반입니다(예전에는 64.2점으로 유효).

숨은 코퍼스에서 프로그램이 낸 출력은 프로그램의 다이제스트를 키로 캐시하므로, 아홉 설정, 위반 예시, 규칙 세트 교차 검사는 서로 다른 프로그램마다 한 번씩만 실행합니다(기본 월드 시드 1–3으로 `validate-case`는 약 40초 걸립니다).

## 참조 해답과 검증된 수치(시드 20261027, 숨은 코퍼스)

기준선(`reference/baseline.py` + 같은 `config.json`)은 고객이 엔지니어 없이 짤 수 있는 스크립트입니다. 완전한 UTF-8 JSON 내보내기 파일(제목, 저자, 평범한 네 자리 연도, 소개글)이 있는 책만 도서 목록 규칙대로 서고에 올리고, 나머지 파일은 모두 팀에 남깁니다(다른 형식, 옛 인코딩, 연호 연도를 처리하지 않고, 사본을 합치지 않으며, 검토 영역도 없음). 모든 설정에서 유효합니다.

참조 해답(`reference/organize.py` + 규칙 세트의 `config.json`)은 탄탄한 규칙 기반 정리 프로그램입니다. 모든 형식, 코퍼스 자체의 UTF-8 문자 통계를 이용한 옛 인코딩 판별, 연호 연도, NFKC 슬러그, 정규화한 제목으로 묶기, 항목별 우선순위, 책 자체 파일 안에서의 이름 짝 맞추기, 스캔본, 쓰레기 파일, 카탈로그를 처리합니다. 의도적으로 남긴 빈틈(개선 여지): zip 압축 파일, 로마 숫자나 한자 숫자 연도, 저작권 줄 연도를 처리하지 않고, 같은 단계 충돌을 감지하지 않으며, 코퍼스 전체의 저자 이름 대응표가 없고, `NO_AUTHOR` 방침을 지킵니다.

| 설정 | 채점 대상 책 | 기준선 목표값 | 참조 해답 목표값 | 최고 가능 점수(완화 없음) | 그 정규화 품질 |
|---|---|---|---|---|---|
| easy/A, B, C | 30 | 10.00 | 100.00 | 100.00 | 1.00 |
| medium/A, B, C | 66 | 13.33 | 92.73 | 100.00 | 1.09 |
| hard/A, B, C | 100 | 10.80 | 85.60 | 99.40(예외 승인 시 100) | 1.18(1.19) |

이 시드에서는 세 규칙 세트의 수치가 같습니다(각 규칙 세트의 경로는 그 규칙 세트 자체의 규칙으로 채점). 참조 해답의 티어별 평균은 **easy 100.00, medium 92.73, hard 85.60**, 기준선은 easy 10.00, medium 13.33, hard 10.80입니다(기준선/참조 해답 0.10 / 0.14 / 0.13). 기준선은 3 / 10 / 12권을 정확히 서고에 올립니다. medium과 hard에서는 그중 6권(사본과 우선순위 쌍)이 그 책에 다른 파일도 있는데 매니페스트 줄에 JSON만 적어서 5분의 1을 잃고, hard에서는 `CONFLICT` 책 2권을 서고에 올려 아무 점수도 받지 못합니다. 월드 시드 1, 2, 3에서 기준선은 6.7–20.0(easy), 8.2–13.3(medium), 5.4–8.8(hard)이고, 참조 해답은 100.00, 94.24–95.76, 86.60–87.60입니다. 공개 샘플에서 참조 해답은 100.00 / 94.24 / 86.60입니다. `missing_author_review`를 완화하면(저자 없는 두 권을 대체 저자 이름으로 서고에 올리면) 완화가 허용될 때 유효하며, hard에서 86.20(정규화 품질 1.008)입니다.

규칙 세트의 각 파라미터가 답을 바꾸는 빈도(범위 안에서 서고에 올리는 책, 숨은 코퍼스):

| | easy | medium | hard |
|---|---|---|---|
| 연도 기준(초판 ≠ 이 판) | 14 | 30 | 38 |
| 문자(라틴 문자가 아닌 제목과 이름) | 18 | 40 | 55 |
| 공저자(저자가 2명인 책) | 6 | 13 | 14 |
| 구분자(공백이 있는 제목) | 18 | 40 | 52 |
| 길이 자르기(A 60 / B 40 / C 80) | 3 / 3 / 0 | 7 / 7 / 2 | 9 / 9 / 3 |

참조 해답이 숨은 코퍼스에서 잃는 점수: medium — 로마 숫자나 한자 숫자 연도인 책 4권이 `NO_YEAR`로 검토에 가고, 저자 표기 변형이 있는 책 4권이 비공식 이름을 받습니다(각 0.8). hard — 여기에 더해 zip 안의 책 4권, 저작권 줄 연도 3권, 검토로 보내지 않고 서고에 올린 같은 단계 충돌 2권, `NO_AUTHOR` 방침을 지켜서 잃는 2 × 0.3입니다.

## 참고 사항

- 공개 코퍼스는 모든 설정과 로캘에서 바이트 단위로 같습니다(`content_dirs: [corpus]`). 코퍼스 밖에 있는 정리 메모만 현지화되어 있습니다.
- `write only inside out_dir`와 `never modify the corpus`는 실행기가 강제하며(프로그램은 코퍼스의 사본을 받고, docker에서는 읽기 전용), 채점하지 않습니다.

## 저장된 데이터셋(`dataset/`)

`python -m fdebench2.cli export-dataset cases/data_knowledge/multilingual_corpus_curator`로 작성합니다. `validate-case`가 다시 생성하며, 생성기와 달라지면 실패합니다(약 2 MB, 작은 파일 약 2,300개).

```
dataset/
  agent_view/<lang>/corpus/...       에이전트의 샘플 드라이브(모든 로캘에서 바이트 단위로 같음) + 정리 메모
  hidden/corpus/...                  organize()가 받는 그대로의 숨은 드라이브(아홉 설정 모두 같음)
  gt/<tier>_<A|B|C>/
    setting.json, score.json         설정과 숨은 코퍼스에서의 참조 해답 점수(기준선의 목표값과
                                       두 정규화 품질 포함)
    reference/program/               참조 산출물(organize.py + 규칙 세트의 config.json)
    reference_output/                참조 해답이 숨은 코퍼스에서 쓴 결과(library/, _review/, manifest.csv)
    expected_output/                 이 설정에서 채점하는 책들의 올바른 out_dir(숨은 코퍼스):
                                       library/... 서고에 올린 책마다 소개글 파일 하나, 규칙 세트의 경로에
                                       _review/<REASON>/<경로의 /를 __로 바꾼 이름>  검토할 책의 원본 파일
                                       manifest.csv  placed / review 줄(사유 포함), hard에서는 JUNK skipped 줄
    books.csv                        정답 키(숨은 코퍼스): 책마다 종류, 티어, 채점 여부, 예상 상태,
                                       경로와 사유, 정규 제목/저자/연도, 원본 파일
    expected_score.json              평가기가 expected_output에 매긴 점수: easy와 medium은 100, hard는 99.4
                                       (NO_AUTHOR 책 2권이 검토에서 0.7; 완화한 규칙 없음)
```

정답 키는 숨은 코퍼스에만 있습니다. 공개 샘플은 에이전트가 배우는 재료이며, 그 위에서는 점수를 계산하지 않습니다. 예상 트리에는 그 티어에서 채점하는 책(30 / 66 / 100)만 들어 있고, 티어 밖의 책은 그 설정의 정답에 속하지 않습니다. 고객 이메일이나 SQL 내보내기는 추가하지 않았습니다. 드라이브에 이미 고객 자신의 카탈로그 내보내기 파일이 있고, 새 부수 자료를 넣으면 이 케이스가 시험하는 내용이 바뀌기 때문입니다.
