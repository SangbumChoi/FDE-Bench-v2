# 多语种语料库管理员 — `data_knowledge/multilingual_corpus_curator`

一家小出版社把大约一百本书（中文、英文、韩文、日文、西班牙文）的资料放在一个杂乱的共享盘上：每本书的书名、作者、出版年份和简介分散在一到三个不同格式的文件里，旁边还有扫描件、压缩包、目录导出和垃圾文件。智能体交付一个**程序**——`program/organize.py`，其中定义 `organize(task)`，`task = {"corpus_dir": "$INPUT_DIR", "out_dir": "$OUTPUT_DIR"}`——由它整理出一个规范化的书库：

```
out_dir/library/<抽到的布局>.txt   每本书一个 UTF-8 文件：只有这本书的简介
out_dir/_review/...                无法归档的书的源文件
out_dir/manifest.csv               source,status,path,reason（placed | review | skipped）
```

智能体能看到一个可见样本（`data/corpus/`，100 本书，约 120 个文件），程序则在按同一配方、换一个种子生成的**隐藏语料**上评分（规模和构成相同），所有设置下的隐藏语料完全相同。所有内容都是合成的：书名、人名和简介由用各语言原生编写的虚构词表生成。读取所有格式只需要标准库。

## 设置：一份语料，层级 × 规则种子

一个设置由一个层级和一个规则种子组成。世界、可见语料、隐藏语料和需求在每个设置下都相同（验证器会检查智能体看到的内容逐字节一致）。层级决定哪些书计分、适用哪些规则，以及规则种子从哪些候选池中抽取；规则种子逐个参数独立抽取客户的书库规则，因此正确的书库随种子而不同。公开规则种子组为规则种子 **11、18 和 21**（九个设置，保存在 `dataset/gt/` 中，并由验证器检查）；其他任何种子都是非公开抽取，其答案不在任何地方公布。

### 层级（语料相同，范围、严格程度和候选池不同）

| | easy | medium | hard |
|---|---|---|---|
| **计分的书**（隐藏语料） | 30 本格式规整的书：一个文件，UTF-8，元数据完整，普通的四位数年份 | 66 本：+ 所有能读的书 | 100 本：+ 例外情况 |
| **新增内容** | 各种格式、路径布局、命名规则、简介提取、年份依据、罗马字配对 | 旧编码（GB18030、CP949、Shift_JIS、CP1252）；`令和元年`、`民國98年`、`단기 4342년`、`二〇〇九年`、`MMIX`；全角书名和重音被拆开的书名；路径中不允许的字符；同一作者有多种罗马字写法（正式配对只出现在该作者的其他书里）；跨格式、跨文件夹需要合并的副本；来源优先级（内嵌元数据 > 书名页 > 文件名） | 从另一个文件补回缺失的作者/书名/简介；从有意义的文件名取书名；从 `©` 行取年份；带原因代码送去复核：`NO_TITLE` / `NO_YEAR` / `NO_DESCRIPTION` / `CONFLICT`（同级来源年份不一致）/ `UNREADABLE`（只有图像的扫描件）；客户对无作者书的规定（以 `NO_AUTHOR` 送去复核，或以备用作者名上架）；与可读文件重复的扫描件；垃圾文件（`.DS_Store`、`Thumbs.db`、`desktop.ini`、`~$` 锁定文件、`__MACOSX/._*`、空文件）；zip 压缩包里的书；包含多本书的目录 CSV（英文和日文表头） |
| **名称长度候选池**（`max_len`） | 60、48、40：只有带副标题的长书名会被截断 | 50、40、32：+ 几个稍长的书名，在 32 下还有合著者列表 | 40、32、24：+ 中等长度的书名和合著者列表 |
| **无作者书的规定**（`no_author`） | 不抽取（这些书不在范围内） | 不抽取 | 送去复核，或以“Unknown”或“Anonymous”为作者名上架 |
| **规则** | `utf8_output`、`safe_names`（物理约束）；`one_file_per_book`、`review_reason`（合同约束） | 同上 | + `no_fabrication`（合同约束）；仅在复核规定下有 `missing_author_review`（业务惯例，可放宽） |
| **额外计分项** | 范围外的书不予考虑 | 每个不对应任何书的书库文件扣 0.5 | 复核规定：没有作者、在复核区等待的书得 0.7（以备用作者名上架得 1，但需要批准的例外）；上架规定：这类书和其他上架的书一样计分，送去复核得 0；文字不出现在任何来源中的书库文件违反 `no_fabrication` |
| **隐藏需求列为范围外的内容** | “共享盘里的其他文件（旧编码、同一本书的多份副本、损坏或不完整的资料、压缩包、目录表、扫描件）这次还不检查，但程序不能因为它们而中断” | “例外情况（缺字段、扫描件、压缩包、目录表、垃圾文件）这次还不计分，但不是书的东西不能进书库” | 无 |

规则种子在每个层级都抽取候选池中的同一个位置（抽取结果不取决于层级），但 `max_len` 每个层级的候选池不同，`no_author` 只在 hard 中有候选值。因此同一个种子在越难的层级给出越紧的名称长度上限，在 hard 中还可能改变无作者书的规定：三个层级的参考解在每个公开种子下都不同，每个参考解拿到另一个层级下评分，都低于那个层级自己的参考解（见下表）。

### 参数

规则种子 s 从每个有 n 个候选值的候选池中抽取位置 `Random("data_knowledge/multilingual_corpus_curator|<name>|s").randrange(n)`，与其他参数无关。前五个候选池在每个层级都相同。

| 参数 | 候选池 | 改变什么（隐藏语料，公开世界，范围内上架的书 easy / medium / hard） | 应问事项 |
|---|---|---|---|
| `layout` | `library/<年份>/<书名>/<作者>.txt`、`library/<年份>/<作者>/<书名>.txt`、`library/<作者>/<年份>_<书名>.txt` | 每本上架书的路径（30 / 66 / 88） | `layout` |
| `year_basis` | 首次出版年份、本版年份（只有一个年份的书两者都用它） | 两个年份不同的书（14 / 30 / 38） | `year_basis` |
| `script` | 原文文字、拉丁字母（元数据中配对的罗马字） | 中文、韩文和日文书（18 / 40 / 55） | `script` |
| `multi_author` | 只写第一作者、全部作者用 `" & "` 连接 | 有两位作者的书（6 / 13 / 14） | `co_authors` |
| `sep` | `_`、`-`、普通空格 | 含空格的名称（原文文字下为 18 / 40 / 52，拉丁字母下为每本书） | `name_rules` |
| `max_len` | easy 60、48、40；medium 50、40、32；hard 40、32、24 | 超过上限的名称：easy 在每个值下都是 3；medium 7、7、8–11；hard 9、10–13、13–21（范围随文字和合著者规则变化） | `name_rules` |
| `no_author` | easy 和 medium 为 `review`；hard 为 `review`、`Unknown`、`Anonymous` | 2 本无作者的书（hard）：`review` 时依可放宽的 `missing_author_review` 以 `NO_AUTHOR` 送去复核（各 0.7）；取一个名字时以该作者名像其他书一样上架（各 1，在复核区得 0） | `missing_author` |

`derive_params` 补充 `fallback_author`，即文本中引用的名字：在上架规定下是抽到的名字，在复核规定下是“Unknown”（批准的例外会用的名字）。没有不可行的组合：在公开世界和世界种子 1–20 上（可见语料和隐藏语料），在 easy 和 medium 的 216 种组合、hard 的 648 种组合中的任何一种下，任何层级都没有两本上架的书共用一条路径，所以本案例不定义 `admissible`。

每个设置都适用的命名规则：NFKC；每个 `\ / : * ? " < > |` 或控制字符换成空格；连续空白换成分隔符；截断到 `max_len` 个字符；去掉两端的空格、句点和分隔符。上限越紧，涉及的名称越多，所以把这些步骤的顺序弄错，失分也越频繁：在 NFKC 之前截断重音被拆开的西班牙文书名，保留的字母会更少；截断点落在分隔符上，就会留下一个需要去掉的分隔符。

### 智能体必须问的事项

有六个应问事项承载规则种子的抽取结果，既不能从数据中读出，也不能从另一次运行中沿用：`layout`、`year_basis`、`script`、`co_authors`、`name_rules`（分隔符和长度上限），以及 hard 中的 `missing_author`（无作者书的规定和备用名字）。其余事项（`content`、`manifest_review`、`precedence`、`scoring`，以及按层级的 `encodings`、`year_notations`、`author_variants`、`duplicates`、`exceptions`、`containers`）在任何抽取下都相同。

## 评分

每本计分的书：书库路径完全正确且简介正确得 **1**；否则，凭简介找到的书库文件得 0.4，年份、书名、作者每对一项再加 0.2；路径正确但内容是别的文字得 0.2。应当复核的书：清单中列出它任一文件的每一行都是 `review` 且原因代码正确，得 1（各行一致但为另一个代码得 0.4；在复核规定下，`NO_AUTHOR` 的书在复核区得 0.7）；各行不一致，或这本书同时还有书库文件，得 0。应当上架的书在复核区得 0；在上架规定下，无作者的书也属于这一类，其预期作者是抽到的备用名字。每本书的清单行也要检查（只能有这一行列出这本书的文件，要全部列出且不能有别的；`placed` 加上这本书的书库路径，或 `review` 且其文件逐字节复制到 `_review/` 下；与可读文件重复的扫描件可以写在这一行里、记为 skipped，或者不写）：缺这一行或这一行有错，扣掉这本书得分的五分之一。medium 和 hard 中每个不对应任何书的书库文件扣 0.5。目标值 = 100 × 得分 / 计分的书数（最大化）；质量在基线（0）和参考解（1）之间归一化。比较简介时先做 NFKC 并去掉所有空白，所以折行不影响结果。在 hard 中，一个非空书库文件如果既不包含任何一本书的完整简介段落，也不是某段简介的片段（20 个字符以上），`no_fabrication` 也会触发：占位文字和编造的简介都属于这种情况；多出一个小标题或漏掉一段只会少得分。

两个由评分给出答案的探测（隐藏语料，公开世界）：把 `expected_output` 的复核行换成每个语料文件各六行 `review`（每个原因代码一行），在 hard/s18 中得 72.40，在 hard/s11 和 hard/s21 中得 74.00（easy 和 medium 中为 80.00），而目录树本身得 99.40 / 100.00；把同一棵预期目录树里的每段简介都换成 `x`，在 easy 和 medium 中得 20.00，在 hard 中违反 `no_fabrication`。

程序在隐藏语料上的输出按程序的摘要缓存，因此各个设置、违规示例以及参数作用检查和跨层级检查对每个不同的程序只运行一次（使用默认世界种子 1–3 时，`validate-case` 约需两分钟）。

## 参考解与验证过的数字（种子 20261027，隐藏语料）

基线（`reference/baseline.py` + 同一个 `config.json`）是客户不靠工程师也能写出的脚本：只把有完整 UTF-8 JSON 导出（书名、作者、普通的四位数年份和简介）的书按编目规则上架，其余文件都留给团队（不处理其他格式、旧编码或年号年份，不合并副本，没有复核区）。它在每个设置下都有效。

参考解（`reference/organize.py` + 该设置的 `config.json`）是一个扎实的基于规则的整理程序：支持所有格式，借助语料自身的 UTF-8 字符统计识别旧编码，处理年号年份，生成 NFKC slug，按规范化书名分组，逐字段取优先级，在本书自己的文件中配对名称，处理扫描件、垃圾文件和目录，并遵循抽到的无作者书规定。刻意留下的缺口（提升空间）：不处理 zip 压缩包、罗马数字或汉字数字年份、版权行年份，不检测同级冲突，也没有覆盖整个语料的作者名映射。

| 层级 | 计分的书 | 基线目标值 | 参考解目标值 | 最高可能值（不放宽规则） | 其归一化质量 |
|---|---|---|---|---|---|
| easy（s11、s18、s21） | 30 | 10.00 | 100.00 | 100.00 | 1.00 |
| medium（s11、s18、s21） | 66 | 13.33 | 92.73 | 100.00 | 1.09 |
| hard，复核规定（s18） | 100 | 10.80 | 85.60 | 99.40（有例外时为 100） | 1.18（1.19） |
| hard，上架规定（s11、s21） | 100 | 10.80 | 86.20 | 100.00 | 1.18 |

在这个世界下，层级内抽到的书库规则不会改变这些数字（每个设置的路径都按它自己的规则评分）；只有无作者书的规定会改变它们，相差 0.6。参考解在这组种子上的各层级平均值：**easy 100.00、medium 92.73、hard 86.00**；基线：easy 10.00、medium 13.33、hard 10.80（基线/参考解 0.10 / 0.14 / 0.13）。基线完全正确地上架 3 / 10 / 12 本；在 medium 和 hard 中，其中 6 本（副本和优先级配对）因为这本书还有其他文件、而它的清单行只列了 JSON，被扣掉五分之一；在 hard 中它还把 2 本 `CONFLICT` 书上了架，这两本得 0。在世界种子 1、2、3 上，基线得 6.67–20.00（easy）、8.18–13.33（medium）和 5.40–8.80（hard），对应的参考解为 100.00、94.24–95.76 和 86.60–87.60（复核规定）或 87.20–88.20（上架规定）。在复核规定下放宽 `missing_author_review`（把两本没有作者的书以“Unknown”上架）在该规则被放宽时有效，在 hard/s18 中得 86.20（归一化质量 1.008）。

参考解在隐藏语料上失分的地方：medium——4 本罗马数字或汉字数字年份的书以 `NO_YEAR` 送去复核，4 本作者写法有变体的书用了非正式的名字（各得 0.8）；hard——另外还有 4 本 zip 里的书、3 个版权行年份、2 个同级冲突被上架而没有送去复核，以及在复核规定下遵守 `NO_AUTHOR` 规定的 2 × 0.3。

## 备注

- 可见语料在每个设置和语言版本下都逐字节相同（`content_dirs: [corpus]`）；只有语料之外的整理说明做了本地化。
- `write only inside out_dir` 和 `never modify the corpus` 由运行器强制执行（程序拿到的是语料的副本，在 docker 下为只读），不计分。

## 保存的数据集（`dataset/`）

由 `python -m fdebench2.cli export-dataset cases/data_knowledge/multilingual_corpus_curator` 写出；`validate-case` 会重新生成它，与生成器不一致时报错（约 2 MB，约 2,300 个小文件）。

```
dataset/
  agent_view/<lang>/corpus/...       智能体的样本盘（各语言版本逐字节相同）+ 整理说明
  hidden/corpus/...                  organize() 收到的隐藏盘原样（每个设置都相同）
  gt/<tier>_s<seed>/                 easy_s11 ... hard_s21，公开规则种子组
    setting.json, score.json         抽到的参数（+ 推导出的 fallback_author），以及参考解在隐藏语料上的
                                       得分（含基线的目标值和两者的归一化质量）
    reference/program/               参考交付物（organize.py + 该设置的 config.json）
    reference_output/                参考解在隐藏语料上写出的内容（library/、_review/、manifest.csv）
    expected_output/                 此设置下计分的书在隐藏语料上的正确 out_dir：
                                       library/... 每本上架的书一个简介文件，位于该设置规定的路径
                                       _review/<REASON>/<把 / 换成 __ 的路径>  复核书的源文件
                                       manifest.csv  placed / review 行（带原因），hard 中还有 JUNK 的 skipped 行
    books.csv                        答案表（隐藏语料）：每本书的类型、层级、是否计分、预期状态、
                                       路径和原因、规范书名/作者/年份及其源文件
    expected_score.json              评估器给 expected_output 的得分：easy 和 medium 为 100；hard 在复核规定下
                                       为 99.4（两本 NO_AUTHOR 书在复核区得 0.7；没有放宽任何规则），在上架
                                       规定下为 100
```

只有隐藏语料有答案表：可见样本是智能体用来学习的材料，不在它上面计算分数。预期目录树只包含该层级计分的书（30 / 66 / 100）；层级之外的书不属于该设置的答案。没有加入客户邮件或 SQL 导出：共享盘里已经有客户自己的目录导出，新增旁证材料会改变这个案例考查的内容。
