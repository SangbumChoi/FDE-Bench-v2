# 多语种语料库管理员 — `data_knowledge/multilingual_corpus_curator`

一家小出版社把大约一百本书（中文、英文、韩文、日文、西班牙文）的资料放在一个杂乱的共享盘上：每本书的书名、作者、出版年份和简介分散在一到三个不同格式的文件里，旁边还有扫描件、压缩包、目录导出和垃圾文件。智能体交付一个**程序**——`program/organize.py`，其中定义 `organize(task)`，`task = {"corpus_dir": "$INPUT_DIR", "out_dir": "$OUTPUT_DIR"}`——由它整理出一个规范化的书库：

```
out_dir/library/<规则集规定的布局>.txt   每本书一个 UTF-8 文件：只有这本书的简介
out_dir/_review/...                      无法归档的书的源文件
out_dir/manifest.csv                     source,status,path,reason（placed | review | skipped）
```

智能体能看到一个可见样本（`data/corpus/`，100 本书，约 120 个文件），程序则在按同一配方、换一个种子生成的**隐藏语料**上评分（规模和构成相同），九个设置下的隐藏语料完全相同。所有内容都是合成的：书名、人名和简介由用各语言原生编写的虚构词表生成。读取所有格式只需要标准库。

## 设置：一份语料，九套标准答案

世界、可见语料、隐藏语料和需求在每个设置下都相同（验证器会检查智能体看到的内容逐字节一致）。层级决定哪些书计分、适用哪些规则；规则集决定正确的书库是什么样子。

### 层级（语料相同，范围和严格程度不同）

| | easy | medium | hard |
|---|---|---|---|
| **计分的书**（隐藏语料） | 30 本格式规整的书：一个文件，UTF-8，元数据完整，普通的四位数年份 | 66 本：+ 所有能读的书 | 100 本：+ 例外情况 |
| **新增内容** | 各种格式、路径布局、命名规则、简介提取、年份依据、罗马字配对 | 旧编码（GB18030、CP949、Shift_JIS、CP1252）；`令和元年`、`民國98年`、`단기 4342년`、`二〇〇九年`、`MMIX`；全角书名和重音被拆开的书名；路径中不允许的字符；同一作者有多种罗马字写法（正式配对只出现在该作者的其他书里）；跨格式、跨文件夹需要合并的副本；来源优先级（内嵌元数据 > 书名页 > 文件名） | 从另一个文件补回缺失的作者/书名/简介；从有意义的文件名取书名；从 `©` 行取年份；带原因代码送去复核：`NO_AUTHOR` / `NO_TITLE` / `NO_YEAR` / `NO_DESCRIPTION` / `CONFLICT`（同级来源年份不一致）/ `UNREADABLE`（只有图像的扫描件）；与可读文件重复的扫描件；垃圾文件（`.DS_Store`、`Thumbs.db`、`desktop.ini`、`~$` 锁定文件、`__MACOSX/._*`、空文件）；zip 压缩包里的书；包含多本书的目录 CSV（英文和日文表头） |
| **规则** | `utf8_output`、`safe_names`（物理约束）；`one_file_per_book`、`review_reason`（合同约束） | 同上 | + `no_fabrication`（合同约束）；`missing_author_review`（业务惯例，可放宽） |
| **额外计分项** | 范围外的书不予考虑 | 每个不对应任何书的书库文件扣 0.5 | + 没有作者、在复核区等待的书得 0.7（以备用作者名上架得 1，但需要批准的例外）；文字不出现在任何来源中的书库文件触犯 `no_fabrication` |

### 规则集（客户书库规则的超参数）

| 参数 | A | B | C |
|---|---|---|---|
| 路径布局 | `library/<年份>/<书名>/<作者>.txt` | `library/<年份>/<作者>/<书名>.txt` | `library/<作者>/<年份>_<书名>.txt` |
| 年份依据 | 首次出版 | 本版 | 首次出版 |
| 书名和人名的文字 | 原文文字 | 原文文字 | 拉丁字母（元数据中配对的罗马字） |
| 合著者 | 只写第一作者 | 全部，用 `" & "` 连接 | 只写第一作者 |
| 替换空格的分隔符 | `_` | `-` | 普通空格 |
| 书名/作者部分的最大长度 | 60 | 40 | 80 |
| 备用作者名（仅在有批准的例外时使用） | `Unknown` | `Anonymous` | `Unknown Author` |

每个规则集都适用的命名规则：NFKC；每个 `\ / : * ? " < > |` 或控制字符换成空格；连续空白换成分隔符；截断到最大长度；去掉两端的空格、句点和分隔符。

在每个层级内，把每个规则集的参考解拿到其他规则集下评分，结果都明显不对（行中的参考解在列中规则集下的目标值，除以该规则集参考解的目标值；全部有效，差别都在路径上）：

| 参考解 → 评分所用规则集 | easy | medium | hard |
|---|---|---|---|
| A 在 B 下 / B 在 A 下 | 0.507 | 0.520 | 0.575 |
| A 或 B 在 C 下 / C 在 A 或 B 下 | 0.400 | 0.405 | 0.470 |

## 文件格式与例外一览

| 类型 | 信息在哪里 |
|---|---|
| JSON | `title`、`title_latin`、`authors[{name, name_latin}]`、`first_published`、`edition_year`、`description`（medium 中年份可能是年号字符串） |
| 类 ONIX 的 XML（命名空间 `ns.editeur.org/onix/3.0`） | `TitleText`（+ `textscript="Latn"`）、`Contributor/PersonName` + `AlternativeName` 或 `PersonNameInverted`、`PublishingDateRole` 01 = 本版，11 = 首次出版、`TextContent/Text` |
| EPUB（zip + OPF） | `dc:title`、带 `alternate-script` / `file-as` 细化信息的 `dc:creator`、`dc:date`（本版）、`first-published` meta、`dc:description`；`dcterms:modified` 是陷阱 |
| DOCX（zip + XML） | `docProps/core.xml` 中的 title 和 creator（`dcterms:created` 是陷阱）；拆成多个 run 的正文段落 = 书名页 + 简介 |
| PDF（未压缩的文本流） | Info 中的 `/Title`、`/Author`（UTF-16 十六进制字符串；`/CreationDate` 是陷阱）；页面文字为 UTF-16 的 `Tj` 字符串，有折行 |
| 扫描 PDF | 只有图像的页面，没有文字也没有书名：无法读取 |
| HTML | `<title>`、`<meta name="author">`；正文中的 `h1`、`p.latin`、`p.byline`、`p.edition`、`h2`、简介段落；`<meta charset>`（medium 中为 Shift_JIS / CP949） |
| Markdown | 前置元数据（`title`、`title_latin`、`author`、`author_latin`、`first_published`、`edition`）+ 正文书名页 |
| 纯文本 | 书名页（书名、`(罗马字书名)`、`姓名（罗马字） 著` / `지음` / `by` / `por`、版次行、可选的 `©` 行）、小标题（`内容简介`、`内容紹介`、`책 소개`、`About this book`、`Sinopsis`）、简介（有时有硬换行、CRLF，或用旧编码） |
| 目录 CSV | 每行一本书；英文或日文表头；`source` = `file.csv#row` |
| Zip 压缩包 | 每个装 2 本书，外加一个 AppleDouble `__MACOSX/._*` 条目；`source` = `archive.zip!inner/path` |

每份语料的构成（数量固定，语言部分随机）：easy 30 本；medium 7 个编码、6 种年份写法、4 个全角/重音拆开的书名、5 个禁用字符、5 个罗马字变体、6 组多文件副本、3 个优先级冲突；hard 3 个作者补回、2 个无作者、2 个从文件名取书名、2 个无书名、2 个简介补回、2 个无简介、3 个版权行年份、2 个无年份、2 个同级冲突、2 个只有扫描件、2 个有可读副本的扫描件、4 本 zip 里的书、6 个目录行；另有 8 个垃圾文件。

## 评分

每本计分的书：书库路径完全正确且简介正确得 **1**；否则，凭简介找到的书库文件得 0.4，年份、书名、作者每对一项再加 0.2；路径正确但内容是别的文字得 0.2。应当复核的书：清单中列出它任一文件的每一行都是 `review` 且原因代码正确，得 1（各行一致但为另一个代码得 0.4；`NO_AUTHOR` 的书在复核区得 0.7）；各行不一致，或这本书同时还有书库文件，得 0。每本书的清单行也要检查（只能有这一行列出这本书的文件，要全部列出且不能有别的；`placed` 加上这本书的书库路径，或 `review` 且其文件逐字节复制到 `_review/` 下；与可读文件重复的扫描件可以写在这一行里、记为 skipped，或者不写）：缺这一行或这一行有错，扣掉这本书得分的五分之一。medium 和 hard 中每个不对应任何书的书库文件扣 0.5。目标值 = 100 × 得分 / 计分的书数（最大化）；质量在基线（0）和参考解（1）之间归一化。比较简介时先做 NFKC 并去掉所有空白，所以折行不影响结果。在 hard 中，一个非空书库文件如果既不包含任何一本书的完整简介段落，也不是某段简介的片段（20 个字符以上），`no_fabrication` 也会触发：占位文字和编造的简介都属于这种情况；多出一个小标题或漏掉一段只会少得分。

两个由评分给出答案的探测（hard，隐藏语料）：把 `expected_output` 的复核行换成每个语料文件、每个原因代码各一行，得 71.6（以前能拿到最高可能的 99.4）；把同一棵预期目录树里的每段简介都换成 `x`，触犯 `no_fabrication`（以前得 64.2，且有效）。

程序在隐藏语料上的输出按程序的摘要缓存，因此九个设置、违规示例和跨规则集检查对每个不同的程序只运行一次（使用默认世界种子 1–3 时，`validate-case` 约需 40 秒）。

## 参考解与验证过的数字（种子 20261027，隐藏语料）

基线（`reference/baseline.py` + 同一个 `config.json`）是客户不靠工程师也能写出的脚本：只把有完整 UTF-8 JSON 导出（书名、作者、普通的四位数年份和简介）的书按编目规则上架，其余文件都留给团队（不处理其他格式、旧编码或年号年份，不合并副本，没有复核区）。它在每个设置下都有效。

参考解（`reference/organize.py` + 该规则集的 `config.json`）是一个扎实的基于规则的整理程序：支持所有格式，借助语料自身的 UTF-8 字符统计识别旧编码，处理年号年份，生成 NFKC slug，按规范化书名分组，逐字段取优先级，在本书自己的文件中配对名称，处理扫描件、垃圾文件和目录。刻意留下的缺口（提升空间）：不处理 zip 压缩包、罗马数字或汉字数字年份、版权行年份，不检测同级冲突，没有覆盖整个语料的作者名映射，并且遵守 `NO_AUTHOR` 规定。

| 设置 | 计分的书 | 基线目标值 | 参考解目标值 | 最高可能值（不放宽规则） | 其归一化质量 |
|---|---|---|---|---|---|
| easy/A, B, C | 30 | 10.00 | 100.00 | 100.00 | 1.00 |
| medium/A, B, C | 66 | 13.33 | 92.73 | 100.00 | 1.09 |
| hard/A, B, C | 100 | 10.80 | 85.60 | 99.40（有例外时为 100） | 1.18（1.19） |

在这个种子下三个规则集的数字相同（每个规则集的路径都按它自己的规则评分）。参考解各层级的平均值：**easy 100.00、medium 92.73、hard 85.60**；基线：easy 10.00、medium 13.33、hard 10.80（基线/参考解 0.10 / 0.14 / 0.13）。基线完全正确地上架 3 / 10 / 12 本；在 medium 和 hard 中，其中 6 本（副本和优先级配对）因为这本书还有其他文件、而它的清单行只列了 JSON，被扣掉五分之一；在 hard 中它还把 2 本 `CONFLICT` 书上了架，这两本得 0。在世界种子 1、2、3 上，基线得 6.7–20.0（easy）、8.2–13.3（medium）和 5.4–8.8（hard），对应的参考解为 100.00、94.24–95.76 和 86.60–87.60。在可见样本上，参考解得 100.00 / 94.24 / 86.60。放宽 `missing_author_review`（把两本没有作者的书以备用作者名上架）在该规则被放宽时有效，hard 中得 86.20（归一化质量 1.008）。

规则集的各个参数改变答案的频率（计分范围内上架的书，隐藏语料）：

| | easy | medium | hard |
|---|---|---|---|
| 年份依据（首次出版 ≠ 本版） | 14 | 30 | 38 |
| 文字（非拉丁字母的书名和人名） | 18 | 40 | 55 |
| 合著者（有 2 位作者的书） | 6 | 13 | 14 |
| 分隔符（带空格的书名） | 18 | 40 | 52 |
| 长度截断（A 60 / B 40 / C 80） | 3 / 3 / 0 | 7 / 7 / 2 | 9 / 9 / 3 |

参考解在隐藏语料上失分的地方：medium——4 本罗马数字或汉字数字年份的书以 `NO_YEAR` 送去复核，4 本作者写法有变体的书用了非正式的名字（各得 0.8）；hard——另外还有 4 本 zip 里的书、3 个版权行年份、2 个同级冲突被上架而没有送去复核，以及遵守 `NO_AUTHOR` 规定的 2 × 0.3。

## 备注

- 可见语料在每个设置和语言版本下都逐字节相同（`content_dirs: [corpus]`）；只有语料之外的整理说明做了本地化。
- `write only inside out_dir` 和 `never modify the corpus` 由运行器强制执行（程序拿到的是语料的副本，在 docker 下为只读），不计分。

## 保存的数据集（`dataset/`）

由 `python -m fdebench2.cli export-dataset cases/data_knowledge/multilingual_corpus_curator` 写出；`validate-case` 会重新生成它，与生成器不一致时报错（约 2 MB，约 2,300 个小文件）。

```
dataset/
  visible/<lang>/corpus/...          智能体的样本盘（各语言版本逐字节相同）+ 整理说明
  hidden/corpus/...                  organize() 收到的隐藏盘原样（九个设置都相同）
  gt/<tier>_<A|B|C>/
    setting.json, score.json         设置，以及参考解在隐藏语料上的得分（含基线的
                                       目标值和两者的归一化质量）
    reference/program/               参考交付物（organize.py + 该规则集的 config.json）
    reference_output/                参考解在隐藏语料上写出的内容（library/、_review/、manifest.csv）
    expected_output/                 此设置下计分的书在隐藏语料上的正确 out_dir：
                                       library/... 每本上架的书一个简介文件，位于规则集规定的路径
                                       _review/<REASON>/<把 / 换成 __ 的路径>  复核书的源文件
                                       manifest.csv  placed / review 行（带原因），hard 中还有 JUNK 的 skipped 行    books.csv                        答案表（隐藏语料）：每本书的类型、层级、是否计分、预期状态、
                                       路径和原因、规范书名/作者/年份及其源文件
    expected_score.json              评估器给 expected_output 的得分：easy 和 medium 为 100，hard 为 99.4
                                       （两本 NO_AUTHOR 书在复核区得 0.7；没有放宽任何规则）
```

只有隐藏语料有答案表：可见样本是智能体用来学习的材料，不在它上面计算分数。预期目录树只包含该层级计分的书（30 / 66 / 100）；层级之外的书不属于该设置的答案。没有加入客户邮件或 SQL 导出：共享盘里已经有客户自己的目录导出，新增旁证材料会改变这个案例考查的内容。
