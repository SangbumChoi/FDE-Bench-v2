What the agent is asked

The client's request, the only text the agent gets up front. It is the same in every setting.

中文

我们的共享盘里放着大约一百本书的资料，有中文、英文、韩文、日文和西班牙文的，一直没人整理：书名、作者、年份和简介散落在各地办公室、扫描组和版权组留下的各种文件里。附件是共享盘的一个样本（corpus/）。

我们需要一个程序，能在整个共享盘上运行，整理出一个干净的书库：每本书一个文本文件，内容是这本书的简介，按我们编目组的规矩归档，另外附一份清单，记下每样东西去了哪里。归不了档的不要瞎猜，留出来给我们的人看。

English

Our shared drive holds the material of about a hundred of our books, in Chinese, English, Korean, Japanese and Spanish, and nobody has kept it in order: titles, authors, years and blurbs are scattered over all kinds of files from the regional offices, the scanning team and the rights desk. A sample of the drive is attached (corpus/).

We need a program we can run on the full drive that builds a clean library from it: one text file per book with the book's description, filed the way our catalogue team wants, plus a manifest of what went where. Anything it cannot file should be set aside for our team to look at, not guessed.

한국어

공유 드라이브에 저희 책 100권 정도의 자료가 중국어, 영어, 한국어, 일본어, 스페인어로 들어 있는데, 아무도 정리를 하지 않았습니다. 제목, 저자, 연도, 소개글이 지역 사무소와 스캔팀, 판권팀이 남긴 온갖 파일에 흩어져 있습니다. 드라이브 샘플을 첨부합니다(corpus/).

전체 드라이브에서 돌릴 수 있는 프로그램이 필요합니다. 책마다 소개글이 담긴 텍스트 파일 하나씩, 저희 목록팀이 원하는 방식대로 정리된 깔끔한 서고를 만들고, 무엇이 어디로 갔는지 목록도 남겨 주세요. 정리할 수 없는 것은 추측하지 말고 저희 팀이 볼 수 있게 따로 빼 두어야 합니다.

Español

En nuestra unidad compartida está el material de unos cien libros nuestros, en chino, inglés, coreano, japonés y español, y nadie lo ha mantenido en orden: títulos, autores, años y sinopsis andan repartidos en todo tipo de archivos de las oficinas regionales, el equipo de escaneo y el departamento de derechos. Adjuntamos una muestra de la unidad (corpus/).

Necesitamos un programa que podamos ejecutar sobre la unidad completa y que construya con ella una biblioteca limpia: un archivo de texto por libro con su sinopsis, archivado como lo quiere nuestro equipo de catalogación, y un manifiesto de qué fue a parar dónde. Lo que no pueda archivar debe quedar aparte para que lo revise nuestro equipo, sin inventar nada.

Deliverable spec (agent-visible)

A program/ directory with organize.py defining organize(task); task = {"corpus_dir": <a folder laid out like
data/corpus>, "out_dir": <an empty folder>}. It reads corpus_dir (never changes it) and writes only inside out_dir:
  out_dir/library/...    one UTF-8 .txt file per book holding the book's description (the folder layout and
                         file naming are the client's: ask)
  out_dir/_review/...    the material of books that cannot be placed
  out_dir/manifest.csv   header source,status,path,reason; a row per book (source = its corpus-relative file
                         path(s), ";"-separated) and per skipped file; status placed | review | skipped
It is run once, offline, on the client's full drive (same structure and mix as the sample, about 100 books).
Python standard library only; at most 5 minutes.

Settings: one dataset, 9 ground truths

The agent sees the same request and data in every setting. The tier (= difficulty) decides which rules apply; the rule set gives their parameters. Each difficulty is reported as the mean over rule sets A, B and C.

Tiers

TierWhat is in force
easyOnly the well-formed books are scored (about 30 of 100): one file each, complete metadata, UTF-8, plain 4-digit years. The library path, the file name and the description must be right.
mediumEasy plus every readable book (about 66): legacy encodings (GB18030, CP949, Shift_JIS, CP1252), era and other year notations, full-width or decomposed titles, forbidden path characters, romanized author spellings, copies of a book in several formats to merge, and source precedence. Stray library files cost credit.
hardMedium plus the exceptions (all 100 books): missing authors, titles, years or descriptions that another source supplies or that send the book to review with a reason code, conflicting sources, unreadable scans, junk files, books inside zip archives and multi-book catalog CSVs; no invented descriptions.

Rules

Breaking any rule makes the deliverable invalid, unless the rule's class may bend under the run's company policy and the agent went through the exception process.

  • physical never bends
  • contractual bends only if the policy allows contractual exceptions
  • business_policy may bend through the policy's exception process
RuleClassTiersDescription (parameters in {{…}} come from the rule set)
utf8_outputphysicaleasy, medium, hardEvery file in library/ and manifest.csv is valid UTF-8.
safe_namesphysicaleasy, medium, hardNo output file or folder name contains \ / : * ? " < > | or a control character, is . or .., ends in a space or a dot, or is longer than 255 bytes.
one_file_per_bookcontractualeasy, medium, hardA book has at most one file in library/; copies of the same book in other formats or folders are merged into it.
review_reasoncontractualeasy, medium, hardEvery manifest row with status review gives one of the reason codes UNREADABLE, NO_TITLE, NO_AUTHOR, NO_YEAR, NO_DESCRIPTION, CONFLICT.
no_fabricationcontractualhardA book whose sources have no description is not placed in library/ (no invented or placeholder descriptions), and no library file is empty.
missing_author_reviewbusiness_policyhardA book with no author in any source goes to _review/ with NO_AUTHOR rather than being shelved under "{{fallback_author}}".

Case notes (README.md)

Multilingual Corpus Curator — data_knowledge/multilingual_corpus_curator

A small publisher keeps the material of about a hundred books (Chinese, English, Korean, Japanese, Spanish) on one messy shared drive: each book's title, authors, publication years and description are spread over one to three files of mixed formats, next to scans, archives, catalog exports and junk. The agent delivers a program, program/organize.py with organize(task), task = {"corpus_dir": "$INPUT_DIR", "out_dir": "$OUTPUT_DIR"}, that builds a normalized library:

out_dir/library/<layout of the rule set>.txt   one UTF-8 file per book: the book's description only
out_dir/_review/...                            source files of books that cannot be placed
out_dir/manifest.csv                           source,status,path,reason (placed | review | skipped)

The agent sees a visible sample (data/corpus/, 100 books, ~120 files) and the program is scored on a hidden corpus built by the same recipe with another seed (same size and mix), identical in all nine settings. Everything is synthetic: titles, names and blurbs are generated from invented vocabularies written natively in each language. Only the standard library is needed to read every format.

Settings: one corpus, nine ground truths

The world, the visible corpus, the hidden corpus and the request are the same in every setting (the validator checks the agent's view is byte-identical). The tier decides which books are scored and which rules apply; the rule set decides how the correct library looks.

Composition of each corpus (fixed counts, languages partly random): 30 easy; medium 7 encodings, 6 year notations, 4 full-width/decomposed titles, 5 forbidden characters, 5 romanization variants, 6 multi-file copies, 3 precedence conflicts; hard 3 author recoveries, 2 no author, 2 titles from file names, 2 no title, 2 description recoveries, 2 no description, 3 copyright-line years, 2 no year, 2 same-rank conflicts, 2 scan-only, 2 scans with a readable copy, 4 books in zips, 6 catalog rows; plus 8 junk files.

Scoring

Per scored book: 1 for the exact library path with the right description; otherwise a library file found by its description earns 0.4 + 0.2 for each right component (year, title, author), and the right path with a wrong description earns 0.6. A book that belongs in review earns 1 for a manifest review row naming one of its files with the right reason code (0.4 with another code); a NO_AUTHOR book earns 0.7 in review. Medium and hard subtract 0.5 per library file that is no book. Quality = 100 × credit / books scored, relative to the reference (maximize). Descriptions are compared after NFKC with whitespace removed, so wrapping does not matter. The program's output on the hidden corpus is cached by the program's digest, so the nine settings, the violating examples and the cross-rule-set checks run each distinct program once (validate-case takes ~10 s).

Stored dataset (dataset/)

Written by python -m fdebench2.cli export-dataset cases/data_knowledge/multilingual_corpus_curator; validate-case regenerates it and fails if it drifts from the generator (~2 MB, ~2,900 small files).

Only the hidden corpus has an answer key: the visible sample is the agent's material to learn from, and no score is computed on it. The expected trees hold only the books the tier scores (30 / 66 / 100); books outside the tier are not part of that setting's answer. No client e-mails or SQL exports were added: the drive already contains the client's own catalog exports, and new side material would change what the case tests.
