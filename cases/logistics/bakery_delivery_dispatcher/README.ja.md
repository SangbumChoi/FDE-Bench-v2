# ベーカリー配送の配車担当者 — `logistics/bakery_delivery_dispatcher`

あるベーカリーのセントラルキッチンは、毎朝4台の車両で各店舗にパンのトレーを届けています。顧客はエージェントに、
明日（月曜日）のルートを「店舗にトレーが間に合うように、またドライバーが必要以上に長く走らなくて済むように」組むよう
依頼します。成果物は `routes.json` で、使う車両ごとに出発時刻（`HH:MM`、省略時は05:00）と訪問順の店舗を記載します。
評価器はこの計画をワールドの移動モデルで走らせ、参照解と比べて採点します。

このケースには設定がありません。どの難易度でも同じ一つの固定問題です（ティアもルールセットもありません）。進め方の
調整項目（仕様をすべて渡すか先に質問させるか、顧客のペルソナ、データのノイズ、イベント）は、ほかのすべてのケースと同様に
その上に適用されます（[cases/README.md](../../README.md) を参照）。このケースはフレームワークのテストフィクスチャ
（`tests/conftest.py`）でもあるため、検証を高速なまま保つ必要があります。

## データ

`cafes`（18店舗 C01–C18：`x_km` / `y_km` はキッチン (0, 0) からの相対位置、`trays` 8–30、`tier`
premium/standard、`opens`、`deliver_by`、`partner_brand`）と `vans`（V1–V4、`max_trays` 120、冷蔵車はV4のみ）
からなります。ファイル名、ヘッダー、ラベルはローカライズされています（`매장목록.csv` の `매장등급 = 프리미엄`、
`cafeterias.csv` の `categoria = premium`）が、IDと数値はローカライズしません。休業中の店舗も普通の1行にすぎず、
休業していることは顧客だけが知っています。

ケースシード（20261025）では、営業中の17店舗にトレー356枚を届け、車両全体の積載能力は480枚です。提携店舗は
港町店（C05、標準店）、時計台店（C10、旗艦店）、競技場前店（C16、旗艦店）で、ほかの旗艦店はC01、C04、C07、C13です。

## 顧客が知っていること（隠れた要件）

- 道路距離は直線距離の1.3倍です。速度は区間の出発時刻で決まり、07:00より前は時速30km、07:00以降は時速20km
  （朝の渋滞時間帯）です。荷下ろしには4分に、トレー1枚あたり0.2分を加えた時間がかかります。
- `opens` より前に着いた車両は待ちます。`deliver_by` を過ぎた到着も受け入れられますが、遅れた1分ごとに、車両の
  稼働3分と同じだけのコスト（クレーム、納品代金の値引き）がベーカリーにかかります。
- 車両は05:00から出発し、09:30（ドライバーの勤務終了）までに戻ります。1台に積めるのは `max_trays` 枚までです。
- 南山店（C11）は今週改装のため休業です。
- `partner_brand` の店舗は提携先の冷蔵商品を扱うため、冷蔵車V4しか配送できません。
- 各店舗は、1台の車両の1回の訪問でトレーをすべて受け取ります。
- 会社の慣習：どのルートでも旗艦店が標準店より先です。

確認すべき事項は9つです：道路距離、速度、荷下ろし時間、勤務時間、休業店舗、コールドチェーン、1回の訪問、旗艦店優先、
遅延コスト。

## ルール

| ルール | 区分 | 意味 |
|---|---|---|
| `van_capacity` | 物理的 | 車両1台に積めるトレーは最大120枚です。 |
| `shift_window` | 物理的 | 車両は05:00以降に出発し、09:30までにキッチンへ戻ります。 |
| `closed_cafe` | 物理的 | 休業中の店舗（C11）には配送しません。 |
| `serve_each_once` | 契約上 | 営業中の全店舗にちょうど1回ずつ配送します。 |
| `cold_chain` | 契約上 | 提携ブランドの店舗には冷蔵車だけが配送します。 |
| `premium_first` | 業務慣行 | どのルートでも旗艦店が標準店より先です（業務慣行を緩和可能とする方針のもとでは、例外手続きを経て緩和されうる）。 |

**品質（低いほど良い）：** 全車両が出ている時間（出発から帰着まで。まだ開いていない店舗での待ち時間を含む）の合計に、
店舗への到着が `deliver_by` を過ぎた分数の3倍を加えた値です。

## 含まれる状況

- **隠れた事実：** C11は今週休業ですが、データのどこにもそうは書かれていません。
- **データの意味：** `partner_brand = yes` は冷蔵商品を意味するため、冷蔵車でしか配送できません。
- **緩和されうる慣習：** 旗艦店優先。このシードでは、この慣習のためにV4がC05より先にC16とC10を回ることになり、
  ルールを守るどの計画でも、C05には `deliver_by` の07:30より約10分遅れて着きます。
- **トレードオフ：** 遅く出発すれば、まだ開いていない店舗での待ちを避けられますが、07:00以降に始まる区間は遅くなり、
  遅れた到着のコストは3倍です。
- 日付の決まったイベントも、ステークホルダーからの圧力もありません（REVIEW.md の F8 を参照）。

## 参照解とベースライン

**参照解**（`_solve`）は、最小コストの実行可能挿入（提携店舗を先に、次にランク順、大きい店舗から）でルートを作ります。
貪欲な構築が行き詰まった場合は、提携店舗の実行可能な順序ごとにV4をその順序で始めてやり直し、さらに挿入順序をシャッフル
してやり直します。その後、目的値が下がる間は訪問先を1つずつ移し替え、各ルートに5分刻みのグリッド上で最良の出発時刻を
与えます。

**ベースライン**（`baseline_solution`）は、エンジニアなしで配車担当者が自分で組む計画です。V4が提携店舗を受け持ちます
（旗艦店を先に、最も早く戻れる順序で）。ほかの店舗は真西から始めてキッチンの周りを回る方位角の順に並べ、次の店舗が
入らなくなるまで（積載能力、09:30までの帰着）V1、V2、V3、そしてV4に順に積みます。各車両は旗艦店を先に回り、残りは
開店順に回ります。どの車両も勤務開始の05:00に出発し、`deliver_by` は考慮しません。店舗が余った場合は、方位角順の
次の店舗から回り直します（どの開始点でもうまくいかなければ、すべての車両を05:00に出発させて参照解のルートを走らせます。これは常に
有効で、これまでに作ったワールドでこれが必要になったものはありません）。

| シード 20261025 | 目的値 | 稼働時間（分） | 遅延時間（分） | ルート |
|---|---|---|---|---|
| 参照解 | 625.55 | 592.74 | 10.94 | V1 06:20 C01 C04 C15 C08 · V2 06:00 C13 C07 C18 C06 · V3 05:45 C09 C03 C14 C02 C17 · V4 06:10 C16 C10 C05 C12 |
| ベースライン | 963.09 | 897.53 | 21.85 | V1 C03 C14 C02 C17 · V2 C07 C13 C09 C18 C06 C12 · V3 C01 C04 C08 C15 · V4 C16 C10 C05、すべて05:00出発 |

ベースラインの余分なコストの大半は待ち時間です。05:00に出発すると、車両は06:00以降に開店する店舗に早く着きすぎます。

ほかのワールドシード（`validate-case` のパネルと、さらに2つ）：

| ワールドシード | 参照解 | ベースライン | ベースライン / 参照解 |
|---|---|---|---|
| 1 | 568.06 | 1,292.28 | 2.27 |
| 2 | 779.02 | 1,192.03 | 1.53 |
| 3 | 560.91 | 1,402.46 | 2.50 |
| 7 | 543.02 | 939.29 | 1.73 |
| 42 | 532.93 | 1,415.56 | 2.66 |

ケースシードとワールドシード1–50の計51ワールドすべてでベースラインは有効で（フォールバックは一度も使われません）、
コストは参照解の1.37～4.16倍（中央値2.19）です。`validate-case --world-seeds 1,...,50` は通ります。

**改善余地**（シード20261025。「q」は正規化品質で、ベースラインが0、参照解が1）。参照解から始めた焼きなまし法
（simulated annealing）の探索（移し替え・交換・2-opt の操作、出発時刻は分単位。ケースには含まれない分析用スクリプト）は、
すべてのルールのもとで601.51に達します。q = 1.07 で、方針の品質上限1.5のもとで品質点の0.71を得ます（参照解は0.67）。
この計画の積載量は89/85/115/67枚、最も遅い帰着は09:21なので、積載能力も勤務時間もここでは制約になっていません。
`premium_first` を緩和すると、同じ探索は遅延なしで521.98（q = 1.31）に達し、4ルートのうち3ルートで慣習を緩和します。

## 補足

- 合成データです。位置、トレー数、開店時刻、速度、荷下ろし時間、遅延の重みは架空の値です。速度は区間の出発時刻に
  応じて07:00で一段切り替わるだけで、時間依存の移動モデルではありません。
- `build_world` は、参照ソルバーがすべてのルールを守る計画を見つけ、かつどのルールにもそのルールだけを破る計画が
  見つかるまで、シードの乱数列から引き続けます。そのため、どのワールドシードでも使えるワールドができます。
- `validate-case` は、参照解の品質が1.0であること、ベースラインが有効で参照解より悪いこと、ルールごとにそのルール
  だけを破る成果物が1つあること、5つのロケールでデータが決定的であること、そしてワールドシード1、2、3を確認します。
