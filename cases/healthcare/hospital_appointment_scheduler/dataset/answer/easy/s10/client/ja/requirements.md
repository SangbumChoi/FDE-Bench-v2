# 外来の日次予約プログラム

## 背景

11月9日（月）から、外来予約係の業務をプログラムで回したいと考えています。毎営業日、その日の新しい予約依頼・キャンセル・各種連絡と現在の予約状況を受け取り、医師の空き枠に患者さんを予約して、診療科ごとの状況を報告するプログラムです。何よりも、空き枠のせいで医師の診療時間が無駄になるのを減らしたいのです。作っていただけますか。予約システムのエクスポート（医師、外来枠表、過去4週間の予約依頼と予約実績およびその結果、キャンセル、来院記録、待機リスト）、予約係が受け取ったメール（休診、メモ、外来管理室からの連絡）、そして試行日1日分（プログラムが受け取る入力と試行版プログラムの回答）を添付します。

プログラムは **2026年11月9日（月）から12月4日（金）までの20営業日** で動かして評価します。この期間はデータに含まれておらず、その中の依頼はすべて初めて見るものです。

## 成果物

`program/` フォルダに、**`on_day(day)`** を定義した `scheduler.py` を入れてください。ほかに必要なものも同じフォルダに置きます。Python の標準ライブラリだけを使ってください。エンジンにはネットワークがなく、実行中はデータファイルを読めないので、データから学んだことはフォルダ内に写しておく必要があります。

- エンジンはプログラムを **一度だけ** 読み込み、営業日ごとに順番に `on_day` を1回ずつ、同じプロセスで呼びます。モジュール変数は翌日まで残ります。1回の呼び出しは10秒までです。実行中は誰にも質問できないので、以下のルールはすべてプログラムに組み込んでおく必要があります。
- 呼び出しは **その日の業務終了後** に来ます。当日の外来はもう終わっており、予約は翌日からです。
- `day`（`試行日_入力例.json` がエンジンの実際の呼び出し1回分そのままです）:
  - `date`、`day_index`（0〜19）、`days_in_period`（20）、`period_end`
  - `booking_window`: `first`（翌営業日）と `last`（10営業日先）。予約はこの期間内にしか入れられません。
  - `doctors`: `doctor_id`、`department`（コード: IM、CARD、DERM、ORTH、PED）、`languages`（コード、エクスポートの `languages` テーブルと同じ）
  - `sessions`: 予約可能期間の外来枠表。医師・日付・セッション（`AM` 09:00〜12:00、`PM` 13:00〜16:00）ごとの20分枠の開始時刻
  - `new_requests`: 本日受け付けた依頼。各件に `request_id`、`patient_id`、`received`、`department`、`visit_type`（`new` 初診、`follow_up` 再診）、`previous_doctor`（再診）、`urgency`（`U` 緊急、`S` 早期、`R` 通常）、`triage_note`、`preferred_language`、`earliest_date`、`referral_valid_until`（初診）、`pre_visit_test`（空腹時採血が必要なら true）、`past_appointments` と `missed_appointments`（当院での受診記録）、`notes`（職員のメモ）があります。
  - `notices`: 本日受けた連絡。`cancellation`（患者さんの予約キャンセル）、`doctor_absence`、`interpreter_absence`、`staff_note`（形式は試行日ファイル参照）
  - `attendance`: 本日の予約と、患者さんが来たかどうか
  - `book`: 明日以降のすべての予約。それまでの呼び出し（11月9日より前は予約係）が残したとおりで、`request_id`、`doctor_id`、`date`、`start`、`slots`、`test_date`、`booked_on`、`request` があります。
  - `waitlist`: 昨日までに受け付け、まだ予約がない（キャンセルされていない）依頼
- 戻り値は `{"actions": [...], "status_table": {...}}` です（`試行日_出力例.json` 参照）。
  - `{"type": "book", "request_id", "doctor_id", "date", "start", "test_date"}`: 待ちリストまたは本日の新規依頼を予約します。`start` は最初の枠の時刻（`HH:MM`）、日付は `YYYY-MM-DD`、`test_date` は採血日または null です。
  - `{"type": "move", ...}`（項目は同じ）: 既存の予約の医師・日付・時刻（または採血日）を変えます。
  - `{"type": "release", "request_id"}`: 病院側で予約を取り消し、依頼を待ちリストに戻します。
  - アクションは順番に適用します。1件の依頼に予約は最大1つです。予約しなかった依頼は待ちリストに残り、翌日また届きます。
  - `status_table`: 診療科コードごとに1行。定義は後述します。
- キャンセルの連絡が届いた時点で、その予約はすでに `book` から消えており、その依頼は終了です。

## データについて

- `予約システム_エクスポート.sql`: 11月6日（金）業務終了時点の予約システムのテキスト形式の SQL ダンプです（`sqlite3 booking.db < 予約システム_エクスポート.sql` で読み込めます。先頭のコメントにテーブル一覧があります）。5診療科の医師14名と対応言語、週間の外来担当、10月12日〜11月20日の外来枠表、予約依頼、10月12日〜11月6日の予約とその結果（来院、無断欠席、患者キャンセル）および11月9日以降の予約済み分、キャンセル、来院記録、待機リストの履歴、試行日の状況表が入っています。営業日は月〜金で、市民の日（11月23日（月））も病院は通常の営業日です。
- `mail/`: 予約係が受け取ったメール（`.eml`）。医師の休診、通訳の不在、部長や院長室からのメモ、外来管理室からの連絡です。こうした連絡はプログラムには `notices` と依頼の `notes` として届きます（試行ファイル参照）。
- エクスポートとメールは学ぶための履歴で、プログラムが必要とするものはすべて `day` に入ってきます。
- 診療時間: **初診** は同じ医師・同じセッションの **連続した2枠**（最初の枠の時刻で予約）、**再診** は1枠です。
- 依頼はその `department` の医師に予約し、`earliest_date` より前には決して入れません。依頼の **最短受診可能日** は、`earliest_date` と受付翌営業日のうち遅いほうです。
- `triage_note` は参考情報です。

## 予約ルール

**緊急の依頼**

- **緊急（U）** の依頼は **受け付けた当日に** 予約し、最短受診可能日から **2営業日以内**（その日か、その後の2営業日のいずれか）に入れなければなりません。あとで動かす場合もこの範囲を出てはいけません。
- **緊急用の確保枠:** **すべての午前セッションの最初の2枠（09:00と09:20）** は緊急の依頼のために空けておきます。2営業日以上先なら U の依頼しか使えません。前営業日の呼び出しで（つまり翌日の外来分は）解放され、誰でも予約できます。

**誰が誰を診るか**

- 再診は患者さんの `previous_doctor` に予約します。患者さんは自分を知っている医師を期待しているからです。ただしこれは当院の慣行で、保健当局との契約上のルールではないため、外来運営室長が例外を認めることができます。
- 通訳: 医師が患者さんの `preferred_language` を話せない場合は通訳が必要です。病院全体で **対面通訳者は1日3名** で、**初診** には必ず対面通訳が要るため、患者さんの言語を話せない医師との初診は1日最大3件です。再診は電話通訳で、制限はありません。
- 祝日: **11月23日（月）の市民の日** は **整形外科が休診** です。ほかの診療科は通常どおり診療します。外来枠表は直していないので、`sessions` にはその日の整形外科のセッションがそのまま出てきます。11月23日に整形外科の予約は入れません。

**患者さんの予約の変更**

- 病院が患者さんの予約の **日付や時刻** を変えるとき（移動、または取り消して当日かそれ以降に取り直す場合）、新しい予約は **変更した日から3営業日以上先** でなければなりません（取り消してから取り直す場合は、取り消した日から数えます）。患者さんにそれだけ前もってお知らせする必要があるからです。同じ日付・同じ時刻のまま医師だけを替える場合は、この予告期間は要りません。
- 病院が予約を変えるたび（移動または取り消し）、患者さんの負担になり、点数でも差し引かれます。理由なく予約を動かさないでください。

**待ちリスト**

- 待っている依頼は当院の **優先順位** で予約します: まず緊急度順（U、S、R）、同じ緊急度の中では受診可能日（earliest_date）の早い順、つまり早く来られる患者から。
- 同じ診療科・同じ受診区分・（再診なら）同じ前回担当医で、**より優先順位の高い** 依頼がその日の終わりにまだ待っていて、その枠を使えたのであれば、それより低い依頼を予約してはいけません。待っている依頼がその枠を使えなかった場合は問いません: 受診可能日がその枠より後の場合、その医師では通訳が必要な初診で、予約されたほうは不要であり、かつその日の対面通訳者がすべて埋まっている場合、プログラムがその予約を取り消していて、その枠が取り消した日から数えた予告期間内の場合です。
- 実際には、空いている枠と新しく空いた枠を待ちリストから優先順位どおりに埋めてください。今いちばん医師の時間を無駄にしているのは、キャンセルされた枠と、翌日分として解放された緊急用確保枠です。

**今回の範囲**

- `doctor_absence` と `interpreter_absence` の連絡: 今回は範囲外です（代診医と外部の通訳会社でまかないます）。何もなかったものとして予約してください。
- 紹介状と採血: 今回は紹介状の確認は紹介窓口が、空腹時採血の予約は検査室が患者さんと直接行うので、`referral_valid_until` と `pre_visit_test` は気にせず、`test_date` は null のままにしてください。
- 無断欠席: 今回は無断欠席を見込みません。予約した患者さんは全員来るものとします。`attendance` は参考情報です。
- 同じ患者さんからの2回目の依頼: 依頼だけでは同じ症状かどうか分からないので、今回は依頼1件ごとに予約を取ります。重複かどうかは外来で患者さんに確認します。

## 状況表

毎日、アクションを適用したあとで、診療科コード（`IM`、`CARD`、`DERM`、`ORTH`、`PED`）ごとに、**予約可能期間**（次の10営業日）について整数を3つ返します。

- `free_slots`: その診療科の医師の外来枠のうち、予約が入っておらず誰でも予約できる枠の数。緊急用に確保している枠（下記）と、休診する診療科（祝日）の枠は除きます。
- `held_back`: 2営業日以上先の緊急用確保枠（午前セッションの09:00と09:20）のうち、予約が入っていない枠の数（除外の基準は同じ）
- `waitlist`: アクション適用後もまだ待っている、その診療科の依頼の数（本日までに受付、予約なし、キャンセルでない）。

各項目は完全に一致したときだけ正解です。1日の点数は15項目のうち正解の割合で、状況表の精度は20日間の平均です。

## 評価方法

**必須条件**（1つでも破るとプログラムは認められません）:

- すべての呼び出しが、実在する依頼について正しい形式のアクションを返すこと（予約は待っている依頼だけ、移動・取り消しはこれからの予約だけ、日付は予約可能期間内）。呼び出しが落ちたり時間切れになったりすると違反です。
- 1つの枠に予約が2件入らないこと。
- 外来枠表の枠だけを使う（初診は1セッション内の連続2枠）、正しい診療科、受診可能日より前に入れない、11月23日に整形外科の予約なし、通訳が必要な初診は1日最大3件。
- 緊急の依頼は当日に2営業日以内で予約、2営業日以上先の緊急用確保枠を守る、日付・時刻の変更は3営業日以上前に予告、待ちリストの優先順位を守る。
- 再診は前回担当医に（慣行であり、例外は可能）。

**品質** = 0.8 ×（運営価値 ÷ 同じ期間の当院の基準プログラムの運営価値）+ 0.2 × 状況表の精度。高いほど良いです。**運営価値** は次のとおりです。

- 11月10日から12月7日までの外来日に **診察した患者枠ごとに +10**（初診は2枠、再診は1枠）。当院がいちばん重視している部分で、空き枠1つ1つが無駄になった医師の時間です。
- 依頼が待った営業日ごとに − 0.4 × 緊急度の重み（U 3、S 2、R 1）。最短受診可能日（それより前なら11月10日）から予約日まで、最後まで予約がなければ12月8日まで数えます。
- 最後まで予約されなかった依頼ごとに − 10（12月18日より前に来られない依頼は数えません）。
- 病院が患者さんの予約を変えるたび（移動または取り消し）に − 4。
