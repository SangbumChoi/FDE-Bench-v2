# 家庭生活补助审批

## 背景

我们家庭生活补助的申请积压了大约300件。能帮我们判定哪些家庭符合条件、每月各发多少吗？申请清单、家庭成员、资产申报、去年的金额表以及发给居民的须知都附上了。须知是写给居民看的，故意没有写具体数字，准确的规则如下。

## 交付物

一个CSV文件 `determinations.csv`，表头为ASCII的 `household_id,eligible,monthly_amount,reason_code`，`申请清单.csv` 中每个申请一行：

- `household_id` 与数据中的家庭编号完全一致（如 H001）；
- `eligible` = `yes` 或 `no`；
- `monthly_amount` = 今年的每月补助金额（不符合条件时为 0）；
- `reason_code` = 以下之一：`APPROVED`（新申请通过）、`RENEWAL`（续期通过）、`DENY_RESIDENCY`、`DENY_ASSETS`、`DENY_INCOME`。`APPROVED` 和 `RENEWAL` 只能配 `eligible = yes`，`DENY_` 开头的只能配 `eligible = no`。同时有多个原因时，按居住、资产、收入的顺序取第一个。

## 数据说明

- **家庭人数**：只计算 `家庭成员.csv` 中 `居住在申请地址` = 是 的成员。住在别处的成员（在外地上学的子女、在国外工作的配偶等）不计入家庭人数，他们的收入、残疾等情况也完全不考虑。
- **日期**：`申请清单.csv` 中的 `申请日期` 和 `本市居住起始日` 写作“2025年3月5日”的形式。
- **居住要求**：在申请日期当天，家庭须已在本市居住满6个月，即 `本市居住起始日` 不得晚于 `申请日期` 往前推6个月的同一天（2026年9月14日申请 → 须在2026年3月14日或更早开始居住）。这是法定条件。不满足的：不符合条件，`DENY_RESIDENCY`。
- **资产**（`资产申报.csv`）：把申报价值全部相加，但不算自住的房子（`自住房产`）和一辆车（有多辆车时，价值最高的一辆免计，其余照算）。这个可计资产合计超过“单人家庭6,000，申请地址每多一名成员加3,000”的，不符合条件：`DENY_ASSETS`。
- **今年的金额**：`2025年度金额表.csv` 是去年的表。今年的基本生活金额和住房补贴上限是去年的数值上调3.2%，再各自向下取整到10的倍数（单人：640 → 660，380 → 390）。新表还没有公布，所以数据里没有。
- **所需金额**：对应家庭人数的基本生活金额 + 月租金（不超过该人数的住房补贴上限；自有住房无租金的，住房部分为0）+ 申请地址每名 `残疾` = 是 的成员120。
- **可计收入**（只算住在申请地址的成员，均为月额）：工资收入按人计算，每位有工资的人前150不计，剩余部分再扣除30%，即按每人（工资 − 150）的70%计入。养老金、失业金、`子女抚养费` 和其他收入全额计入（子女抚养费也是家庭收入，虽然有些居民认为不算）。
- **发放金额**：所需金额 − 可计收入，向下取整到整数，且不超过该家庭人数的预算法上限：1人1,050，2人1,450，3人1,800，4人2,100，5人2,350，6人及以上2,550。结果为0或以下的，不符合条件：`DENY_INCOME`。
- **续期**（`申请类型` = 续期，带有 `上年度月发放额`）：为了加快处理，我们的惯例是续期申请不重新审核，直接按上年度的月发放额批准（原因 `RENEWAL`）。所有续期家庭都已满足居住和资产条件。

## 评判方式

**硬性约束**（任意一条不满足，整批结果无效）：

- 不得批准居住未满6个月的家庭。
- 不得批准超过资产上限的家庭。
- 每月金额不得超过对应家庭人数的上限。
- 每一行都有与决定一致的有效原因代码。
- 续期申请必须按上年度月发放额原额批准。

**质量**：所有家庭实际发放金额（不符合条件为0）与按今年规则应得金额之差的绝对值之和，再加上每个判错资格的家庭400。越低越好。
