### ルールシード（ルールセット A/B/C からの移行）

固定の3つのルールセットは、ルールシードがパラメータごとに1つずつ抽選する候補プールになりました（README の「ルールパラメータ」）。データ、依頼、価格メール（W4 以降に発注する S03 の C01 は +20%、発注週で採点）は変わっていません。例外は11月の予算で、下記の調整により125 M から115 M に変わりました。

- **プール。** `usd_krw` は easy と medium で 1,380 · 1,450 · 1,320 · 1,500、hard で 1,380。`safety_weeks` はすべてのティアで 1 · 1.5 · 0.5。`max_share` は easy と medium で 80 · 70 · 90%、hard で 80%。`quality_hold`（仕入先と最後の週を1つの値として）は easy と medium で以前の A/B/C の組である S07（W3 まで）· S05（W4 まで）· S01（W4 まで）、hard で S03（W5 まで）· S05（W5 まで）· S01（W5 まで）。公開ルールシードは `rule_seeds: [42, 3, 78]` で、計画レートの1つを除くすべての候補が現れます（シード3つ、レート4つ）。
- **効き方（検証器、ワールド 20261123、1、2、3）。** 最初の公開シードから：medium では計画レート 1,320 → 1,500 で参照解が +1.17 / +2.22 / +1.79% 動き、ワールド 3 で予算を超えます。割合の上限 90% → 80% では4つのワールドすべてで無効になります。hard では安全在庫 1 → 1.5週で +10.3 から +11.9% 動き、保留 S03（W5 まで）→ S01（W5 まで）で4つのワールドすべてで無効になります。
- **効かなかったため外したもの、まとめたもの。** 保留の週だけを変えること（hard で S03 の W4 → W5 は何も変えなかった。11月の予算がすでに S03 の発注を W3 に押し出している）。そのため保留の週は仕入先と一緒に抽選します。hard の計画レートと割合の上限（1,320 → 1,550 はワールドによって hard の参照解を0.6–1.4%動かし、上限90%の参照解は4つのワールドのうち2つで上限70%の下でも有効だった）。そのため hard は 1,380 と 80% のままです。予算のパラメータとして試した月次予算の財務の留保（0 / 5 / 10%）は、hard の参照解を0–1.3%動かしただけでした。hard 用の60%の割合の上限は採用しませんでした。参照解の、明細を丸ごと移す2社目の手順では、C02 と C25 でそこに届きません。
- **admissible()** は、仕入先の品物がそもそも到着しうる前に終わる保留を退けます（S03 と S05 は11–13営業日で見積もっているので W4 より前には何も届かず、「S05（W3 まで）」は何も変えず、違反例もありません）。プールにそのような値はなく、このフックは編集に対する安全装置です。
- **プール全体での予算の調整。** 11月の上限は、すべてのティアの許容される225通りの組み合わせ全体での、制約なしの11月の支出の最小値の95%なので、ルールシードが何を抽選しても効きます（以前は easy/C が上限125 M に対して125.1 M を使っていました）。12月と1月はすべての組み合わせに対して余裕を保ちます。
- **すべての組み合わせで有効な参照解とベースライン。** 非公開のシードはどんな組み合わせでも抽選しうるので、予算の手順は、間に合うように後ろ倒しできる明細がないときにもう例外を投げません。明細を1つ遅らせて移す、1月の超過分を W6 に前倒しする、明細を1つ削る、のいずれかを、後ろ倒しにした1ウォンあたりの追加コストが最も安いものから行います。ベースラインも同じ代替手段を使います。このワールドでは225通りすべてで、参照解は有効で、ベースラインは有効かつそれより悪くなります。
- **より強い参照解。** 1週ロットと残り在庫のトリム（部品にまだ必要な分まで明細を減らすか、同じ週に最小発注数量の小さい仕入先に置き換える）も試すようになり、変種は全部で8つです。トリムは必要でした。トリムがないと、このワールドで抽出した easy の162設定のうち30設定でベースラインが参照解を上回り、すべて安全在庫が0.5週でした（計画期間の終わりに、2社目の供給元の最小発注数量の分だけ買いすぎる）。公開ルールシードでのベースライン/参照解の比：easy 1.054–1.091、medium 1.046–1.065、hard 1.156–1.377。
- **まだ未対応。** 他のワールドでは、easy と medium のいくつかの組み合わせで、ベースラインがなお参照解と並ぶか上回ります。すべて Kowon Passive（S07）が W3 まで保留で、ほとんどが安全在庫0.5週の組み合わせです。ワールド 1 ではなし、ワールド 2 では medium の108通りのうち9通り（最大1.6%）、ワールド 3 では easy 2通りと medium 3通り（最大0.2%）です。参照解の2週ロットは発注を11月に前倒しで集め、より速く高い仕入先への後ろ倒しは、ベースラインの小さなロット・フォー・ロットの明細より高くつきます。このとき品質は単純な比率に戻ります。これは F2 に属します。
- **チェック担当者のフォローアップ（解決済み）。** 非公開ルールシード 4–10 をワールドシード 1–3 で確認したところ、これらの組み合わせに当たりました。ルールシード 6 と 8（S07 が W3 まで保留、0.5週）では、ワールド 2 と 3 の easy と medium で、ベースラインが参照解より0.1–1.6%低くなっていました。参照解は現在15の変種のうち最も安いものを採ります。上記の8つ、同じプランナーでトリムを予算の手順の後だけに行うもの（先にトリムすると、予算の手順にはより高い後ろ倒ししか残らないことがある）、そして重要部品の各発注を割合の上限で分けるロット・フォー・ロットのプランナーに3つのトリムの選択肢を組み合わせたものです。それらの組み合わせでは、予算の手順の後にトリムするクォータ方式のプランナーが勝ち、ベースラインより1.0–1.4%低くなります（トリムが、ベースラインが残す計画期間末のロットを削ります）。ワールド 20261123、1、2、3 のそれぞれで225通りすべてが、有効な参照解と、少なくとも1.0%悪い有効なベースラインを持つようになりました（ベースライン/参照解の比の最小値は1.0098、ワールド 2 の medium。hard は少なくとも1.128）。公開ルールシードの参照解：easy/s42 505.86 → 503.68、easy/s3 573.41 → 564.63、medium/s42 513.61 → 504.47、medium/s3 558.17 → 556.57、medium/s78 482.66 → 479.39、hard/s3 609.07 → 608.79、hard/s78 514.40 → 514.19 M KRW。ベースライン/参照解の比は easy で1.054–1.100、medium で1.053–1.085、hard で1.156–1.378です。データと予算の調整は変わっていません（調整にはトリムなしの既定のプランナーを使います）。

### F1 — 強い計画にとって、2社購買の慣行を緩和する価値がない（高、一部確認）

要件は `dual_source_critical` について「実際にコストが下がるなら」例外を認めています。旧尺度では緩和は一度も得になりませんでした。局所探索の計画で節約は0.2–2.1%（hard では0%）、品質は1.0で頭打ちになり、緩和したルールには0.05または0.1のコストがかかります。新尺度では、弱い計画だけが緩和で得をします。参照解の水準では、2社目の手順をなくすと easy と medium で目的値が2.5–4.8%下がります。これにより正規化品質は1.0から1.27–3.25に上がり、最終スコアで +0.11 から +0.20 となってペナルティを上回ります。局所探索の計画では、同じ手順の節約は0.6–2.0%（hard では0–0.3%）にとどまります。そこでの品質は、easy/B（+0.02）と hard/B（+0.005）を除いてすでに上限1.5を超えています。つまり得になるのは慣行のコストのためではなく、ベースラインとの差が小さいため（F2）です。

**状況：** 未対応 — 提案：強い計画でも緩和が得になるべきかを決めます。そうすべきなら、高額な重要部品（C05 PCB、C06 ディスプレイ）で2社目の供給元を構造的に高くするか遅くする、あるいは C01 と C03 の安い代替である S04 をなくします。そのうえで最適化した計画で利得を測ります。easy と medium で少なくとも3–5%あり、上限を適用した後もペナルティより価値があるべきです。hard では慣行に実際のコストを持たせます。たとえば2社目の供給元を遅れがちな仕入先からしか選べないようにします。上限の位置が誰が得をするかを決めるので、F2 の調整後に再確認します。

**状況（ルールシード）：** 未対応。公開ルールシードで測り直しました。2社目の手順なしの最良の計画は easy と medium で2.6–4.0%（medium/s3 では0.2%）節約し、hard では何も節約しません。hard の参照解がすでにそのような計画だからです。15の変種による参照解の後（ルールシード、チェック担当者のフォローアップ）：easy で1.4–3.6%、medium で0.2–3.3%、hard で最大0.3%。

### F2 — 弱い貪欲法の参照解と、後ろ倒しした明細が元の最小発注数量のままだった問題（高、確認済み）

hard の3設定すべてで、`_defer` は W1 の C04 の明細（S03、最小発注数量4,100）を W3 の S09 に移し、まだ必要なのは1,386個だけなのに4,100個をすべて残していました。残りの2,714個は廃棄され、3.80 M KRW のコストになりました。参照解はまた素朴な貪欲法でもあります。平滑化した遅延率の最小値が S09 の8.3%なので、5%の安全リードタイムのしきい値は何も決めていません。first-improvement 局所探索は参照解を3.0–11.1%上回ります（品質比1.030–1.111）。新尺度でこの探索は q 1.25–4.90 となり、9設定中6設定で上限1.5を超えます。A と C の easy と medium では、ベースラインは参照解より2.1–2.8%高いだけなので、小さな改善が大きく見えます。他の ワールドシードでは差がもっと小さいことがよくあります。シード 1–40（39のワールドが生成される）では、easy と medium の234設定のうち15設定でベースラインが参照解の2%以内で、最も小さいもので0.6%です（シード 5 medium/A、シード 17 easy/A）。そこでは参照解より1%良い計画がすでに q 2.5 を超えます。hard ではベースラインは参照解の1.08–1.29倍のままです。

**状況：** 今回の変更で修正済み：`_defer` のバグ。移した明細は、`_resize` によって、新しい予定入荷の時点からその部品にまだ不足している数量に決め直されるようになりました。プランナーと同じ方法で丸め、元より増えることはありません。hard では C04 を1,400個買うようになり、廃棄は0.02 M に下がります。参照解は −3.6% から +0.1% 変わります。hard は −1.5/−3.6/−2.0%、B の設定は約 −3.5% です。easy/A は0.12%悪くなります。比率による貪欲な後ろ倒しが、今は11月に必要な分より多く後ろ倒しするためです。12月の上限は参照解より5%高く調整するため、データ上は525 M から490 M に下がります。未対応 — 提案：参照解を最適に近づけます。局所探索か固定ソルバーを使う MILP を同梱するか、hard では実績の推定値に基づく期待コスト探索を使います。安全リードタイムのルールに意味を持たせます。たとえば仕入先の推定遅延率と1週間分の保管コストを比べます。そのうえで case.yaml の `quality_cap` を既知の最良の正規化品質から設定するか、ベースラインとの差を広げて、汎用の最適化器が飽和しないようにします。

**状況（ルールシード）：** 一部改善。参照解は現在、8つのプランナーの変種（2社目の手順の有無、2週または1週ロット、最後の明細を減らすか別の仕入先に置き換える残り在庫のトリムの有無）のうち最も安いものを採り、予算の手順は遅らせた移動、前倒し、削減に切り替えることで、すべての組み合わせで有効です。公開ルールシードでのベースラインとの差は広がりました。easy と medium で1.046–1.091（以前は1.021–1.113）、hard で1.156–1.377です。まだ未対応：局所探索の改善余地は測り直しておらず、安全リードタイムのしきい値は依然として何も決めず、ワールドシード 2 と 3 では easy と medium の432通りのうち14通りでベースラインが参照解と並ぶか上回ります（「ルールシード」を参照）。この最後の点は解決しました。クォータ方式のプランナーと予算の手順の後のトリムを変種に加えたことで、参照解はワールド 20261123、1、2、3 のすべての組み合わせでベースラインを少なくとも1.0%上回ります。局所探索と安全リードタイムのルールは未対応のままです。

### F4 — 欠品待ちが基板ではなく部品1個単位で値付けされている（高、一部確認）

欠品待ちのコストは部品ごとに別々に、1個・1週あたりその部品の標準原価の5倍なので、安い部品の不足はほとんど数に入りません。hard/A の参照解は、6 KRW の MLCC C10 を11,366個・週（約384–392基板・週）待たせたままにしており、そのコストは0.34 M KRW です。基板1枚の材料費は18,210 KRW（B100）または37,534 KRW（B200）です。基板・週あたりで見ると、C10 の不足は約890 KRW、ディスプレイは74,000で、およそ83倍の差です。レビューの2,500倍は1個あたりの比率です。

**状況：** 未対応 — 提案：欠品待ちを基板・週あたりで値付けします。一つの方法は、不足1個あたり `board_penalty / qty_per_board` とし、`board_penalty` を基板の材料費の5倍か、明示したマージンにすることです。これなら部品ごとに分離できるので、厳密な期待値計算はそのまま使えます。もう一つの方法は、生産数を部品間の最小値としてシミュレーションすることです。いずれの場合も予算と参照解を再調整し、`cost_model` の事項に基板あたりの生産停止コストを明記します。

### F5 — ルールセットが入れ子になっており、予算が効くのは主に11月と B だけ（中、確認済み）

すべての数値パラメータで B が最も厳しく、C が最も緩やかです。1,450、1.5、70% に対して 1,320、0.5、90% です。ルールセットを互いに区別しているのは品質保留の仕入先です。18の交差ペアはすべて無効で、そのうち16が `quality_hold` で引っかかります（6つは2社購買でも、4つは予算でも）。今回の変更前、検証者は A と C の easy と medium で、11月の上限のコストを0.02–1.55%と測定しました。easy/C で制約のない11月の支出は125.1 M で、上限は125 M です。12月（現在は490 M）と1月は参照解に対して5%の余裕を持たせて作られています。局所探索の計画は12月に269–435 M を使います。

**状況：** 未対応 — 提案：パラメータ間の相関をなくします。たとえば A：高い為替レートと低い安全在庫、B：低い為替レート、高い安全在庫、緩い割合、C：中程度の為替レートと厳しい割合とします。少なくとももう1つのパラメータを入れ子でないものにします。どの月が厳しいか、あるいはどの部品が重要部品か割当対象か、などです。どの設定でも順守のコストが少なくとも2%になるようにルールセットごとに上限を調整し、1つのルールセットでは12月が効くようにします。

**状況（ルールシード）：** ほぼ修正済み。各パラメータを個別に抽選するので、厳しい値がそろって出ることはもうありません。たとえば公開ルールシードには、1,320 に1週と上限90%の組み合わせも、1,380 に0.5週と上限70%の組み合わせもあります。入れ子でない保留は残り、より厳しい hard のプール（S03、S05、S01 のいずれかが W5 まで）が加わりました。すべてのパラメータが4つのワールドで効きます（上記の「ルールシード」を参照）。11月の上限は今、プールのすべての組み合わせについて、制約なしの11月の支出の最小値の95%に調整されているので、easy/C でかろうじて効いていた以前と違い、すべての組み合わせで効きます（115 M。公開ルールシードでの制約なしの11月の支出は132–346 M）。12月は、後ろ倒しが積み重なるいくつかの hard の組み合わせでのみ効きます。順守のコストはどこでも2%になるわけではありません（予算のパラメータを試しましたが効きませんでした）。未対応：厳しい月は依然として常に11月です。

### F6 — 下位ティアの範囲の絞り込みがスイッチのように読め、easy の価格の文が崩れていた（中、確認済み）

easy と medium の要件は、顧客が供給割当の通知を転送しているのに、すべての仕入先がすべて確定してくれる前提で計画するよう求めています。easy はさらに、生産計画が W5 と W6 で目に見えて落ち込んでいるのに、「定価で計画」し「祝日は考えない」ように言っています。en:29 は "adjusted for the approved email, whatever its size" となっていましたが、他のロケールは「明細の大きさにかかわらず」としています。事項 `round_scope_easy` と `round_scope_medium` は、それぞれ3つと2つの事実を1つの事項に詰め込んでいます。

**状況：** 今回の変更で修正済み：崩れていた文。en:29 は現在 "every order line is priced at `unit_price` per piece regardless of its size (with the approved change from the supplier price email)" となっています。他の4ロケールも同じ箇所でメールによる変更に触れています。未対応 — 提案：範囲の絞り込みのそれぞれに、ストーリーの中で理由を付けます。たとえば次のようなものです。

### F7 — 「特定の国に依存しない」はずのシナリオが韓国の工場になっている（中、確認済み）
