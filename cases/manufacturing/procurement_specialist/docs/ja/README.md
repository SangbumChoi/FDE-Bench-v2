# 購買スペシャリスト — `manufacturing/procurement_specialist`

2機種の制御基板（B100 と、ディスプレイ付きの B200）を組み立てる受託製造業者が、エージェントに20数点の部品について8週間分の購買発注計画（W1 = 2026年11月23日の週から W8 まで）を依頼します。「生産を止めず、かつ使いすぎにならないように」というものです。成果物は `orders.csv`（`order_week,component_id,supplier_id,quantity`）です。計画は生産計画に対して W1–W10 でシミュレーションされます。舞台は一つの事実を除いて特定の国に依存しません。予算は現地通貨（KRW）建てで、1社の仕入先がドル建てで見積を出し、それを固定の計画レートで換算します。

設定はティアとルールシードの組です。ティアは今回どの顧客ルールが適用されるかを決め、ルールシードはそれらのパラメータ（計画レート、安全在庫、割合の上限、品質保留）を候補プールから抽選します。公開ルールシードは3つ（42、3、78）なので、公開の正解は9通りです。それ以外のルールシードはすべて、同じ候補からの非公開の抽選です。**エージェントはどの設定でも同じ依頼と同じデータを見ます**（検証器はプロンプトとワークスペースがバイト単位で同一であることを確認します）。変わるのは顧客だけが知っている要件（シミュレーションの顧客はこれをもとに答えます）と評価器です。進め方の調整項目（仕様をすべて渡すか先に質問させるか、顧客のペルソナ、データのノイズ、イベント）は、すべてのケースと同様にその上に適用されます（[cases/README.md](../../../../README.md) を参照）。

## データ（どの設定でも同じ）

`components`（`部品マスタ.csv`：部品24点と新しいフラッシュ C25、`critical` フラグ、標準原価）、`production_plan`（`生産計画.csv`：機種別の基板枚数、W1–W10）、`bom`（`部品表.csv`：`valid_from_week` / `valid_to_week` 付き。C04 は W1–W5、C25 は W6–W10）、`inventory`（`現在庫.csv`：抵抗は5,000個巻きのリール単位）、`open_orders`（`未入荷発注.csv`）、`supplier_quotes.xlsx`（`仕入先見積.xlsx`：`currency`、`unit_price`、`moq`、2段階の全数量割引、営業日単位の `lead_time_days`。`suppliers` シートもあり）、`approved_vendors`（`承認仕入先リスト.csv`）、`budget`（`購買予算.csv`：月ごとの上限）、`delivery_history`（`納入実績.csv`：過去の納入188件、納期回答日と入荷日）、`allocations`（`供給割当.csv`：S03/C01、S03/C03、S08/C06 の月ごとの上限）、そして `mail/`（`.eml` ファイル3通：下記の Nara Display とのメールのやり取り）があります。依頼文が納入実績、供給割当の通知、予定されているフラッシュの変更、メールのやり取りに触れているため、どのティアでもこれらが見えます。

## 仕入先とのメールのやり取り（Nara Display）

`mail/` には、ロケールごとに用意した3通のメールのやり取り（`2026-11-18_nara_display_price_notice.eml` と返信2通）があります。顧客の言語で書かれ、仕入先自身のドメイン（`naradisplay.example`）と顧客の購買部（`boardassembly.example`）から送られています。

1. Nara Display（S08）は、最も高価な部品（14,800 KRW、購買金額の約3分の1）であるディスプレイモジュール C06 の主要な供給元です。同社は見積にある C06 の単価すべて、つまり定価と2つの数量割引単価を **2026年12月9日（水）以降に同社が受領する購買発注から12%** 引き上げ、2027年1月4日からさらに8%の値上げを提案します。
2. 顧客の購買部は12%を受け入れ、8%は当面断ります（12月の予算見直しの後に部長が判断します）。
3. Nara Display が確認します。12月9日から12%で、8%は保留のままです。

つまり、どの変更が承認済みでどれが承認待ちかはデータに書かれています。顧客だけが知っているのは、発注がいつ仕入先に届くかです。すべての発注は発注週の月曜日に出すので、W3 の発注（12月7日月曜日）はまだ旧価格で、値上げは発注週 W4 から適用されます（事実 `price_rise_week`）。採点では、どのティアでも W4 から S08 の C06 を、購買金額でも月次予算でも1.12倍の価格で計算します。未入荷発注は影響を受けず、8%は一切適用しません。計画が S08 に依存しているため、この値上げは重要です。模範解答は、S08 に出すそれ以降の週の C06 の発注を、W3 の1つの明細にまとめて前倒しします（12月は予算に余裕があり、medium では大きくなった明細が2段目の数量割引にも届きます）。適用日を12月9日を含む週全体（W3）と読むプランナーは、前倒し先が11月しかなく、それは予算が許さないため、測定した easy の15設定のうち9設定と medium の15設定のうち3設定で品質の尺度の10–23%を失います（残りの設定では、模範解答の最良の計画はこの事実に左右されません）。hard では供給割当（S08 のディスプレイは月3,500個）のために発注を前倒しする余地がないので、この週は hard ではAIが確認すべき事実ではありません。値上げ自体は hard でも採点に入ります。このメールのやり取りは、ケースオーナーが以前に作った、承認済みと承認待ちを区別する価格通知（W4 から S03 の C01 を +20%、ReflectionAI の購買シナリオを翻案したもの）を作り直したものです。その通知はどの計画も変えませんでした。S04 がすでに MCU のより安い供給元だったからです。

## ルールパラメータ：ルールシードが抽選するもの

各パラメータは、設定のティアに対応する候補プールから、ほかのパラメータとは独立に抽選されます（case.yaml の `params:`）。以前のルールセット A、B、C はプールの中に含まれています。A = (1,380, 1, 80%, S07（W3 まで）)、B = (1,450, 1.5, 70%, S05（W4 まで）)、C = (1,320, 0.5, 90%, S01（W4 まで）) です。現在のルールシードはこれらを自由に組み合わせるので、最も厳しい値がそろって出ることはもうありません。

| パラメータ | easy | medium | hard | 何が変わるか |
|---|---|---|---|---|
| `usd_krw`：S04 のドル建て見積に使う計画レート（1ドルあたりのウォン） | 1,380 · 1,450 · 1,320 · 1,500 | 同じ | 1,380 | 購買金額と月次予算に入る Pacific Parts の価格。1,320 では S04 が MCU と DRAM の最も安い供給元で、1,500 ではかろうじて最安 |
| `safety_weeks`：安全在庫 = この値 × 重要部品の週平均所要量（切り上げ） | 1 · 1.5 · 0.5 | 同じ | 同じ | 計画がどれだけの在庫を積み上げて持ち続けるか。より小さい値で立てた計画が負う安全在庫不足のコスト |
| `max_share`：2社購買で、1社が重要部品の発注個数のうち取れる最大の割合 | 80% · 70% · 90% | 同じ | 80% | どれだけの数量がより高い2社目の供給元に移るか |
| `quality_hold`：品質保留中の仕入先と、その仕入先からの入荷が受け入れを拒否される最後の週 | S07（W3 まで）· S05（W4 まで）· S01（W4 まで） | 同じ | S03（W5 まで）· S05（W5 まで）· S01（W5 まで） | *どの* 部品が最も安い早期の供給元を失うか：S07 は安価な受動部品と機構部品、S05 は主要な PCB の供給元、S01 は主要なコネクタの供給元で IC の2社目の供給元にもよくなる、S03 は主要な半導体メーカー（割当対象でもあり、C25 の供給元でもある） |

テキスト用に算出される値（`derive_params`）：`hold_supplier`（各ロケールでの仕入先名）と `hold_until`（週）。`admissible()` は、仕入先の品物がそもそも到着しうる前に終わってしまう保留を退けます（S03 と S05 は11–13営業日で見積もっているので、W4 より前には両社の品物は何も届きません）。プールの候補はすべてこれを通過し、このフックは候補を編集したときの安全装置です。

プールがこの形になっている理由は次のとおりです（ルールシードを導入したときに、当時の模範解答で測定しました。検証器は変更のたびにこの拘束チェックを繰り返し、ワールドシード 20261123、1、2、3 で通過しています。すべて検証器の拘束チェックで測定しました。最初の公開シードの設定からパラメータを1つ変え、その設定の模範解答がルールに違反するか、目的値が1%動くか、もう一方の設定の模範解答がそれを1%上回れば、そのパラメータは効くとみなします）。

- **保留の週は独立したパラメータではありません。** hard で S03 の保留の終わりを W4 から W5 に動かしても何も変わらなかった（11月の予算がすでに S03 の発注を W3 に押し出し、W6 に入荷する）ため、仕入先と週を1つの値として抽選します。hard で `quality_hold` を S03（W5 まで）→ S01（W5 まで）にすると、ワールドシード 20261123、1、2、3 で模範解答が無効になります。
- **hard では計画レートと割合の上限を固定しています。** 遅延納入、安全リードタイム、供給割当のため、S04 は hard の模範解答の購買金額の4–9%しか占めないので、1,320 → 1,550 はワールドによって模範解答を0.6–1.4%しか動かさず、上限90%で作った hard の模範解答は4つのワールドのうち2つで上限70%の下でも有効でした。medium では両方とも効きます。最初の公開シード（1,320）から、1,450 と 1,500 はワールド 20261123、1、3 で予算を超え、ワールド 2 で模範解答を +1.31% と +1.82% 動かします（1,380 は0.6–0.7%しか動かさず、ワールド 3 で予算を超えます）。90% からは、80% と 70% のどちらでも4つのワールドすべてで模範解答が無効になります。1,500（慎重な財務レート）を加えたのは、最初の版の模範解答では、1,320 → 1,450 がケースのワールドで medium の模範解答を0.85%しか動かさなかったためです。
- **安全在庫**はどこでも効きます。hard で 1 → 1.5週にすると、模範解答は +8.3%（ワールド 2）から +11.9%（ワールド 20261123）動きます。
- **60%の割合の上限**は hard 用に試しましたが、採用しませんでした。模範解答の2社目への振り分けは発注明細を丸ごと移すため、ほとんどの組み合わせで C02 と C25 について60%に届きません。
- **予算のパラメータはありません。** 財務の留保（各月の予算の0、5、10%を取り置く）を試しましたが、hard の模範解答を0–1.3%しか動かさなかった（模範解答はわずかな追加コストで速い仕入先に後ろ倒しする）ため、外しました。予算はデータであり、代わりにプール全体に対して調整して（下記）、どの組み合わせでも11月が効くようにしています。

### エージェントが尋ねるべきこと

データには顧客のルールがどこにも書かれていないので、顧客に尋ねる必要があります。AIが確認すべき事実は、それぞれ1つの事柄だけを扱います（ティアごとの一覧はティアの表に、文面は `locales/<lang>/targets.yaml` に、顧客が何をもとに答えるかは CLIENT_REVIEW.md にあります）。

- ルールシードごとに抽選されるもの：平均所要量の何週分を安全在庫とするか（`safety_stock`）、割合の上限（`max_share`）、品質保留中の仕入先とその保留が終わる週（`quality_hold`。S03 が保留の場合、顧客は、保留が割当中の MCU と DRAM、新しい C25 にも及ぶと付け加えます）、そして medium では S04 のドルに使う計画レート（`usd_planning_rate`）。
- 固定のもの：部品は基板を作る週に必要なこと、`lead_time_days` が営業日であること（medium と hard ではクリスマスと元日の短い週も）、明細ごとの最小発注数量、明細ごとの全数量割引、Nara Display の値上げが始まる週（easy と medium）、予算が超えられない上限であることと週をどの月に数えるか、承認済みの仕入先のみであること、重要部品には2社の仕入先が必要なこと、そして今回の範囲（easy と medium）、または遅延、供給割当、設計変更、欠品待ちのコスト、安全在庫不足のコスト（hard）。

要件には書かれているものの、読み違えても品質の尺度の10分の1未満しか失わないため、もうAIが確認すべき事実ではないもの（GT.md の第1部）：抵抗のリール、保管コスト、easy での計画レート、hard での Nara Display の値上げの週、easy と medium での安全在庫不足のコスト（安全在庫を下限として守るエージェントは、そこでは尺度の最大0.09しか失いません）、そして hard での期待コストによる採点（その唯一の読み違えは、`supplier_lateness` がすでに扱っているものです）。

## 正解の監査

`fdebench2 audit-case`（結果は `dataset/audit.json` に保存され、GT.md は `gt_report.py` がそこから生成します）は、公開ワールドで、各ティアの公開ルールシードに、許容されるパラメータの組み合わせ12通りを加えたもの（39設定）を測ります。

- **どの事実もスコアを左右します。** 25の事実（easy 16、medium 17、hard 18）のそれぞれについて、その事実1つだけを読み違えて立てた模範解答（自然な読み違え。たとえばリードタイムを暦日とする、W2 を12月とする、値上げを W3 からとする、hard でフラッシュの変更をなしとする、hard で安全在庫を下限として守る）は、その事実が適用されるすべてのティアで、測定した設定の少なくとも1つで品質の尺度の10分の1以上を失うか、無効になります。ほとんどの事実は、ほとんどの設定でスコアを左右します。抽選されるパラメータの読み違えは別の候補値に合わせた模範解答で、最も害の小さい値で数えます。読み違えたプランナーは模範解答自身の計画も比べ、その読み方で有効かつ安いほうを採るので、ある設定で最良の計画を変えない事実は、その設定では何も失いません。
- **直接の検査。** `diagnose()` は事実ごとに `enforced`（成果物に反映されたか）を報告します。これは監査か実行の採点が求めたときにだけ計算します（validate-case は計算しません）。計画が次のどちらかに当てはまるとき、その事実は成果物に反映されていないと判定します。顧客の読み方にだけあるルールに違反している場合、または、その事実についてこれまでに見つかった最善の計画より実質的に悪く（リグレット、つまり最善の計画に対する損失が尺度の0.05を超える）、その少なくとも半分を読み違えで説明できる場合です。リグレットは、読み違えごとの模範解答のプランナー自身の計画（事実を一つだけ取り違えた解答の計画。設定ごとに一度だけ計画してキャッシュします）に対して測ります。さらに、計画が守っている別の候補の品質保留は、その計画に何らかのコストを生じていなければなりません。読み違えの制約を、その読み違えに対するプランナー自身の計画より安く守っている計画は、その読み違えに引き寄せられたとはみなしません。読み違えがプランナーに何のコストも生まない場合、読み違えで一部しか説明できない計画は判定不能（None）とします。品質保留、承認済みの仕入先のみ、明細ごとの最小発注数量は、計画がそのルールに違反していれば必ず反映されていないと判定します。模範解答はどこでも反映されていると判定され、スコアを左右する、事実を一つだけ取り違えた解答はすべて反映されていないと判定されます。すべての事実を知っている、これまでに見つかった最善の解答と顧客自身の MRP は、657の事実と設定の組のうち、反映されていないと判定されるものがどちらも0件です（読み違えの下の模範解答と比べていた以前の直接の検査では125件と228件）。プランナーの局所探索で改善する前の386の変種では、6,556の組のうち29件です（以前は2,189件）。ほかの事実とルールを共有する事実（月次予算、2社購買のルール）を取り違えた解答は、そのほかの事実も反映されていないと判定させます（GT.md の第5部、REVIEW.md の直接の検査の節）。
- **近道はふさがれています。** 空の計画、すべてを Express Parts から買う、予算を無視する、すべてを W1 に買う、バッファを一切持たない、重要部品だけを発注する、総所要量をそのまま写す、毎週同じ発注をする、顧客自身の MRP を数量割引まで切り上げる、のいずれも、すべての設定で無効になるか、スコアが0.5以下です。
- **質問は必要です。** 一度も尋ねない最良の計画（`robust_solution`：依頼文の自然な読み方、つまり依頼文のとおりフラッシュの変更を適用し、納入実績と供給割当を使い、値上げは W4 から、安全在庫は中間の候補、割合の上限は最も厳しい値、ドルは最も高いレート、すべての候補の保留を避けて計画したもの）は、easy と medium のすべての設定で無効（W6 から C04 がなくなり、仕入先が1社だけ）で、hard では0.66を得ます。質問の価値は1.00（easy）、1.00（medium）、0.34（hard）です。試した尋ねない読み方（どのティアでも同じもの）のうち、easy で0.32（依頼文に反してフラッシュの変更を無視する場合）、medium で0.13、hard で0.66より良いものはありません（REVIEW.md の2回目）。
- **限界値。** より広い局所探索（`best_known_solution`）は模範解答を0.3–3.2%上回り（品質1.03–1.31、中央値1.106）、線形緩和（`objective_bound`）は模範解答より easy で4–7%、medium で9–12%、hard で18–20%低くなります（最小発注数量と価格の段階は緩和。部品の最後の週より後に届く発注も列に含めます。有効な計画が割合のルールのためにそうした発注を出すことがあるためです）。`quality_cap: 1.11` は、これまでに見つかった最善の解答の品質の中央値なので、これまでに見つかった最善の計画は品質点の満点を得て、模範解答は0.90を得ます。

## 模範解答と従来のやり方の数値（シード 20261123）

模範解答は部品ごとの時間区分 MRP（time-phased MRP）です。展開した所要量から在庫と未入荷発注を差し引いて正味所要量を求め、まだ間に合う仕入先のうち最も安いところに、できるだけ遅く発注します。1回の発注で2週間分（または1週間分）をまかない、割引段階まで数量を切り上げたほうが合計が安ければ切り上げます（medium/hard）。次に重要部品について、割合の上限を満たすまで発注明細を丸ごと2社目の供給元に移します。余った在庫は最も遅い明細から削ります（トリム）。ある月が予算を超える場合は、まだ間に合う仕入先で発注明細を丸ごと翌月の最初の週に移します。後ろ倒しにした1ウォンあたりの追加コストが最も安い明細から移し、それぞれ新しい入荷週からその部品にまだ必要な数量に合わせて数量を決め直します。間に合うように移せる明細がなければ明細を1つ遅らせて移し、12月に余裕があれば1月の超過分を W6 に前倒しし、何も移せなければ明細を1つ削ります。こうして、ルールシードが何を抽選しても模範解答は有効になります。hard では、実績での平滑化した遅延率が5%を超えるすべての仕入先に1週の安全リードタイムを置き、供給割当を守ります。模範解答は15の変種のうち、自身のコストの見方で有効かつ最も安い計画を採ります（変種は、2社目の手順の有無と2週または1週ロットを組み合わせた正味計算プランナーと、重要部品のすべての発注を割合の上限で分けるロット・フォー・ロットのプランナーのそれぞれについて、トリムを予算の手順の前後両方で行う、後だけで行う、まったく行わない、のいずれかを組み合わせたものです）。そのうえで、評価回数を固定した局所探索（最初に見つかった改善を採る first-improvement 方式、計画6,000個、決定的）で改善します。明細を別の週や仕入先に移す、割引段階まで、または100個単位で数量を変える、明細をなくす、という操作を、すべてのルールを守ったまま行います。値上げ前の W3 に S08 のディスプレイを買うのは、この探索の働きです。使うのはエージェントに見える情報だけです。遅延は実績から推定し、真の確率は決して使いません。

従来のやり方（`baseline_solution`、正規化尺度で品質0）は、顧客がエンジニアなしで現在行っている方法、つまり ERP の MRP をそのまま回した結果に購買担当者が手直しを加えたものです。すべての部品をロット・フォー・ロット（lot-for-lot）で発注します（各発注は在庫または安全在庫が最初に不足する週をまかない、最小発注数量以上）。まだ間に合う承認済み仕入先のうち最も安いところへ、リードタイムが許す限り遅く、数量割引まで切り上げずに発注します。重要部品はクォータ方式（quota arrangement）に従います。すべての発注を、ほかの仕入先のうち最も安いところと分け、どちらも割合の上限を超えないようにします。予算を超えた月は模範解答と同じように発注明細を丸ごと翌月に移し、1月の明細は W6 に前倒しします。easy と medium では、今回の範囲のとおり約束どおりの日付で計画します。納入が遅れる hard では、購買担当者がすべての仕入先のリードタイムに1週を足します（一律のバッファです。模範解答は、実績から遅れるとわかる仕入先にだけバッファを置きます）。

データ上の予算は11月115 M、12月480 M、1月85 M KRW です。予算は、すべてのティアについて候補プールの許容されるすべての組み合わせ（225通り）で、制約なしの計画をもとに調整しています。11月は、どの組み合わせであれ11月に使う額の最小値の95%を5 M 単位で切り捨てた値なので、ルールシードが抽選しうるすべての組み合わせで効きます。12月は、ある組み合わせが12月に使う額と11月に上限を超えて使う額の合計の最大値に対して5%の余裕があり、1月は、どの組み合わせであれ1月に使う額の最大値に対して5%の余裕があります。供給割当は月あたり C01 6,500、C03 9,000、C06 3,500 です（調整用の値 1,380 / 1 / 80% / S07（W3 まで）での、制約なしの hard の計画のピーク月の60%）。

このワールドでは225通りの組み合わせすべてで、模範解答と従来のやり方は有効で、従来のやり方のほうが悪く（比は easy で1.060–1.194、medium で1.078–1.229、hard で1.086–1.233）、制約なしの計画は11月の予算を超えます。ワールドシード 1、2、3 でも、それぞれ225通りすべてで同じことが成り立ち、従来のやり方は少なくとも 7.6% / 7.3% / 6.3%（ワールド 1、easy / medium / hard）、5.3% / 5.1% / 13.1%（ワールド 2）、5.5% / 5.9% / 5.0%（ワールド 3。最も小さい5.02%は、安全在庫1.5週で Hanbit Electronics が保留の hard）悪くなります。検証器はワールドシード 1–3 で公開ルールシードを確認し、監査はティアごとにさらに12通りの組み合わせを測ります（GT.md）。

### 依頼を文字どおりに実行した解答

`literal_solution` は、依頼を書かれたとおりに実行したものです。模範解答のプランナーが、データを `robust_solution` と同じ読み方で読みます（BOM にあるフラッシュの変更、納入実績、供給割当の通知、数量割引、祝日で短くなる週は、依頼文が渡しているのですべて使います）。顧客だけが知っている事実は使いません。安全在庫なし、2社購買の慣行なし、品質保留なし、ドルは 1,380 です。どの設定でも同じ計画で、9つの公開設定すべてで無効（品質 0）です。どの設定でも重要部品を1社だけから買い（C04、hard では C25）、C01 の81%を S04 に発注します。Kowon Passive または Hanbit Electronics が保留中の設定ではその仕入先からも買い、Hanbit が保留の easy と medium（ドルは 1,450）では月次予算も超えます。

### 期待値の計算方法（hard）

遅延は最大2週なので、w週末の部品の正味在庫ポジションは、w−1週と w週に約束された納入を除けば確定しています。採点器は週ごとに、それらの納入が遅れるかどうかの組み合わせをすべて列挙し（その部品を見積もる仕入先ごとに最大2件なので、状態は最大2^8通り）、在庫保管、欠品待ち、安全在庫不足、廃棄の期待値を求めます。結果は厳密かつ決定的で、サンプリングは一切行いません。

## 補足

- 事実の背景にある実務。発注明細ごとの全数量割引、フルリールやトレイ単位で決まる最小発注数量、営業日単位のリードタイム、品不足市場での供給割当は、標準的な購買実務です。2021–2023年の部品不足の際、仕入先は部品を割当制にし、注文の一部しか出荷せず、リードタイムを延ばしました（Ultra Librarian, "Electronic Component Allocation & Lead Times", 2022年と2023年の更新版；EMSNow, "Eight commonly used terms when buying electronic components"）。日付または使い切り（use-up）で有効になる設計変更と、それが生む過剰在庫・陳腐化在庫は、Oracle の MRP ドキュメント（"Engineering change planning"、use-up date）や、設計変更管理に関する APICS/CPIM の資料に説明されています。確率的な仕入先リードタイムと、安全リードタイムと安全在庫のトレードオフは、たとえば Humair、Ruark、Tomlin、Willems, "Incorporating Stochastic Lead Times Into the Guaranteed Service Model of Safety Stock Optimization", Interfaces 43(5), 2013 や、確率的リードタイム下の多期間供給計画に関する Ben-Ammar、Dolgui らの研究（離散的で上限のあるリードタイム分布を使う期待コストモデル）に従っています。
- 合成または未検証の部分。価格、最小発注数量、リードタイム、遅延率、供給割当、予算、4つの計画レートはすべて合成値です。コストの重み（週あたり保管0.5%、年に約26%で、在庫保管コストの通常の範囲20–30%に入る；欠品待ちは基板1枚・1週あたり10,000 KRW で部品ごとに数え、基板の材料費のおよそ4分の1から半分で、1週間分の納期遅延の違約金と残業に相当；不足は1.5倍；廃棄は標準原価）は設計上の選択で、測定値ではありません。欠品待ちを部品ごとに数えると、複数の部品が同時に足りない週を多めに数えます（ラインが止まるのは1回です）。それでも各部品のコストを分離したままにできるので、hard の期待値は厳密なままです。短い2つの週は、グレゴリオ暦を使う多くの国と同じく、クリスマスと元日が非稼働日であると仮定しています。他の工場では異なる場合があります。
- 遅延は仕入先だけの性質で（部品や季節には依存しない）、最大2週で、納入ごとに独立です。実際の仕入先の遅延は相関しています（共通の出荷、工場の操業停止）。実績には仕入先ごとに10–28件の納入しかないため、推定値が真の値から大きく外れるものもあります。S05（納入10件）は32%遅れているように見えますが、真の値は15%です。このシードでの真の遅延率は、2%（S09、緊急調達のブローカー）から37%（S04、海外）、35%（S03、割当中の半導体メーカー）までです。
- `validate-case` はすべての公開設定を検査します。5つのロケールでの決定的なデータ、9設定すべてで同じエージェントの見え方、品質1.0の模範解答、模範解答より少なくとも5%悪いが有効な従来のやり方（このワールドとワールドシード 1–3 で）、その設定のルールごとにそのルールだけを破る成果物1つ、すべてのパラメータが効くこと、そしてこのケースは `audited: true` なので、新たに行う正解の監査の結果がすべて合格することです。

## 元の課題との関係

これは Apex Manufacturing の持ち帰り課題（take-home）を合成データで翻案したもので、そのデータの再現でも、その課題への提出物でもありません。どちらも生産スケジュール、BOM、共通部品、在庫、既存の購買発注、仕入先の適格性、リードタイム、調達ルールを使います。ここでの出力はベンチマークの8週間分の `orders.csv` のままで、元の課題は、購買発注とアラートをシナリオのデータベースに書き込む汎用プログラムを求めています。Nara Display とのメールのやり取りは新しく作った架空の商取引イベントで、課題にあった文書ではありません。

元の課題には、日付入りの経営メモ、認証、仕入先の集中度の履歴、承認、危険物の取り扱い、緊急輸送も含まれています。この拡張ではそれらをモデル化していません。既存の品質保留と2社購買のルールは、簡略化した類似物にすぎません。シミュレーションの顧客は、実行中に後からメールを受け取ったり、購買発注を出したり、承認を求めたりしません。この課題が試すのは、自律的なイベント処理ではなく、日付の決まった承認済みの価格改定を（承認待ちのものは無視して）静的な計画と予算に織り込むことです。
