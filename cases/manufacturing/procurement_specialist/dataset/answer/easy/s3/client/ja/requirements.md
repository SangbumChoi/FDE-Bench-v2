# 今後8週間の購買発注計画

## 背景

弊社は2機種の制御基板を組み立てており、20数点の部品をいくつかの仕入先から購入しています。今後2か月、生産を止めず、かつ使いすぎにならないように、どの部品をどの仕入先にどれだけ発注すればよいか計画を立てていただけますか。生産計画、部品表（BOM）、現在庫、未入荷の発注、仕入先の見積、承認仕入先リスト、予算を添付いたします。
最近は供給が不安定なため、仕入先の直近6か月の納入実績と、弊社が受け取った供給割当の通知も添付しました。部品表には、設計部門が予定している両機種のフラッシュメモリの設計変更もすでに入っています。
Nara Display とのディスプレイ価格改定に関するメールのやり取りも転送しますので、発注価格に反映してください。

## 成果物

CSVファイル1つ、`orders.csv` で、ヘッダーは `order_week,component_id,supplier_id,quantity` です。発注明細1件につき1行です。`order_week` は発注を出す週で、1〜8の数字です（1 = W1、2026年11月23日（月）から始まる週、8 = W8、2027年1月11日の週）。`component_id` と `supplier_id` はデータのコードのとおりに記入してください。`quantity` は個数（ピース）単位で、抵抗も同じです。週・部品・仕入先が同じ行は合算して1つの発注明細として扱います。

## データについて

- `生産計画.csv` には W1〜W10 の機種別（`製品コード` B100、B200）の週ごとの生産枚数（`生産枚数`）があります。発注を出すのは W1〜W8 のみです。W9・W10 は、最後の発注が何をカバーするかを評価するために入れています。W10 終了後に残った在庫は、この計画では価値がありません。
- `部品表.csv` は BOM で、その機種の基板1枚に各部品が `基板当たり員数` 個使われます。ある週の部品所要量は、その週に作る機種ごとの基板枚数に `基板当たり員数` を掛け、2機種分を合計したものです。B100 にはディスプレイとアンテナがありません。部品はそれより前ではなく、基板を作る週に必要です。ある週に入荷した品物は、その週の生産全体に使えます（組立のリードタイムによる前倒しはありません）。
- `部品表.csv` に入っているフラッシュの変更（C04 は W5 まで、新しい C25 は W6 から）は、今回はまだ正式に出ていません（設計部門がまだ C25 を認定中です）。両機種とも10週間ずっと C04 を使い続ける前提で計画し、C25 の行と `適用開始週`・`適用終了週` の列は無視してください。C25 は不要です。
- `現在庫.csv` の `在庫数` は W1 開始時点の在庫です。チップ抵抗（C07、C08、C09）以外はすべて個数です。チップ抵抗は倉庫で5,000個巻きのリール単位で数えているため、抵抗の `在庫数 = 12` は60,000個を意味します。
- `未入荷発注.csv`：すでに発注済み・支払済みの注文です。記載の `入荷週` に入荷し、今回の計画の支出には含めません。
- `仕入先見積.xlsx` の `見積` シート：部品・仕入先ごとに1行で、`単価` は `通貨` 建ての1個あたりの価格です。Pacific Parts（S04）だけが米ドル建てで、他の仕入先はすべてウォン建てです。予算はウォン建てで、市場レートではなく固定の計画レート **1ドル = 1,450ウォン** で換算します。
- Nara Display の価格改定（`mail/` のメールのやり取り）：ディスプレイモジュール C06 について、2026年12月9日（水）以降に同社が受領する発注から12%値上げすることに合意しました。同社の C06 の単価すべて、つまり定価と2つの数量割引単価に適用されます。弊社はすべての発注を発注週の月曜日に出すので、W3 の発注（12月7日月曜日）は旧価格のままで、値上げは W4 以降の C06 の発注に適用されます。同社が提案した1月からの8%の追加値上げは受け入れていないので、含めずに計画してください。未入荷の発注には影響しません。
- 今回は定価で計画します（数量割引には未締結の基本契約が必要です）。明細の大きさにかかわらず1個あたり `単価`（上記の Nara Display と合意した値上げを反映）で計算し、数量割引の列は無視してください。
- リードタイムも今回は週単位で扱います。`リードタイム_日` は暦日ではなく営業日で、5で割って切り上げた値を L 週とし、祝日は考えません（クリスマスの週と元日の週も含め、どの週も営業日5日として扱います）。発注はその週の月曜日に出し、第 w 週にリードタイム L 週で出した発注は第 w+L 週から使えます（W1 に12日 = 3週で発注 → W4 から使用可）。入荷分は入荷週の所要量すべてに使えます。
- `最小発注数量` は発注明細1件、つまり仕入先・部品・発注週ごとの最小数量です。これを下回ると仕入先は出荷しません。別の週に出した数量を合算して最小発注数量に届かせることはできません。
- `承認仕入先リスト.csv`：部品は、その部品について `承認状況` が `承認済` の仕入先からのみ購入できます。`審査中`（品質認定中）や `取引停止` は、見積が届いていても使えません。
- Hanbit Electronics（S01） は品質保留中です。W1〜W4 に入荷予定の同社のロットは受入検査で全数返品になり、ラインには届きません。同社の品物は W4 より後に入荷させてください。
- `購買予算.csv` は親会社が定めた月ごとの上限で、目標値ではありません。どの月もこれを超えてはいけません。発注は発注週の月曜日が属する月の予算から差し引かれます。W1〜W2 は2026年11月（W2 は11月30日の月曜日に始まるので、大半の日が12月でも11月に数えます）、W3〜W6 は2026年12月、W7〜W8 は2027年1月です。ドル建ての発注は1ドル = 1,450ウォンで計算します。
- 重要部品は `部品マスタ.csv` で `重要部品 = はい` の部品です。これらは**週平均所要量の 1.5 倍**を安全在庫として持ちたいと考えています。その部品を使う週の所要量の合計をその週数で割り、1.5 を掛けて切り上げた数量です。部品を使う週は、毎週末にこの数量が残っている必要があります。
- 弊社の方針：使用中の重要部品は8週間のうちに異なる2社以上の仕入先に発注し、1社がその部品の総発注数量の **80%** を超えてはいけません（今回の計画の発注のみ、個数で数えます）。2社目の供給元としての認定を維持するためです。
- 今回は `納入実績.csv` と `供給割当.csv` は使いません（経営陣はまず仕入先の確定日程による計画を求めています）。すべての仕入先が約束の週に納入し、発注した数量をすべて確定してくれる前提で計画してください。

## 評価方法

**必須条件**（1つでも破ると計画は無効です）：

- 部品ごとに承認済の仕入先のみを使います。
- すべての発注明細が仕入先の最小発注数量以上です。
- 月ごとの購買額が `購買予算.csv` の予算を超えません。
- Hanbit Electronics（S01） の品物が W1〜W4 に入荷予定になっていません。
- 使用中の重要部品はすべて2社以上の仕入先に発注し、どの仕入先も数量の 80% を超えません（弊社の慣行なので、実際にコストが下がるなら例外も検討します）。

**品質**（低いほど良い）：W1 から W10 まで部品ごとに週単位でシミュレーションします。週初の在庫にその週の入荷分（未入荷発注と今回の計画）を加えてその週の所要量を賄います。部品がなくて作れなかった基板は、部品を待って入荷しだい生産します。合計は次のとおりです。
- すべての発注明細の購買金額（ウォン、ドルは1ドル = 1,450ウォン）
- 在庫保管コスト：毎週末の在庫1個あたり `標準原価_ウォン` の0.5%
- 欠品待ちコスト：部品が足りずに基板1枚が1週待つごとに10,000ウォンかかります（納期遅延の違約金と挽回のための残業）。部品ごとに数え、毎週末にまだ賄えずに待っている所要量1個は、10,000ウォンをその部品の基板当たり個数（所要量を、その部品を使う機種の生産枚数で割った値）で割った額です（2週間足りなければ2回数えます）
- 重要部品の安全在庫不足：部品を使う週の毎週末に安全在庫を下回る1個あたり `標準原価_ウォン` の1.5倍
