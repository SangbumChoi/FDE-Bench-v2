# コールセンター要員計画担当 — `customer_service/callcenter_workforce_planner`

多言語カスタマーサポートセンターが、サポートチームの来週（2026年11月9日月曜日〜15日日曜日）のシフト表をエージェントに
依頼します。依頼の趣旨は「対応しているどの言語でもお客様をお待たせしないよう、電話に出られる人数を十分に確保したい」と
いうものです。センターは毎日08:00–22:00に韓国語、日本語、英語、中国語、スペイン語の電話を受け付けます。成果物は
`roster.json`（`{"assignments": [{"agent", "day", "shift", "language"}, ...]}`）で、担当者が勤務するシフト1回につき
1件です。舞台は特定の国に依存しません。顧客が示すルール以外にどの国の労働法も適用されず、時給には通貨単位がありません。

このケースには**設定がありません**。どの難易度でも問題、ルール、正解は同じです。進め方の調整項目（仕様をすべて渡すか
先に質問させるか、顧客のペルソナ、データのノイズ、イベント）は、ほかのすべてのケースと同様にその上に適用されます
（[cases/README.md](../../README.md) を参照）。

## データ

| ファイル (en) | 内容 |
|---|---|
| `agents.xlsx` | `staff` シート：担当者30名と `contract`（正社員20名、パート10名）、`new_hire`（4名、全員正社員）。`skills` シート：担当者・言語ごとに1行（最初の行がその担当者の主言語） |
| `call_forecast.csv` | 日・30分枠（08:00–21:30）・言語ごとの `agents_needed`: 980行、各1–5名で、入電件数からすでに人数に換算済み |
| `leave.csv` | 休暇申請5件、`from` / `to` は日/月/年の順、`status` は approved または rejected |
| `shifts.csv` | 8時間の正社員シフト4種（S0800、S1000、S1200、S1400）と4時間のパートシフト4種（P0800、P1200、P1600、P1800） |
| `labor_cost.csv` | 雇用形態別の時給：正社員22.0、パート18.0 |

ファイル名、シート名、列名とカテゴリのラベルはローカライズされています（韓国の顧客は `고용형태 = 풀타임` を含む
`고객센터_상담원명단.xlsx` を送ります）。ID、コード、数値はローカライズしません。

## ルール

| ルール | 区分 | 内容 |
|---|---|---|
| `skill_valid` | 物理的 | 担当者は自分の対応言語でのみ電話対応する（シフト全体を通じて1言語） |
| `min_rest` | 物理的 | 同じ担当者の2つのシフトの間に11時間以上（そのため1日1回まで） |
| `shift_type` | 契約上 | 正社員は8時間シフトのみ、パートは4時間シフトのみ |
| `max_shifts` | 契約上 | 週に正社員は5回まで、パートは3回まで |
| `leave_respected` | 契約上 | 承認済みの休暇日には誰も配置しない |
| `buddy_rule` | 業務慣行（緩和可能） | 新人が電話に出ている間は、すべての枠で同じ言語に新人ではない担当者が少なくとも1名いる |

**目的値（最小化）：** 30分枠・言語ごとに不足する担当者1名につき40（不足人数は予測値から配置人数を引いたもので、水曜日は
予測値の60%を切り上げて使う）に、全シフトの人件費（時間 × 時給、正社員の週5回目のシフトは1.5×）を加えた値です。
顧客は40を、担当者が1名30分不足したときに放棄呼、折り返し対応、サービスレベル未達で生じるコストを、時給と同じ単位で
見積もった値だと説明します。

## 隠れた事実（確認すべき事項 9件）

`one_language`（バイリンガルの担当者も1言語分としてのみ数える）、`slot_coverage`（予測はすでに人数単位で、30分枠ごとに
確認する）、`holiday_wednesday`（11月11日は顧客の主要市場がある地域の祝日：予測値の60%を切り上げ、ファイルは更新
されていない）、`contract_limits`、`min_rest`、`leave_dates`（日/月/年、両端を含む、却下された申請は休暇ではない）、
`overtime`（通常は4回、5回目は1.5×）、`buddy_rule`、`understaffing_penalty`（40とコストモデル）。

## 含まれる状況

- **有効性を左右する隠れた事実：** 休息ルール（これを知らない最適化器は、このシードで `min_rest` 違反を13件生じさせます）、
  雇用形態ごとのシフトの種類と回数上限、シフトごとに1言語、そして休暇ファイル（月/日と読むと、A20の11月9日月曜日の休みが
  9月11日になり、ほかの期間は数か月にわたって伸びます）。
- **品質だけを動かす隠れた事実：** 祝日（水曜日の需要 265 → 229 担当者・枠）、時間外割増、人員不足の重み。
- **データの罠：** 日/月/年の日付（このシードでは日が12を超える日付はない）、却下された休暇申請（A03）、祝日が
  反映されていない予測。
- **緩和可能なルール：** `buddy_rule`。最適解でこのルールを緩和すると、目的値が0.58%改善します。
- ケース自体には**圧力をかけるメモも日付の決まったイベントもありません**。汎用の `messy` の進め方のイベントだけです。

## 参照解、ベースライン、最適解（シード 20261109）

**参照解**は貪欲法です。利得が最大の（担当者、日、シフト、言語）を繰り返し追加します。利得は、まだ埋まっていない枠
1つにつき40から、そのシフトの給与（時間外割増を含む）を引いた値です。すべてのルールを守り、後で新人が組む相手を
見つけられるよう、新人ではない担当者を優先します。**ベースライン**は、スーパーバイザーが予測を見ずに作った固定の
ローテーションです。新人ではない担当者は全員、主言語で1週間ずっと同じシフトに入ります。正社員は通常の4日、パートは
3日を連続して勤務し、開始日は同じ言語・雇用形態の中でずらします。休暇日は空けておき、新人はそれぞれ同じ言語の
新人ではない正社員1名にそのまま付いて勤務します（同じ日、同じシフト）。品質は正規化されます：ベースライン0、参照解1。

| ベースライン（固定ローテーション） | 37,376 | 554 | 15,216 | 103 | 0.685 | 0 |
| 参照解（貪欲法） | 25,584 | 183 | 18,264 | 116 | 1 | 1 |

最適解は既知の上限です。同じモデルの厳密なMILP（バイナリ変数約2,000個）をscipyのHiGHSで約8秒で最適性を証明して解き、
`case.py` 自身の評価器で確認しました。これは分析用のスクリプトで、ケースの一部ではありません（scipyは依存関係では
ありません）。方針の既定の品質上限1.5のもとでは、参照解は品質項目の0.67、最適解は0.79を得ます。`case.yaml` は
`quality_cap` を設定していません（REVIEW.md の F1 を参照）。

## 補足

- 合成データです。氏名、対応言語、予測、休暇、時給はシードから生成されます。シフトのパターンとルールは設計上の選択で、
  特定のセンターの慣行ではありません。
- 単純化：予測はすでに担当者数になっており（入電件数、処理時間、Erlang C の段階はない）、シフトは休憩なしですべての枠に
  数えられ、正社員の通常の週は4回（32時間）で、11時間の休息はEUの最低基準ですがスペインの12時間には届きません。
  氏名はどのロケールでもラテン文字で、担当者の言語とは結び付いていません。
- 休暇の日付はどのロケールでも日/月/年です。このシードでは日が12を超える日付はありませんが、ほかのワールドシードでは
  金曜日〜日曜日の承認済み休暇が13–15と表示されます（シード1と3）。
- `validate-case` は、ケース自身のシードとワールドシード1–3でケースを確認します。5つのロケールのデータが決定的であること、
  参照解が品質1で有効であること、ベースラインが有効でより悪いこと、そしてルールごとにそのルールだけを破るシフト表が
  1つずつあることです。
