# 呼叫中心人力排班规划师 — `customer_service/callcenter_workforce_planner`

一家多语种客服中心请智能体为其客服团队排出下周（2026年11月9日周一至15日周日）的班表，要求是“我们支持的每个语种都要有
足够的人接电话，别让客户等太久”。该中心每天 08:00–22:00 接听韩语、日语、英语、中文和西班牙语来电。交付物是
`roster.json`（`{"assignments": [{"agent", "day", "shift", "language"}, ...]}`），每位坐席每上一个班记一条。场景不针对
任何特定国家：除客户说明的规则外，不适用任何国家的劳动法，时薪也不带货币单位。

此案例**没有设置**：每个难度下的问题、规则和标准答案都相同。与所有案例一样，交接方式的各项调节（给出完整需求还是先澄清、客户人设、数据噪声、事件）叠加在其上（见 [cases/README.md](../../README.md)）。

## 数据

| 文件 (en) | 内容 |
|---|---|
| `agents.xlsx` | `staff` 工作表：30 名坐席，含 `contract`（20 名全职、10 名兼职）和 `new_hire`（4 名，均为全职）。`skills` 工作表：每位坐席每个语种一行（第一行是该坐席的主语种） |
| `call_forecast.csv` | 按日期、半小时时段（08:00–21:30）和语种给出的 `agents_needed`：980 行，每行 1–5 人，已由来电量换算为人数 |
| `leave.csv` | 5 条请假申请，`from` / `to` 按“日/月/年”书写，`status` 为 approved 或 rejected |
| `shifts.csv` | 4 个 8 小时全职班次（S0800、S1000、S1200、S1400）和 4 个 4 小时兼职班次（P0800、P1200、P1600、P1800） |
| `labor_cost.csv` | 各用工类型的时薪：全职 22.0，兼职 18.0 |

文件名、工作表名、列名和分类标签都做了本地化（韩国客户发来的是 `고객센터_상담원명단.xlsx`，其中为 `고용형태 = 풀타임`）；
编号、代码和数字不做本地化。

## 规则

| 规则 | 类别 | 内容 |
|---|---|---|
| `skill_valid` | 物理约束 | 坐席只接听其语言技能中的语种（整个班次只用一个语种） |
| `min_rest` | 物理约束 | 同一坐席两个班之间至少间隔 11 小时（因此每天最多一个班） |
| `shift_type` | 合同约束 | 全职只上 8 小时班，兼职只上 4 小时班 |
| `max_shifts` | 合同约束 | 每周全职最多 5 个班，兼职最多 3 个班 |
| `leave_respected` | 合同约束 | 已批准的请假日不给任何人排班 |
| `buddy_rule` | 业务惯例（可放宽） | 新员工在岗接听时，每个时段同一语种上至少有一位非新员工坐席 |

**目标（最小化）：** 每个半小时时段、每个语种每缺一名坐席记 40（缺口为预测值减去已排坐席数，周三按预测值的 60% 向上
取整），再加上所有班次的人工成本（时长 × 时薪，全职每周第 5 个班按 1.5×）。客户的解释是：40 与时薪同一单位，是其估算的
每缺一名坐席半小时在客户放弃来电、回拨处理和服务水平不达标上造成的损失。

## 隐藏事实（9 个应问事项）

`one_language`（会两种语言的坐席也只计入一个语种）、`slot_coverage`（预测已经是人数，按半小时时段检查）、
`holiday_wednesday`（11月11日是客户主要市场所在地区的公共假日：按预测值的 60% 向上取整，文件未更新）、`contract_limits`、
`min_rest`、`leave_dates`（“日/月/年”，首尾两天都包含，被驳回的申请不算请假）、`overtime`（正常 4 个班，第 5 个班按
1.5×）、`buddy_rule`、`understaffing_penalty`（40 与成本模型）。

## 包含的情境

- **决定是否有效的隐藏事实：** 休息规则（不知道这条规则的优化器在此种子下会产生 13 处 `min_rest` 违规）、按用工类型
  规定的班次类型和次数上限、每个班次只用一个语种，以及请假文件（若按“月/日”读，A20 在11月9日周一的休假会变成9月11日，
  其他时间段会横跨数月）。
- **只影响质量的隐藏事实：** 公共假日（周三需求从 265 降到 229 个坐席时段）、加班溢价、缺员权重。
- **数据陷阱：** “日/月/年”格式的日期（此种子下没有日大于 12 的日期）、一条被驳回的请假申请（A03）、未按假日更新的预测。
- **可放宽的规则：** `buddy_rule`。在最优解处放宽这条规则，目标值改善 0.58%。
- 案例本身**没有施压留言，也没有带日期的事件**；只有通用的 `messy` 交接方式事件。

## 参考解、基线与最优解（种子 20261109）

**参考解**是贪心算法：反复加入收益最大的（坐席、日期、班次、语种），收益为每个尚未覆盖的时段 40 减去该班次的薪酬（含
加班溢价）；它遵守所有规则，并优先安排非新员工，以便之后新员工能找到搭档。**基线**是主管不看预测排出的固定轮班表：每位
非新员工整周都在主语种上上同一个班次，全职上正常的 4 天，兼职上 3 天，连续排班，起始日在同一语种和用工类型内错开；请假日
留空，每位新员工跟随一位同语种的非新员工全职坐席上班（同样的日期、同样的班次）。质量经过归一化：基线为 0，参考解为 1。

| 班表 | 目标值 | 缺员坐席时段 | 人工成本 | 班次数 | 与参考解之比 | 归一化质量 |
|---|---|---|---|---|---|---|
| 基线（固定轮班表） | 37,376 | 554 | 15,216 | 103 | 0.685 | 0 |
| 参考解（贪心） | 25,584 | 183 | 18,264 | 116 | 1 | 1 |
| 最优解（MILP） | 23,464 | 75 | 20,464 | 126 | 1.090 | 1.180 |
| 忽略公共假日的最优解 | 23,872 | | | | 1.072 | 1.145 |
| 忽略加班、或不知道权重的最优解 | 23,560 | | | | 1.086 | 1.172 |
| 没有搭档规则的最优解（仅在放宽时有效） | 23,328 | | | | 1.097 | 1.191 |
| 只排一个班（A01、周一、S0800、en） | 67,656 | | | 1 | 0.378 | 0（按下限截断） |

最优解是已知的上限：对同一模型建立精确的 MILP（约 2,000 个二元变量），用 scipy 的 HiGHS 约 8 秒求解并证明最优，再用
`case.py` 自带的评估器核对。这是一个分析脚本，不属于案例本身（scipy 不是依赖项）。在默认的政策质量上限 1.5 下，参考解获得
质量分项的 0.67，最优解获得 0.79；`case.yaml` 没有设置 `quality_cap`（见 REVIEW.md 的 F1）。

## 备注

- 合成数据：姓名、语言技能、预测、请假和时薪都由种子生成；班次安排和规则是设计选择，并非某个中心的实际做法。
- 简化之处：预测已经是坐席人数（没有来电量、处理时长和 Erlang C 这一步），班次在每个时段都计入且不含休息时间，全职正常
  一周为 4 个班（32 小时），11 小时休息是欧盟的最低标准，但低于西班牙的 12 小时。各语言版本中的姓名都是拉丁字母，与坐席
  的语种无关。
- 各语言版本中的请假日期都是“日/月/年”。此种子下没有日大于 12 的日期，但在其他世界种子中，周五至周日的已批准请假会出现
  13–15（种子 1 和 3）。
- `validate-case` 在案例自身的种子和世界种子 1–3 上检查案例：五种语言版本的数据是确定性的，参考解有效且质量为 1，基线
  有效且更差，并且每条规则各有一份只违反该规则的班表。
