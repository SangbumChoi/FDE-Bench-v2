FDE-Bench v2

Built cases

13 cases. Each link opens the case page: what the AI has to do, what it is given, how it is scored, and all the details.

What is different

  • One dataset, several right answers. The client's hidden rules change from version to version while the AI gets exactly the same files, so the score depends on finding out this client's facts.
  • Five languages written natively, for the client and, separately, for the AI's instructions.
  • Every client fact is checked to matter. Misreading it costs score, shortcuts are closed, and doing the request word for word scores at most 0.2.
  • Each fact is followed from what the client said, to what the AI found out, to what the deliverable does.
  • Like real work: company policies with an exception process, dated events and pressure during the job, and programs that run day by day on days the AI never saw.

The full comparison with other benchmarks

How it is scored

  1. Valid or not. Breaking any rule above makes the deliverable invalid and the run scores 0. A rule the company policy lets bend counts only if the AI asked the client for an exception.
  2. Quality. The result is placed on a scale where the client's own way without an engineer is 0 and the reference solution is 1. Better than the reference goes above 1; full credit at the policy's cap (1.5).
  3. Final score. Quality, plus how well the AI asked (did its questions uncover the facts above?), how it communicated (the client's language, a NOTES.md) and how efficient it was, weighted by the company policy.
  4. Several versions. The data stays the same; only the client's exact values (a threshold, a unit, a date) change from one version of the case to another. A difficulty's score is the average over several versions, so memorising one answer does not help.
