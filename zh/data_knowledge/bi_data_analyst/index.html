案例说明（README）

BI 数据分析师 — data_knowledge/bi_data_analyst

一家向韩国、日本和美国客户销售订阅盒和单次购买商品的咖啡、茶订阅商店（总部在首尔，所有报表都以韩元计）给智能体发来订单数据库的 CSV 导出、一份简短的数据字典和管理层的十二个问题：“能麻烦您根据数据库导出的数据帮忙回答一下吗？……每个问题给一个数字就行。”交付物是包含所有问题编号的 answers.json（{"Q01": ..., ..., "Q12": ...}），每个值是一个数字或 null。null 表示“不知道”：CEO 的董事会材料中该数字显示为“暂无数据”。需求里没有提到任何决定这些数字的口径，也没有说错误的数字会带来什么代价。两者都在隐藏需求中，模拟客户只有在被问到时才会说明。

一个设置由一个层级和一个规则种子组成。层级决定本轮董事会材料需要哪些问题。规则种子从各自的三个候选值中、彼此独立地为客户的四条规则各抽取一个值：财年的第一个月、活跃客户的时间窗口、金额取整的单位，以及“不知道”相对于正确答案和错误答案值多少。因此每个层级有 81 种组合。公开规则种子为 4、12 和 23（九种设置，保存在 dataset/gt/ 中，并由验证器检查）；其他任何种子都是非公开抽取，其答案不在任何地方公布。智能体在每种设置下看到的需求和数据都相同（验证器会检查它的提示词和工作区逐字节一致）。模拟客户依据该设置的隐藏需求作答，评估器也按该设置评分。因此这个案例衡量两件事：智能体能否找到口径并答对，以及在应当说“不知道”时是否会这样说（校准弃答，calibrated abstention）。与所有案例一样，交接方式的各项调节（给出完整需求还是先澄清、客户人设、数据噪声、事件）叠加在其上（见 cases/README.md）。

答案与得分

Q01..Q12 每个键都必须存在，值为有限数字或 null。缺少某个键，或者值两者都不是，就违反 answer_format（物理约束）。层级计分的每道题得到一份奖励：答对得 2，答错得 0，填 null 得 dont_know_reward，后者由规则种子抽取：

dont_know_reward错误不知道（null）正确全部 null 的答卷得分仅当 P(答对) 高于此值时作答

10120.5050%
1.501.520.7575%

目标值（最大化）是奖励总和除以 2 × 计分题数，取值在 [0, 1] 之间。全部答对的答卷得 1。对层级不计分的题目作答或填 null 都没有影响。指标为 scored、answered、right、wrong、dont_know、accuracy_on_answered（right / answered）、coverage（answered / scored）、奖励总和 reward，以及答错的题目和答“不知道”的题目列表。

弃答阈值。 了解计分规则的答卷，只应在答对概率 p 胜过“不知道”时才作答：p × 2 > dont_know_reward。客户把这套规则作为业务事实说出来，它也是一个应问事项（answer_rewards，类型 missing）：“错误的数字一旦报到董事会，就得在下次会议上更正，也有损信誉；‘暂无数据’只是留下一个空白”，随后给出三个数值。当 null 值 0.5 时，客户还会补充“这次董事会更希望看到数字，而不是空白”；当它值 1.5 时，则补充前两次材料都出现过更正，“这次董事会宁可看到空白，也不愿看到错误的数字”。

除金额容差外，正误判定不取决于抽到的值。Q03、Q04、Q05 和 Q10 必须完全一致。金额须在 0.5% 与取整单位一半（50、500 或 5,000 韩元）两者中较宽的范围内，因此按抽到的单位取整后的精确值一定算对。Q11 须在 0.05 个百分点以内，Q08 和 Q12 须在 0.5% 以内。以小数而非百分数给出的比例也接受。violating_examples 断言：把精确答案按设置的单位取整后，在每个设置下、在验证器构建的每个世界上，都能无违规地得到 1.0。

智能体必须问什么

hard 中要问全部十一个应问事项（easy 中九个，medium 中十个），但其中四个承载着规则种子抽到的值，既不能从另一次运行中沿用，也无法从数据中猜出：财年的第一个月（fiscal_year）、活跃窗口（active_customer）、取整单位（report_rounding），以及“暂无数据”值多少（answer_rewards）。其余七个无论抽到什么值都相同。不知道 answer_rewards，智能体就无法判断一个有 60% 把握的答案该不该给出（在 0.5 和 1 下该给，在 1.5 下不该给）；不知道 report_rounding，就无法判断哪些金额数字有效。

参考解与基线数字（公开世界种子 20261026）

参考解是一位细心的分析师：使用该设置的口径，除了品类更名之外每个口径都处理正确——它只用 pantry 标签回答“食品储藏”那道题。层级不计分的题目它填 null。它的弃答策略有章可循且是确定性的：它的食品储藏数字只覆盖 2025-10 以后上架的商品，所以它认为这个答案对错各半，只有当 ½ × right_reward > dont_know_reward 时才保留。当 null 值 0.5 时这一条件成立（1 > 0.5），所以它作答并答错。在 1（1 = 1，打平则弃答）和 1.5（1 < 1.5）下它回答“不知道”。在 easy 和 medium 中 Q06 不计分，所以参考解在那里答对每一道计分题。

基线是没有分析师时财务部报出的结果：每道题都是“暂无数据”（null）。它在每道计分题上拿到抽到的“不知道”奖励（最高分的 0.25 / 0.50 / 0.75），因此全部回答“不知道”在归一化尺度上得 0。表面值答卷是不采用客户任何口径、直接对导出数据求和的结果：按存储的 UTC 日期划分自然年期间、不论状态计入所有订单、收入 = 订单 total 减去日期落在该期间的退款、所有币种按 2026-09-30 的汇率换算、活跃 = 最近 30 天内下过单、“食品储藏” = pantry 标签。它回答每一道题，并遵守客户无论如何都会执行的两条财务规定（排除测试账号、金额按设置单位取整）。在公开世界、公开规则种子下，它在每个设置下都低于基线：它的错误数字一分不得。
