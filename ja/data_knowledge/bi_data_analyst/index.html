ケースの解説（README）

BI データアナリスト — data_knowledge/bi_data_analyst

韓国・日本・米国のお客様に定期便ボックスと単品商品を販売するコーヒーとお茶の定期便ショップ（本社はソウル、レポートはすべてウォン建て）が、注文データベースの CSV エクスポート、簡単なデータ辞書、経営陣からの12の質問をエージェントに送ります。「データベースのエクスポートから回答していただけますでしょうか。…質問ごとに数値をひとつずつお返しください。」成果物はすべての質問番号を含む answers.json（{"Q01": ..., ..., "Q12": ...}）で、それぞれの値は数値または null です。null は「わからない」を意味し、CEO の取締役会資料ではその数値が「集計中」と表示されます。依頼には数値を決める定義がひとつも書かれておらず、誤った数値がどれほどの損失になるかも書かれていません。どちらも隠れた要件に含まれており、シミュレーションの顧客は質問されたときにだけ答えます。

設定は、ティアとルールシードの組み合わせです。ティアは、今回の取締役会資料にどの質問が必要かを決めます。ルールシードは、顧客のルールを四つ、それぞれ独立に三つの候補値から抽選します。会計年度の最初の月、アクティブ顧客の期間、金額を丸める単位、そして「わからない」が正しい回答と誤った回答に比べてどれだけの価値を持つかです。そのため組み合わせはティアごとに81通りになります。公開ルールシードは 4、12、23 です（9つの設定。dataset/gt/ に保存され、検証器が確認します）。それ以外のシードはすべて非公開の抽選で、その正解はどこにも公開されません。エージェントはどの設定でも同じ依頼と同じデータを見ます（検証器は、プロンプトと作業領域がバイト単位で同一であることを確認します）。シミュレーションの顧客はその設定の隠れた要件に基づいて答え、評価器はその設定で採点します。したがって、このケースは二つのことを測ります。エージェントが定義を見つけて正しく答えられるか、そして「わからない」と言うべきときにそう言えるか（較正された回答保留、calibrated abstention）です。進め方の調整項目（仕様をすべて渡すか先に質問させるか、顧客のペルソナ、データのノイズ、イベント）は、ほかのすべてのケースと同様にその上に適用されます（cases/README.md を参照）。

回答と得点

Q01..Q12 のすべてのキーが必要で、値は有限の数値または null です。キーが欠けていたり、値がそのどちらでもなかったりすると、answer_format（物理的）に違反します。ティアが採点する質問ごとに報酬が得られます。正しければ 2、誤りなら 0、null なら dont_know_reward で、この値はルールシードが抽選します：

dont_know_reward誤りわからない（null）正しいすべて null の回答シートの得点P(正解) がこれを上回るときだけ答える
0.500.520.2525%
10120.5050%
1.501.520.7575%

目的値（最大化）は報酬の合計を 2 × 採点対象の質問数で割った値で、[0, 1] の範囲の数です。すべて正しい回答シートは 1 になります。ティアが採点しない質問への回答や null は何の影響もありません。指標は scored、answered、right、wrong、dont_know、accuracy_on_answered（right / answered）、coverage（answered / scored）、報酬の合計 reward、そして誤った質問と「わからない」とした質問の一覧です。

回答保留のしきい値。 報酬の仕組みを知っている回答シートなら、正解の確率 p が「わからない」を上回るときだけ質問に答えるべきです：p × 2 > dont_know_reward。顧客はこの仕組みを業務上の事実として述べ、これは確認すべき事項です（answer_rewards、種類 missing）。「誤った数値が取締役会に出ると次の会議で訂正が必要になり、信用も損ないますが、『集計中』は空欄がひとつ残るだけです」と述べたあと、三つの値が続きます。null の価値が 0.5 のとき、顧客は「今回、取締役会は空欄よりも数値を見たいと考えています」と付け加え、1.5 のときは、前回までの2回の資料で訂正が続いたため「今回、取締役会は誤った数値よりも空欄のほうがずっと良いと考えています」と付け加えます。

正誤の判定は、金額の許容誤差を除けば抽選された値に左右されません。Q03、Q04、Q05、Q10 は完全に一致しなければなりません。金額は 0.5% と端数処理単位の半分（50、500 または 5,000 ウォン）のうち広いほうの範囲内でなければならないため、正確な値を抽選された単位のとおりに丸めた回答は必ず正解になります。Q11 は 0.05 ポイント以内、Q08 と Q12 は 0.5% 以内でなければなりません。割合をパーセントではなく小数で答えたものも受け付けます。violating_examples は、正確な回答を設定の単位に丸めると、すべての設定、そして検証器が作るすべてのワールドで、違反なしに 1.0 になることを確かめています。

参照解とベースラインの数値（公開ワールドシード 20261026）

参照解は、設定の慣行に従い、カテゴリ名の変更を除くすべての定義を正しく扱う、注意深いアナリストです。「パントリー」の質問には pantry ラベルだけで答えます。ティアが採点しない質問は null のままにします。回答保留の方針は筋が通っていて決定的です。パントリーの数値は 2025-10 以降に発売された商品しか含まないため、その回答が正しい確率を五分五分とみなし、½ × right_reward > dont_know_reward のときだけ回答を残します。null の価値が 0.5 のときはこれが成り立つので（1 > 0.5）答えて誤ります。1（1 = 1、同点なら保留）と 1.5（1 < 1.5）では「わからない」と答えます。easy と medium では Q06 を採点しないので、そこでは参照解は採点されるすべての質問に正解します。

ベースラインは、アナリストなしで経理チームが報告するもの、つまりすべての質問について「集計中」（null）です。採点されるすべての質問で、抽選された「わからない」の報酬を得るので（最大値の 0.25 / 0.50 / 0.75）、すべてに「わからない」と答えると正規化した尺度では 0 になります。額面どおりの回答シートは、顧客の定義をひとつも使わずにエクスポートをそのまま集計したものです：保存された UTC の日付による暦年の期間、ステータスにかかわらずすべての注文、売上 = 注文の total からその期間の日付の返金を差し引いたもの、すべての通貨を 2026-09-30 のレートで換算、アクティブ = 直近30日間に注文あり、「パントリー」= pantry ラベル。この回答シートはすべての質問に答え、顧客がいずれにせよ適用する二つの経理の方針（テストアカウントの除外、設定の単位での金額の丸め）は守ります。公開ワールドの公開ルールシードでは、どの設定でもベースラインを下回ります。誤った数値は何も得られないからです。
